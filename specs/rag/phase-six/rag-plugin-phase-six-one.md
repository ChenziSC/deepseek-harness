# DSH RAG 插件第六阶段 6.1 概要设计规格

本文记录上下文前缀从一次性 Pilot 进入可选建库能力的原始范围、成本限制和最终验收结论。[详细技术方案](rag-plugin-phase-six-one-detailed-design.md)说明评测实现，[实施任务](rag-plugin-phase-six-one-implementation-tasks.md)记录完成状态。最终证据见[6.1 验收报告](rag-plugin-phase-six-one-acceptance-report.md)。

## 1. 决策

上下文前缀没有通过产品接入验收。正式建库继续使用标题、章节路径和原始分片，不接受生成前缀记录，不调用生成式模型；运行时检索也不生成前缀。候选统计、成本规划、有界生成和评测代码保留为离线研究工具。

第六阶段 Pilot 在受控歧义样本上显示机制潜力，但真实 6.1 评测没有获得高歧义召回收益，并在 SciFact 与 MLQA 上产生超过保护线的排序回退。全部候选成功率为98.16%，盲复核事实性为95.89%，有界输入节省率为79.7587%；这些结果均未达到门槛，因此索引接入已撤回。

## 2. 完整语料成本基线

规划阶段对本地已有的五个完整语料执行了不调用 LLM 的流式扫描。高歧义候选使用保守规则识别开头指代、承接表达、跨段引用以及缺少绝对日期的相对时间；分片使用当前384 token、64 token overlap配置。SciFact和MLQA为精确统计；MLDR与T2Ranking读取、校验、摘要并计数全部文档，但按稳定文档ID抽取千分之一执行分片级估算。T2Ranking另用已有100,001分片切片校准，百分之一抽样估算为98,455分片，误差为-1.55%。

| 数据集 | 完整文档数 | 预计分片数 | 高歧义候选 | 候选比例 |
| --- | ---: | ---: | ---: | ---: |
| SciFact | 5,183 | 7,230 | 708 | 9.79% |
| MLQA eng-zho | 4,468 | 5,874 | 713 | 12.14% |
| MLDR-en | 200,000 | 约2,930,303 | 约354,545 | 12.10% |
| MLDR-zh | 200,000 | 约3,291,542 | 约393,035 | 11.94% |
| T2Ranking | 2,303,643 | 约4,317,600 | 约613,975 | 14.22% |
| 合计 | 2,713,294 | 约10,552,549 | 约1,362,976 | 12.92% |

按`context-prefix-v5`的实际计划逻辑，上述候选仍预计需要约14.74亿输入token，输出上界约2.45亿token，共约17.19亿token。该结果是无LLM扫描得到的计划估算，不是实际账单；它也说明即使只处理约12.92%的高歧义分片，对完整语料执行一次生成仍然过于昂贵。6.1因此只在不超过50,000个分片的真实评测子集上生成，并同时要求候选筛选、章节窗口批处理和内容寻址缓存。

## 3. 最终产品行为

- 正式`index`命令不提供上下文前缀模式，不读取前缀凭据，不调用生成模型，也不改变 BM25 或 Dense 输入。
- manifest 保持格式4，SQLite保持schema 3，不保存前缀文本、状态、生成器身份或用量。
- 离线命令可以统计候选、生成有限计划并在显式预算下产出评测记录；这些记录不能直接进入产品索引。
- 离线记录和缓存保留原始分片摘要、生成身份与实际用量，用于复现实验和成本分析。

## 4. 实施范围

### 4.1 确定性候选检测

实现版本化的`strict-v1`检测器，不调用 LLM。缺少标题本身不能成为候选条件；弱标题、同名标题或短文本必须与指代、跨段引用、相对时间等另一项信号同时出现。候选超过配置比例时按确定性风险等级和 chunk ID 截断或失败，行为由显式配置决定。

### 4.2 有界上下文和批量生成

生成输入只包含文档元数据、目标章节的有限窗口和同一窗口内的候选分片，不重复发送完整长文档。一次请求可以为多个候选返回前缀，输出逐 chunk 对应，单个前缀具有独立 token 上限。

### 4.3 生成缓存和增量更新

前缀使用独立内容寻址缓存。身份覆盖模型 ID 与完整 revision、提示版本、参数、检测器版本、文档和章节窗口摘要、目标 chunk ID 及输出限制。普通文档派生缓存和向量缓存保持独立，不能因启用前缀而破坏未选中分片的复用。

### 4.4 索引接入结论

评测实现曾验证前缀与原始证据分离、Dense-only 和双路输入以及向量缓存失效范围。由于最终门槛失败，这些能力不保留在索引清单、SQLite schema 或`knowledge_search`运行路径中。

## 5. 成本约束

`ambiguous-only`模式至少要求调用方明确提供以下限制：

- 最大候选比例，建议首次验证不超过15%；
- 最大累计输入 token；
- 最大累计输出 token；
- 单个前缀最大 token；
- 单次请求最大候选分片数和最大上下文窗口；
- 预算耗尽时采用提前失败还是确定性回退。

生成器必须返回服务端实际计量。构建器在每个批次前检查剩余预算，在每个批次后累计实际用量；实际用量超过声明上限时不得继续发起请求。重试消耗计入同一预算，失败记录不能从成本统计中删除。

## 6. 验收

### 6.1 默认与正确性

- 未配置或配置`off`时，不加载生成器、不读取凭据、不发起网络请求，构建产物与第六阶段默认输入一致。
- 前缀记录与 chunk ID 一一对应；缺失、重复、跨文档引用或身份不一致时构建提前失败。
- 返回证据逐字保持原始分片内容，引用可解析率为100%。
- 同一输入和生成身份重复构建时，前缀缓存命中率为100%，不会重复消费生成 token。

### 6.2 成本

- 完整五语料只执行流式候选统计和成本规划，不落盘完整分片集合，不创建完整 SQLite、BM25、Exact 或 HNSW 索引，也不执行全量 LLM 生成或向量编码。
- 质量评测使用包含全部目标 qrels 文档和固定干扰文档的分层子集；每个数据集最多10,000个分片，五个数据集合计最多50,000个分片。
- 已有索引和向量缓存可以只读复用；不得为了6.1评测重新构建任何完整数据集。
- 真实评测子集相对“每个分片分别输入完整文档”的方案，生成输入 token 至少减少80%。
- 混合评测索引 token 总增幅不超过10%，没有正文因前缀占用 Dense 输入上限而静默截断。
- 报告同时给出首次构建、无变化重建、约1%文档变化和提示版本升级的生成 token 与向量失效数量。

### 6.3 质量与稳定性

- 使用真实 SciFact、MLQA、MLDR-en、MLDR-zh和T2Ranking文档及独立 qrels，不复用第六阶段构造样本作为主结论。
- 高歧义子集相对确定性前缀的完整证据覆盖率或 Recall@10 至少提高5个百分点。
- 完整混合集上 BM25、Dense 和 Hybrid 任一路 nDCG@10 不下降超过1个百分点，至少两个数据集获得方向一致的主指标正收益。
- 前缀成功率不低于99%，抽样事实性通过率不低于99%；所有失败与回退保留在主结果中。

实际结果未通过输入节省、高歧义增益、nDCG保护、全部候选成功率和事实性门槛。索引接入按预定失败条件撤回；详细结果见[6.1 验收报告](rag-plugin-phase-six-one-acceptance-report.md)。

## 7. 非目标

- 不把上下文前缀设为默认值，也不在升级时自动迁移既有索引。
- 不为评测构建完整数据集的 SQLite、BM25、Exact 或 HNSW 索引，不对完整五语料调用 LLM，也不承诺完整语料的实际生成账单或完成时间。
- 不逐 chunk 重复发送完整文档，不让模型自行选择无限上下文。
- 不实现在线查询时前缀生成、在线向量更新或 HNSW 原地修改。
- 不把前缀当成可信事实、引用正文、摘要答案或权限过滤依据。
- 不在本阶段引入 RAPTOR、GraphRAG、实体图谱或新的远程向量数据库。

## 8. 交付物

- 候选规划器、预算预览和机器可读计划；
- 可注入生成器、批量生成协议和内容寻址前缀缓存；
- 五个完整语料的无 LLM 候选统计；
- 真实混合评测、事实性盲复核、增量成本报告和6.1验收报告；
- 撤回后的格式4索引和SQLite schema 3，不包含上下文前缀字段。
