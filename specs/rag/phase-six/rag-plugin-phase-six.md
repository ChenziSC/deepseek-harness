# DSH RAG 插件第六阶段概要设计规格

本文定义第六阶段的范围、依赖顺序、成本约束和验收标准。[详细技术方案](rag-plugin-phase-six-detailed-design.md)固定类型、索引格式、过滤算法、派生缓存和 Pilot 协议，[实施任务](rag-plugin-phase-six-implementation-tasks.md)给出依赖图、任务边界、成本和逐项完成条件，[阶段验收报告](rag-plugin-phase-six-acceptance-report.md)记录最终结果。第五阶段的已实现能力与遗留限制见[第五阶段验收报告](../phase-five/rag-plugin-phase-five-acceptance-report.md)，当前增量向量复用结果见[第四阶段向量构建报告](../phase-four/rag-plugin-phase-four-vector-build-report.md)。

## 1. 定位

第六阶段优先解决三个相互关联的问题：检索缺少结构化的版本与有效期信号；局部文档变化虽然能复用向量，但仍会重新分片、预处理和组装完整索引；上下文感知检索可能改善孤立分片的实体、时间和指代歧义，但当前插件只有标题与章节路径增强，尚无本地收益证据。

本阶段采用“基础数据先稳定、构建复用随后完善、高成本质量方案最后验证”的顺序。版本元数据先进入语料和索引格式，使后续缓存身份一次包含完整输入；文档级派生内容复用随后降低重复实验成本；上下文感知检索只进行抽样 pilot，不在收益成立前触发完整语料的前缀生成和向量重建。

## 2. 优先级与依赖

| 顺序 | 工作项 | 优先级 | 依赖 | 编码成本 | 运行等待成本 | 本阶段决定 |
| ---: | --- | --- | --- | --- | --- | --- |
| 1 | 版本、有效期与替代关系元数据 | P0 | 无 | 3–5人日 | 低；只需小型索引和固定评测 | 正式实现 |
| 2 | 文档级分片与 BM25 派生内容复用 | P0 | 元数据字段和索引身份稳定 | 4–7人日 | 中；重复性能组约半天 | 正式实现 |
| 3 | 上下文感知检索对照 Pilot | P1 | 元数据可作为确定性前缀；复用机制可记录派生产物身份 | 2–3人日 | 中；抽样前缀生成和向量编码约1–4小时 | 只做 Pilot 和继续/停止决策 |
| 4 | 并行独立查询 | P1 | 有界搜索已有稳定基线 | 2–4人日 | 低至中 | 延后；不阻塞前三项 |
| 5 | RAPTOR 层次摘要 | P2 | 上下文前缀 Pilot 和派生内容缓存 | 8–15人日 | 高 | 不进入本阶段 |
| 6 | GraphRAG | P3 | 稳定实体模式、图存储和领域评测 | 15–30人日以上 | 高 | 不进入本阶段 |

版本元数据必须先于文档级缓存，因为有效期、版本和替代关系会影响可服务记录及缓存失效规则。文档级复用必须先于任何正式的 LLM 前缀实现，因为生成式前缀是高成本派生产物，需要内容寻址、失败恢复和局部失效能力。RAPTOR、GraphRAG 和 L0/L1/L2 层次摘要都依赖相同的派生产物管理基础，不能绕过前两项直接实施。

## 3. P0：版本与有效期检索

### 3.1 输入元数据

通用 JSONL 语料允许为文档提供可选的版本与有效期元数据。最小字段集包括来源版本、开始生效时间、结束生效时间和被替代文档标识；时间使用带时区的 RFC 3339 字符串，结束时间采用左闭右开区间。没有元数据的既有文档保持可检索，但结果明确表示其有效期未知。

字段的具体名称和类型由详细设计固定。实现不得把来源权威性压缩成一个通用数字分数，也不得仅凭版本字符串大小推断新旧关系。来源系统负责提供时间和替代关系，构建器负责严格校验，检索器只执行已声明的过滤语义。

### 3.2 索引与向量关系

版本与有效期作为 SQLite 过滤字段和模型可见证据元数据保存，默认不拼接进 Dense 输入。因此，标题、章节路径和正文未变化时，现有内容寻址向量缓存应达到100%命中；索引格式或 SQLite 表结构升级不构成重新编码向量的理由。

如果后续实验决定把某个元数据字段加入 BM25 或 Dense 检索文本，必须作为独立候选运行消融，并明确报告因此失效的向量比例。本阶段不能把过滤元数据和上下文增强隐式合并。

### 3.3 查询语义

默认查询排除查询时刻已经明确失效的文档。用户明确询问历史状态时，调用方可以提供一个查询时点；没有显式查询时点时使用运行时当前时间。历史查询只改变有效期过滤，不绕过部署权限，也不使已撤回但不允许历史访问的内容重新可见。

替代关系用于解释冲突和显示来源链，不自动删除原始记录。若两个同时有效的文档互相冲突，检索器继续返回双方，Agent 按第五阶段规则搜索裁定证据或保留不确定性。

### 3.4 验收

- 固定样本覆盖当前有效、尚未生效、已经失效、有效期未知、显式历史查询、替代链和同时有效冲突。
- 默认查询不得返回明确失效或尚未生效的证据；显式历史查询必须返回对应时点有效的证据。
- 过滤后的引用、文档标识和版本元数据保持可追溯，引用可解析率为100%。
- 只修改过滤元数据且 Dense 输入不变时，向量缓存命中率为100%，Exact 向量载荷保持逐字节一致。

## 4. P0：第二批增量建库优化

### 4.1 目标

第四阶段的向量缓存已经把1,096分片的无变化构建从273.2秒降至65.7秒，约1%文档变化降至68.0秒，但构建器仍重新执行文档分片、token 计数、BM25 文本预处理、SQLite 写入和 HNSW 组装。第六阶段继续减少未变化文档的重复计算，不引入在线可变索引。

### 4.2 文档级派生内容缓存

构建器增加独立于最终索引的内容寻址缓存。缓存键至少包含原始文档的准确字段、分片配置、tokenizer 身份、BM25 分析器身份和派生内容实现版本；缓存值包含规范化文档元数据、分片正文、章节路径、token 范围以及可直接写入 SQLite FTS 的预处理文本。

未变化文档直接读取这些派生记录，发生变化的文档只重新计算自身记录。删除、插入和输入重排不得使旧记录关联到错误文档或 ordinal。Dense 向量继续使用第四阶段已有的独立缓存，文档缓存不得复制或替代向量缓存。

每个缓存项在完整计算后以事务提交。中断构建可以复用已提交项，未完成项不可见；缓存损坏、版本不匹配或字段缺失必须产生可定位的未命中或明确错误，不能静默使用部分记录。

### 4.3 不可变发布

目标索引仍按当前输入生成一个完整、只读且自洽的新版本。SQLite 行、Exact 顺序和 HNSW ordinal 均以目标版本为准；缓存只减少计算，不把运行时改成多段查询，也不在原有 HNSW 图上原地增删。

HNSW 在本阶段仍允许完整重建。第四阶段1,096分片实验中，HNSW 添加与保存平均只占约70毫秒，优先优化它不会解决当前主要等待时间。只有更大规模测量证明 HNSW 组装成为主要瓶颈时，才另行评估分段图或在线更新。

### 4.4 性能验收

沿用第四阶段1,096分片的真实 SciFact 配置，对冷启动、0%、约1%、约10%和100%文档变化各运行至少三次。报告分片、BM25 预处理、SQLite、Dense、HNSW、总耗时、峰值 RSS、缓存命中和实际重算文档数。

- 0%和约1%变化不得对未变化文档运行 tokenizer 分片或 BM25 预处理。
- 0%和约1%变化的平均总时间相对第四阶段对应基线至少降低30%。
- 100%变化的平均总时间不得回退超过5%，峰值 RSS不得增加超过10%。
- 冷构建、缓存构建和中断恢复生成的文档、分片、BM25 排名、Exact 向量及固定查询指标必须一致。
- 性能门槛未达到时可以保留正确性基础，但不得宣称构建速度获得正收益。

## 5. P1：上下文感知检索 Pilot

### 5.1 对照方案

Pilot 使用包含代词指代、相对时间、同名实体、跨章节归属和弱标题结构的固定语料，比较三个索引输入：

1. 当前基线：标题、Markdown 章节路径和原始分片。
2. 确定性前缀：由标题、章节路径、来源版本和有效期元数据生成，不调用 LLM。
3. LLM 前缀：模型根据原文档和目标分片生成一段有限长度的上下文说明，再与原始分片共同索引。

三组使用相同的原始文档、分片边界、查询、候选数量和模型 revision。分别评测 BM25、Dense 和 Hybrid，关闭 Reranker 与相邻扩展以隔离前缀效果；选出候选后再检查其与默认相邻扩展的组合结果。

### 5.2 成本控制

Pilot 只处理足以覆盖目标歧义类型的抽样语料，不构建现有全部语料的上下文向量。每个 LLM 前缀记录模型、完整 revision、提示版本、输入摘要、输出文本、token 用量、延迟和失败状态；完全相同的输入只生成一次。

LLM 前缀会改变 BM25 文本和 Dense 输入，因此不能复用当前普通分片的最终向量。Pilot 使用隔离的缓存命名空间；如果未来正式启用，首次迁移需要重新编码启用该方案的分片，之后才能按新身份增量复用。

### 5.3 继续门槛

LLM 前缀只有同时满足以下条件，才进入后续正式实现规格：

- 相对当前基线，完整证据覆盖率或 Recall@10 至少提高5个百分点。
- 相对确定性前缀仍有可重复的正收益，不能把结构化元数据已经提供的收益重复归因于 LLM。
- BM25、Dense 和 Hybrid 任一路 nDCG@10 不下降超过1个百分点。
- 平均索引文本 token 增幅不超过25%，没有分片超过 Dense 输入上限后静默截断关键正文。
- 至少三次运行的结论方向一致，并完整报告前缀生成时间、token 和失败率。

未达到门槛时停止正式实现，保留当前标题与章节路径增强。达到门槛时只产出下一阶段的正式设计，不在第六阶段直接修改默认索引策略或执行完整语料重建。

## 6. 总成本与交付顺序

第六阶段预计需要12–16人日，模型和构建运行等待约半天至一天；等待可与代码、测试和报告编写交错，不等同于额外人日。前两项不要求完整向量重建，第三项只构建抽样向量。

实施顺序固定为：

1. 固定版本过滤和增量构建的样本、指标及第四阶段性能基线。
2. 完成语料元数据、索引记录和查询过滤。
3. 完成文档级派生内容缓存及中断恢复。
4. 运行增量构建正确性与性能评测。
5. 运行上下文感知检索三路 Pilot。
6. 根据预设门槛给出继续或停止结论，并运行最终组合回归。

## 7. 非目标

- 不执行完整语料的上下文前缀生成或向量重建。
- 不实现在线 HNSW 原地增删、多段实时查询或后台索引服务。
- 不实现 RAPTOR、GraphRAG、OpenViking 式 L0/L1/L2 文件系统、第二种 ANN 或语义分片。
- 不实现知识写入、Proposer/Reviewer 审核、定期整理、用户记忆或结构化案例知识发现。
- 不实现租户隔离、访问控制、远程向量数据库、通用内容审核或跨工具污点跟踪。
- 不修改 `agent-loop`，也不改变第五阶段的六次默认搜索预算、顺序搜索规则和24,000字符累计结果限制。

## 8. 完成条件

- 版本和有效期字段具有严格输入校验、索引记录、查询过滤、模型可见来源及固定回归样本。
- 只修改过滤元数据不会触发 Dense 重新编码，既有向量能够安全复用。
- 文档级缓存只重算变化文档，满足正确性、中断恢复和第4.4节的性能门槛。
- 上下文感知检索 Pilot 使用预先固定的语料、查询、模型和判断标准，给出可复现的继续或停止结论。
- 相关代码具备逐文件100%覆盖率；模型可见工具输出发生变化时更新真实 Loader 快照。
- `typecheck`、`lint`、相关测试、`doc-sync`、`hygiene` 和 `git diff --check` 通过。
- 模型、向量、索引、完整语料、原始会话和包含本机绝对路径的运行日志不进入提交范围。
