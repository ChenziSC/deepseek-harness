# DSH RAG 插件第六阶段 6.2 实施任务

## 1. 交付原则

本阶段只做行为保持型整理和后续迭代约束。每个批次先证明当前行为，再移动代码；不得借重构调整检索策略、默认值、索引格式或评测门槛。无需完整建库、向量全量重算或LLM调用。

## 2. 优先级、依赖与成本

| 顺序 | 工作项 | 优先级 | 依赖 | 编码成本 | 运行等待成本 |
| ---: | --- | --- | --- | --- | --- |
| 1 | 冻结行为基线与所有权清单 | P0 | 6.1最终工作树 | 0.5–1人日 | 小型索引与测试，约分钟级 |
| 2 | 写入包级迭代规则与入口约束 | P0 | T0清单 | 0.5人日 | 无 |
| 3 | 隔离上下文前缀离线代码并收窄根导出 | P0 | T0、T1 | 0.5–1.5人日 | typecheck与单测，分钟级 |
| 4 | 合并普通与派生构建公共流水线 | P0 | T0 | 1.5–3人日 | 小型Exact/HNSW构建，分钟级 |
| 5 | 拆分CLI命令 | P1 | T2后的入口、T3构建接口 | 1–2人日 | CLI测试，分钟级 |
| 6 | 提取有限缓存公共零件 | P1 | T3稳定 | 0.5–1人日 | 缓存单测，分钟级 |
| 7 | 审计内存BM25并决定迁移或保留 | P1/P2 | T2离线边界 | 0.5–1.5人日 | 小型评测，分钟级 |
| 8 | 验收、Agent Note与文档收尾 | P1 | 全部任务 | 0.5–1人日 | 相关门禁约数十分钟 |

预计总成本为4–7人日。T3是主要风险项；如果行为基线发现普通与派生构建存在有意差异，先记录差异再调整抽取范围，不为追求统一强行合并。

## 4. 基线和治理

### T0：冻结行为基线与所有权清单

- 记录当前RAG生产文件行数、根入口导出、模块依赖方向和`pnpm run duplication`结果。
- 使用固定小语料覆盖BM25-only、Exact、HNSW、Both和Exact派生构建，保存规范化manifest、SQLite顺序、Exact摘要和查询结果。
- 重放CLI代表性成功与失败路径、现有`knowledge-search`快照和文档派生/向量缓存测试。
- 把每个大文件的职责分配到产品入口、构建、CLI、存储或离线研究，避免移动后形成新的杂物模块。
- 不把当前覆盖率目录、完整索引或模型缓存纳入交付物。

完成条件：每项后续重构都有可比较行为；所有计划移动的符号有唯一目标所有者；未解决的当前重复片段具有清单。

### T1：建立后续迭代规则

- 新增`packages/experimental/knowledge-local/AGENTS.md`，写入职责地图、依赖方向、根导出限制、400/500行检查点、复制处理规则和阶段结束清单。
- 规则明确区分硬门禁与评审触发点：jscpd结果是硬门禁，文件行数用于提前审查而不是机械失败。
- 要求新增公共导出列出生产消费者；测试可以直接导入包内源文件。
- 要求失败实验进入`offline`，不得继续依赖产品配置、Provider或索引格式。
- 在包级规则中链接本Spec作为首个重构实例，但长期规则本身不依赖阶段编号。

完成条件：以后进入该包工作的Agent会自动读取规则；规则可执行、不过度重复根级AGENTS，并且没有引入新的仓库通用流程。

## 5. 产品与离线路径

### T2：隔离上下文前缀并收窄根导出

- 将6.1上下文前缀规划、artifact、生成、缓存、OpenAI适配和统计移动到`src/offline/contextual-prefix`。
- 更新离线CLI、脚本和测试引用，保持artifact格式、缓存schema、提示和评测结果不变。
- 将`src/index.ts`收窄到插件类、`Config`和真实产品消费者所需的最小类型。
- 删除测试为了方便而使用的根导入，改为导入所有者模块。
- 增加根运行时导出测试和产品代码不依赖`offline`的检查。
- 检查`package.json`的`./src/*`导出是否仍有必要；若无真实消费者则移除，若保留则说明其内部开发用途和限制。

完成条件：正式Provider、正式`index`构建和manifest路径不依赖上下文前缀；离线复现测试通过；根入口不再是算法与评测导出桶。

## 6. 构建与缓存

### T3：合并普通与派生构建流水线

- 从`index-builder.ts`抽取语料暂存、分片/SQLite写入、payload复验、manifest组装与最终提交。
- 实现普通编码和Exact复制两个窄Dense策略，分别拥有自己的准备、写入和manifest字段。
- 保留文档派生缓存、向量缓存、Exact导入、自动Dense选择和HNSW构建语义。
- 明确每个数据库、缓存和文件句柄的创建者与关闭者，覆盖构造失败、中途失败和成功关闭。
- 将公共类型、阶段和策略移动到`src/build`，保留一个小型兼容入口仅在确有内部消费者时使用。
- 对规范manifest、SQLite行、Exact字节和检索排序执行重构前后对照。

完成条件：两条构建路径只各自实现Dense差异，不重复暂存、分片、SQLite finalize、payload摘要和manifest写入；`pnpm run duplication`不再报告这两条路径。

### T4：提取有限缓存公共零件

- 比较`vector-cache.ts`、`document-derivation-cache.ts`与离线上下文前缀缓存的摘要、事务和关闭代码。
- 只提取长度分隔摘要、摘要格式校验和事务执行等同语义函数。
- 保留各自schema、缓存键字段顺序、payload解析、错误信息和类型。
- 为公共函数建立直接单测，并重跑三类缓存的损坏、回滚、命中和关闭测试。
- 若某段代码外观相似但失败语义不同，保留独立实现并在验收报告解释，不创建通用基类。

完成条件：jscpd缓存重复消失或有明确、窄小且合理的保留项；缓存身份和失效矩阵不变。

## 7. CLI 与评测

### T5：按命令拆分CLI

- 保留顶层`runCli`、帮助和统一错误出口，将`index`、`derive`、`evaluate`、`prepare/slice`、`verify`和上下文前缀命令移动到拥有模块。
- 提取缺失值、安全整数、有限数字、枚举和列表等原子解析函数。
- 业务默认、互斥选项、路径和模型装配留在对应命令，避免建立声明式CLI框架。
- 将CLI执行测试按命令拆分测试文件或describe所有权，公共分派测试只覆盖路由、帮助和未知命令。
- 比较现有帮助文本、JSON输出、退出码和代表性错误。

完成条件：顶层CLI文件只负责分派；任何命令文件不同时承担底层建库或评测算法；未出现新的通用CLI依赖。

### T6：审计内存BM25

- 固定中英文、混合文本、并列分数、重复词和候选截断样本，对照内存BM25与SQLite FTS5。
- 搜索全部生产、测试、脚本与报告消费者，确认内存实现的实际用途。
- 若仅为近似评测，迁移到临时SQLite正式路径并删除内存评分实现。
- 若逐词诊断仍不可替代，将最小实现移动到`offline/evaluation`并从根导出删除，文档明确不能作为产品质量基线。
- 不为统一两者而修改正式FTS5查询或质量策略。

完成条件：仓库内不存在两个都自称正式基线的BM25评分实现；去留结论有样本差异和消费者证据。

## 8. 收尾

### T7：验收、说明与检查

- 编写6.2验收报告，列出删除的重复片段、移动后的所有权、根导出、最大文件清单和所有超过500行文件的保留理由。
- 为非平凡简化新增proposed Agent Note，说明单一构建流水线、产品/离线依赖方向和未采用的过度抽象。
- 更新受影响README、CLI帮助和JSDoc；若产品行为完全不变，不修改质量结论。
- 运行受影响文件的100%覆盖率、现有Loader快照、小型Exact/HNSW构建、真实BGE-M3 smoke、`typecheck`、`lint`、`duplication`、`doc-sync`、`hygiene`和`git diff --check`。
- 检查无完整语料、完整向量、模型缓存、覆盖率目录、临时SQLite和绝对本机路径进入交付范围。
- 未得到用户明确指令时不commit、不push。

完成条件：概要规格的行为、结构和成本门槛全部有证据；包级规则已落地；重构没有改变第六阶段产品结论。

## 9. 建议评审批次

以下批次用于控制评审范围，不代表允许自动提交：

1. 行为基线、包级规则、上下文前缀离线移动与根导出收窄。
2. 单一建库流水线和构建对照测试。
3. CLI拆分与有限缓存公共函数。
4. 内存BM25结论、Agent Note、验收报告和文档收尾。

如果T3改动量明显大于预估，应将普通编码策略与Exact派生策略分成连续评审批次，但两批都以同一公共流水线为目标，不能留下长期双实现。

## 10. 明确暂缓

- 不优化检索质量或构建性能指标；如重构自然减少重复I/O，可记录但不作为本阶段收益承诺。
- 不重建完整SciFact、MLQA、MLDR或T2Ranking索引。
- 不调用上下文前缀LLM，不恢复6.1产品接入。
- 不创建通用缓存框架、CLI框架、repository层或新的插件能力。
- 不用硬性全仓行数阈值替代职责审查。
