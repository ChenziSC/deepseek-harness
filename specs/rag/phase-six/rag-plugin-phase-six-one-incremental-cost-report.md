# DSH RAG 插件第六阶段 6.1 增量成本报告

本文记录上下文前缀候选在有限 SciFact 评测子集上的生成缓存、文档派生缓存和向量缓存行为。机器摘要见 [`data/contextual-prefix-incremental-cost-summary.json`](data/contextual-prefix-incremental-cost-summary.json)。本实验只使用 1,299 篇文档、基线 1,815 个分片，没有构建任何完整基准语料索引。

## 结果

| 场景 | 前缀缓存 | 生成调用与 token | 文档重算 | 向量编码 | 索引构建时间 |
| --- | --- | --- | ---: | ---: | ---: |
| 0% 变化 | 193/193 候选命中 | 0 次，0 输入、0 输出 token | 0/1,299 | 0/1,815 | 2.51 秒 |
| 约 1% 变化 | 191/193 候选命中 | 2 次，2,340 输入、120 输出 token | 13/1,299 | 14/1,828 | 6.19 秒 |
| 约 10% 变化 | 173/193 候选命中 | 21 次（含 1 次重试），19,417 输入、1,036 输出 token | 130/1,299 | 146/1,945 | 32.81 秒 |
| 提示版本升级 | 0/193 候选命中 | 预计 190 次、173,908 输入、最多 39,760 输出 token | 未执行 | 未执行 | 未执行 |

相同有界子集的冷构建需要重算 1,299 篇文档并编码 1,815 个向量，构建器记录 463.58 秒。与该单次冷构建相比，0%、约 1% 和约 10% 变化场景分别减少 99.46%、98.67% 和 92.92%的构建时间。局部正文变化只使相应上下文窗口、文档派生和 Dense 输入失效；0% 变化不会再次消费生成 token。

提示版本是前缀缓存身份的一部分，因此升级提示会使 193 个候选全部失效。这不是局部变化，无法复用旧前缀。实验只生成计划和成本上界，没有为了补齐该对照再次调用模型。

## 结论

三层内容寻址缓存能够控制普通局部修改的重复计算和生成费用，但不能消除提示版本升级的全量候选失效。该成本结论仅说明缓存机制有效，不能证明上下文前缀本身值得进入产品索引；真实质量、稳定性和事实性门槛失败后，产品索引接入仍应撤回。
