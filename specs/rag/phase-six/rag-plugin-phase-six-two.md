# DSH RAG 插件第六阶段 6.2 概要设计规格

本文定义第六阶段 6.2 的行为保持型整理：清除多轮迭代积累的重复实现，提前拆分已经承担多个职责的大文件，并把后续 RAG 迭代约束写入包级规则和自动检查。详细模块方案见[详细技术方案](rag-plugin-phase-six-two-detailed-design.md)，执行顺序见[实施任务](rag-plugin-phase-six-two-implementation-tasks.md)。

## 1. 决策

6.2 不增加检索能力，也不调整第六阶段已经验收的默认策略。它先固定 6.1 的产品行为、索引格式、CLI 输出和评测结果，再重组实现；重组完成后，相同输入必须产生等价的 SQLite 内容、Dense 向量、manifest、检索结果和 CLI 结果。

本阶段优先处理五类问题：普通建库与 Exact 派生建库的重复收尾流程、过宽的包根导出、正式运行代码与失败实验代码混放、930 行 CLI 的多命令耦合、三类 SQLite 缓存重复的基础操作。内存 BM25 与正式 SQLite FTS5 的双实现先完成语义差异审计，只有在评测可以复用正式检索路径且不会降低可诊断性时才删除。

## 2. 当前证据

以 6.1 完成后的工作树为基线，`pnpm run duplication`报告17组重复片段、214行重复代码。`packages/experimental/knowledge-local/src/index-builder.ts`为1365行，`cli.ts`为930行，`evaluation.ts`为709行，`sqlite-index.ts`为602行；上下文前缀六个模块合计约2090行，但最终只保留离线研究价值。

`index-builder.ts`中的普通构建和 Exact 派生构建分别实现语料暂存、分片写入、派生缓存、SQLite finalize与复验、临时文件清理、payload摘要、manifest组装和最终写入。两条路径需要不同的 Dense 来源，但不应各自拥有完整构建生命周期。

包根`src/index.ts`为361行，导出建库、分片、缓存、评测、上下文前缀、数据准备、模型运行时和底层索引等大量符号；包外正式运行实际只需要插件类与配置。测试和一次性脚本的便利不能继续扩大产品入口。

## 3. 目标结构

```text
src/
  index.ts                         # 仅 Loader 插件、Config 和稳定产品入口
  build/
    types.ts                       # 构建请求、计划和统计类型
    stage.ts                       # 语料暂存与文档顺序
    chunks.ts                      # 派生缓存、分片和 SQLite 写入
    dense.ts                       # 编码或复用 Exact 向量、HNSW 写入
    manifest.ts                    # payload 校验与 manifest 组装/最终写入
    pipeline.ts                    # 单一构建生命周期
  cli.ts                           # 帮助、命令分派和统一错误出口
  cli/
    options.ts                     # 仅共享的原子参数解析
    index.ts
    derive.ts
    evaluate.ts
    prepare.ts
    contextual.ts                  # 离线命令组
  offline/
    contextual-prefix/             # 6.1 规划、生成、缓存和统计
    evaluation/                    # 离线评测专用适配
  storage/
    cache-primitives.ts            # 小型摘要、事务和关闭辅助函数
```

该目录是职责目标，不要求为了匹配目录一次性移动所有小文件。只有一个文件已经混合多个变更原因，或拆分能够删除真实重复时才移动；名称可在实现时按现有依赖进一步收窄。

## 4. 实施范围

### 4.1 单一建库流水线

普通构建和 Exact 派生构建共享一个拥有输出目录、语料暂存、文档派生、SQLite 生命周期、payload与manifest提交的流水线。Dense阶段以显式策略注入：普通构建策略负责缓存查询和模型编码，派生策略负责校验源索引前缀并复制已有向量。公共流水线不得通过大量布尔开关重新形成隐式的两套控制流。

manifest 继续最后写入。任何阶段失败都不产生可加载的完成索引；缓存、SQLite、文件句柄和源索引仍按当前语义关闭。格式保持4，SQLite schema保持3。

### 4.2 产品入口与离线能力隔离

包根只导出`LocalKnowledge`、默认导出、`Config`以及正式组装确实需要的类型。建库 CLI、评测、语料工具和上下文前缀不再通过包根暴露；包内测试直接引用拥有实现的源模块，仓库脚本使用明确的离线入口或相对源路径。

6.1上下文前缀代码移动到`offline/contextual-prefix`所有权下。保留候选统计、成本规划、有界生成、缓存和复现实验能力，但不能被正式`index`命令、Provider、manifest或包根入口依赖。

### 4.3 CLI 按命令拆分

`cli.ts`只保留命令表、帮助文本、统一异常处理与进程退出码。每个命令模块拥有自己的选项、依赖装配和输出结构；真正相同的`required`、安全整数、枚举与列表解析放入`cli/options.ts`。不创建通用命令框架，不用复杂注册表替代清晰的命令分派。

### 4.4 缓存公共零件

向量缓存、文档派生缓存和上下文前缀缓存只共享具有同一语义的基础函数，例如长度分隔摘要写入、SQLite事务提交/回滚和幂等关闭。表结构、配置身份、payload校验和错误消息继续由各缓存拥有；不引入通用缓存基类或可配置 ORM。

### 4.5 内存 BM25 审计

正式运行以 SQLite FTS5 为唯一 BM25 实现。内存 BM25 目前服务离线评测和诊断；6.2先比较分词、评分、并列排序、截断与诊断输出。如果评测能直接构建临时 SQLite 并复用正式查询路径，则删除重复评分实现；如果存在明确、仍被使用的诊断能力，则保留最小范围并记录不能统一的原因。

## 5. 后续迭代原则

- 新功能先写清所有者、产品路径或离线路径、输入输出和持久化责任，再开始编码；一个文件不能同时拥有协议解析、业务执行、持久化和 CLI 适配。
- 一个事实只有一个实现。新增相似逻辑前必须搜索现有实现；第二次复制时检查能否共享，第三个副本出现前必须统一实现或在代码旁记录保留原因。
- 只抽取共同语义和共同变更原因，不为消除少量相似语句建立通用框架、基类或配置层。
- 文件达到400行时必须在评审中说明是否仍为单一职责；预计超过500行的新改动应先拆分后扩展。行数是检查触发点，不是要求机械切文件的硬上限。
- 包根导出只服务生产消费者或明确的包级承诺；测试不得为了导入方便推动内部函数成为包根API。
- 失败或未接入产品的实验能力移动到`offline`或脚本路径，不继续占用产品配置、Provider、索引格式或包根入口。
- 每个阶段结束运行定向测试、`pnpm run duplication`、未使用代码检查和大文件清单；发现项必须处理或记录具体保留原因，不能只用忽略标记消音。
- 拆分必须保持行为证据。移动代码不能顺便改变默认值、检索质量策略、持久化格式或错误语义；行为变化另立规格和验收。

这些规则在实施时写入`packages/experimental/knowledge-local/AGENTS.md`，作为后续修改该包时自动加载的局部约束。重复代码继续由现有 jscpd 门禁阻止；大文件清单采用审查触发而非仓库级绝对行数门禁，避免为了数字拆出无意义文件。

## 6. 验收

### 6.1 行为保持

- 使用固定小型语料分别执行 BM25-only、Exact、HNSW、Both和Exact派生构建，manifest语义、SQLite行、向量字节、检索排序和错误结果与基线一致。
- 6.1正式产品行为不变：上下文前缀仍不进入正式索引，格式版本仍为4，SQLite schema仍为3。
- CLI各命令的帮助、成功输出、退出码和已覆盖错误保持兼容；如果仅因明确收窄内部API而改变导入路径，必须一次性更新全部仓库消费者。

### 6.2 结构

- 普通构建与派生构建不再重复拥有语料暂存、SQLite收尾、payload摘要和manifest最终写入。
- `index-builder.ts`和`cli.ts`不再是多职责大文件；拆分后每个生产文件应以单一职责为主，超过500行时验收报告必须给出保留理由。
- 包根不导出离线评测、上下文前缀、缓存实现、模型加载器或底层索引算法。
- 6.1上下文前缀正式运行依赖为零，离线复现测试继续通过。
- `pnpm run duplication`通过，不新增 jscpd 忽略区间；现有 RAG 重复片段被删除或逐项说明保留原因。

### 6.3 成本

- 不构建完整评测数据集，不重新编码完整向量，不调用LLM。
- 验收只使用单元测试、既有快照、小型临时语料和已有 BGE smoke；预计无长时间后台等待和模型token成本。

## 7. 非目标

- 不新增分片、检索、Reranker、两轮搜索或安全策略。
- 不调整现有质量结论、默认开关和预算。
- 不建立仓库通用 CLI 框架、缓存框架、存储抽象层或任意插件架构。
- 不为了减少行数拆分纯类型文件或紧密协作的小函数。
- 不删除仍是复现实验所需的6.1产物解析和离线生成能力。
- 未得到用户明确指令时不commit、不push。

## 8. 交付物

- 重组后的建库流水线、CLI和离线目录；
- 收窄后的包根入口与消费者迁移；
- 小型缓存公共零件或保留独立实现的审计结论；
- 内存BM25去留结论；
- 包级迭代规则、重复代码结果、大文件清单和6.2验收报告。
