# DSH RAG 插件第四阶段验收报告

## 1. 结论

第四阶段实现与评测完成。自动路由、两轮证据收集、两轮触发判断和内容寻址向量复用获得正收益证据；自适应 Reranker、从零编码候选和 Markdown 结构分片得到有限或负面结果，因此没有扩大默认策略声明。

本阶段保留最多两次搜索的硬上限，自动路由使用“精确标识符走 BM25，其他查询走 Dense”，Reranker 继续默认 `off`，Hybrid 只允许显式选择。向量构建使用内容寻址缓存支持局部更新和中断续跑。Markdown 结构分片继续默认启用，但只承诺章节路径和上下文压缩，不宣称每种召回方式都提高排序质量；相邻扩展存在完整证据收益，同时显著增加返回 token。

## 2. 第一批：效果证据

| 项目 | 主要结果 | 验收 |
| --- | --- | --- |
| 自动路由 | 三个主要分组均选择对应最佳固定策略，nDCG@10 差距为 0；旧 Hybrid 同脚本规则在 T2Ranking 低 9.65 pp 且更慢 | 通过；调整路由，Hybrid 不再自动选择 |
| 自适应 Reranker | BM25 `0.15` 和 Hybrid `0.05` 可保留至少 70% 增益，但触发率为 63%–91%，单次触发约增加 4.1–4.7s；Dense 跨数据集不稳定 | 证据完成；不推荐设为默认，维持 `off` |
| 两轮证据收集 | Agent 完整覆盖率 68%，同预算最佳单轮 52%，提高 16 pp；预定义查询 Oracle 为 80% | 通过；Oracle 不计为产品收益 |
| 两轮触发判断 | 判断准确率 95%，必要第二轮召回率 92.31%，精确率 100%，首轮充分停止率 100%，最终证据覆盖率 87% | 通过；保持最多两轮 |

两轮检索的产品意义是补齐一次综合查询没有召回的独立证据需求，而不是机械执行第二次查询。混合评测证明模型能处理显式缺口、中间事实和冲突，但自然语料仍有 13% 最终证据不完整，不能把提示规则视为召回质量的替代品。

## 3. 第二批：建库成本

内容寻址缓存以完整 Dense 配置和准确输入文本作为键，目标索引仍按新 ordinal 完整组装。格式 3 Exact 索引可以经过载荷和配置校验后导入缓存；删除、插入、重排、标题和章节变化不会把旧向量关联到错误分片。成功批次先提交缓存，未完成目标不发布清单。

正式 T7 使用 800 篇 SciFact 文档、1,096 个分片，每组重复三次：

| 变化组 | 新编码 | 平均时间 | 相对冷启动 |
| --- | ---: | ---: | ---: |
| 冷启动 | 1,096 | 273.2s | 基线 |
| 0% | 0 | 65.7s | -76.0% |
| 约 1% | 14 | 68.0s | -75.1% |
| 约 10% | 114 | 83.4s | -69.5% |
| 100% | 1,096 | 277.7s | +1.6% |

冷启动与未变化复用的 Exact 载荷、排名和 21 条 qrels 指标一致。中断后已提交的 160 个向量得到复用，恢复只编码其余 936 个。长度分桶虽缩短时间，但降低 MRR@10 和 nDCG@10；批次 64 只有约 4% 吞吐收益且峰值 RSS 增加约 41%。两项候选均未进入默认实现。

## 4. Markdown 消融

20 个固定 revision 的真实 Markdown 文件生成 25 条人工核验查询。结构分片相对 token 窗口使三种召回的平均五条结果上下文从 626.8 token 降至 422.5 token，减少 32.6%；平均完整证据覆盖率从 85.33% 增至 88.0%，平均 nDCG@10 从 0.9776 降至 0.9754。

分召回看，BM25 的 MRR@10 和 nDCG@10 分别提高 3.00 和 2.28 pp，Dense 与 Hybrid 的 nDCG@10 均下降 1.48 pp。因此结构分片不满足“每种召回整体 nDCG 降幅不超过 1 pp”的严格效果门槛，只能确认上下文压缩、章节路径和 BM25 收益。

相邻扩展使平均完整证据覆盖率从 88.0% 提高到 92.0%，单命中上下文完整率从 73.33% 提高到 78.67%，平均返回 token 增加 77.0%。它保留为质量优先默认值，但不是无成本提升。详细结果见 [Markdown 分片消融报告](rag-plugin-phase-four-markdown-ablation-report.md)。

## 5. 保留限制

- 自动路由是确定性启发式规则，不是逐查询 oracle；T2Ranking 普通组仍比离线 oracle 低 3.38 pp。
- Reranker 的阈值和延迟依赖数据集与运行环境；`auto` 不提供稳定低延迟保证。
- 两轮策略只验证最多两次的证据获取，不是无界研究循环，也不评价开放式答案的全部事实正确率。
- 向量缓存只复用完全相同的 Dense 输入；改变分片策略会使绝大多数输入重新编码，HNSW 图始终完整重建。
- Markdown 消融只有 25 条查询；负结果和成本用于限制结论，不能外推为通用文档检索基准。
