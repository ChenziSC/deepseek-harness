# DSH RAG 插件第四阶段实施任务

## 1. 交付原则

本阶段先使用现有向量补齐自动路由、自适应 Reranker 和两轮检索证据，再修改索引构建器。真实 Markdown 消融必须等待增量向量复用通过正确性和小样本性能验证。每项实验保留机器可读报告；未达到效果门槛时记录负结果，不为了通过验收调整口径。

## 2. 依赖图

```text
T0 规格与现有产物确认
  -> T1 逐查询评测明细
       -> T2 自动路由评测
       -> T3 自适应 Reranker 阈值评测
       -> T4 两轮检索 100 条多跳评测
            -> T4.1 两轮触发判断混合评测
                 -> T5 内容寻址向量缓存
                      -> T6 从零编码执行器优化
                           -> T7 小样本增量与冷启动性能验证
                                -> T8 真实 Markdown 分片消融
                                     -> T9 验收报告与仓库检查
```

T2、T3、T4 和 T4.1 在 T1 后顺序完成，避免多个实验同时占用本地模型和 CPU。T5 必须等待 T4.1 通过；T8 必须依赖 T5、T6 和 T7。

## 3. 第一批：补齐效果证据

### T0：规格与现有产物确认

依赖：无。

- 校验 MLDR English 和 T2Ranking 10k、25k、50k、100k 格式 3 索引及 payload 哈希。
- 记录可直接复用的查询、qrels、模型缓存和索引指纹。
- 明确第二阶段格式 2 索引不直接进入正式第四阶段报告。
- 固定全部实验的候选数、返回数、模型 revision 和机器环境。

完成条件：形成机器可读输入清单，前三项评测不需要重新执行 Dense 编码。

### T1：逐查询评测明细

依赖：T0。

- 为评测器增加逐查询 JSONL 输出。
- 记录请求策略、实际策略、top-2 分差、Reranker 触发、文档排名、qrels、单查询指标和延迟。
- CLI 增加单一自适应阈值参数。
- 保持现有聚合报告兼容；新增字段需要同步测试和 README。

完成条件：同一运行可以从逐查询明细重新计算聚合指标；异常查询不会被静默丢弃。

### T2：自动路由评测

依赖：T1。

- 准备同脚本、跨脚本和精确标识符查询分组。
- 在每条查询上运行 `auto`、BM25、Dense 和 Hybrid。
- 输出路由分布、分类命中率、相对固定策略差异和 oracle regret。
- 若结果未达到概要设计门槛，调整路由规则后只重跑受影响分组。

完成条件：自动路由是否带来质量与延迟收益具有明确结论；没有收益时给出默认策略调整建议。

### T3：自适应 Reranker 阈值评测

依赖：T1、T2 的评测进程已结束。

- 分别获取 BM25、Dense 和 Hybrid 的 top-2 分差分布。
- 运行 `off`、`on` 和去重后的有限阈值集合。
- 输出质量增益保留比例、触发率、触发与未触发延迟。
- 使用不同数据集完成阈值选择和验证，不在同一查询集上同时选择并宣布通过。
- 根据结果决定保留全局阈值、改为按召回方式配置，或不推荐 `auto`。

完成条件：报告明确区分“Reranker 有质量收益”和“自适应规则能节省成本”两个结论；不重新构建向量。

### T4：两轮检索 100 条多跳评测

依赖：T1，且本地不得同时运行 Reranker 大矩阵。

- 从现有格式 3 语料选取两组互补证据并编写 100 条问题。
- 使用受限初始提示的独立 Agent 逐条核验问题、两条检索查询和证据文档 ID；官方 qrels 不作为自动通过依据。
- 实现完整问题单次检索、模型生成单条综合查询、成本对齐单轮、Agent 自主决策和预定义两查询 Oracle。
- 统计完整证据覆盖、第二轮边际命中、重复率、调用次数、候选预算、延迟和 token 成本。
- 保留完整会话日志，但报告不收录语料全文和模型隐藏推理。

完成条件：100 条样本全部通过独立语义复核并完成各轨道；只用 Agent 自主决策相对合理单轮基线的差异判断真实收益，Oracle 仅报告构造性上限；不扩展为通用答案级验收。

### T4.1：两轮触发判断混合评测

依赖：T4。

- 按[混合评测规格](rag-plugin-phase-four-search-decision-spec.md)更新工具提示，保留每个 Agent turn 最多两次搜索的硬上限。
- 固定 100 条混合样本，覆盖单主题、双主题、中间事实多跳、首轮充分复合问题和首轮冲突。
- 根据首轮实际证据覆盖和冲突状态判断第二轮是否必要，不使用查询长度或召回分数作为替代标签。
- 统计必要第二轮触发召回率与精确率、充分证据停止率、判断准确率、第二轮缺失证据命中、中间实体使用和冲突处理。
- 保留模型原始结果和会话日志于未提交缓存，只提交固定输入、摘要和结论。

完成条件：规格中的判断、证据、调用限制和引用门槛全部通过；失败时继续调整提示词或保留负结果，不增加搜索上限。

## 4. 第二批：降低建库成本并验证 Markdown

### T5：内容寻址向量缓存

依赖：T2、T3、T4、T4.1 完成。

- 为索引命令增加显式向量缓存目录和 Exact 索引导入参数。
- 实现按 Dense 配置和完整输入文本寻址的 SQLite 向量缓存。
- 验证导入索引格式、payload 哈希、ordinal 对齐和完整 Dense 模型配置。
- 按新 ordinal 读取缓存命中，只批量编码未命中输入，并原子提交成功批次。
- 输出缓存命中数、编码数、复用率和各阶段耗时。
- 始终重建目标 SQLite、清单和可选 HNSW，不修改源索引。

完成条件：新增、修改、删除、重排、重复文本、中断恢复和损坏缓存测试通过；模型或输入不一致时不会错误复用。

### T6：从零编码执行器优化

依赖：T5。

- 增加分片、tokenization、推理、向量 I/O 和 HNSW 构建分阶段计时。
- 评估按文本数和 token 总量双重限制的动态批处理。
- 在有界窗口中评估按 token 长度分桶，并比较向量、Exact 排名和 qrels 指标。
- 只有 I/O 占比支持时才实现有界队列重叠，避免增加没有可测收益的并发状态。
- 抽样比较模型 worker 数和运行时线程配置，不默认启用未经验证的并行。

完成条件：空缓存路径可以完整构建；每个候选都有吞吐、质量和资源结论；未通过的候选不进入受支持路径。

### T7：小样本增量与冷启动性能验证

依赖：T5、T6。

- 使用 1,000 至 5,000 分片样本比较当前固定批次与候选优化。
- 冷启动组使用空缓存，记录 chunks/s、tokens/s、padding 比例、墙钟时间和 RSS。
- 增量组构造 0%、1%、10% 和 100% 变化版本，记录缓存命中和 embedding 调用。
- 每组重复三次，验证向量容差、Exact 排序和 qrels 指标。
- 验证中断后源索引保持可用，目标目录没有可加载 manifest，重启能够复用已提交批次。

完成条件：未变化输入 100% 命中；局部变化只编码缓存未命中输入；只接受重复运行稳定且资源可控的冷启动优化；不运行完整 100k 重编码。

### T8：真实 Markdown 分片消融

依赖：T5、T6、T7。

- 固定真实 Markdown 文件清单、Git revision 和语料摘要。
- 准备至少覆盖五种结构类型的人工核验查询与 qrels。
- 构建 token 窗口基线和 Markdown 结构索引，优先利用 T5 复用相同 Dense 输入。
- 在结构索引上分别关闭和开启相邻扩展。
- 输出总体、结构子集和上下文完整性指标。

完成条件：报告分别判断结构分片和相邻扩展是否有意义；未达门槛时不宣称质量提升。

### T9：验收报告与仓库检查

依赖：T2、T3、T4、T4.1、T7、T8。

- 编写第四阶段验收报告，汇总正收益、负收益、成本和保留限制。
- 更新受影响的 README、Agent Note 和生成文档。
- 运行相关包逐文件覆盖率、真实模型小样本、知识快照、`typecheck`、`lint`、`doc-sync`、`hygiene` 和 `git diff --check`。
- 确认缓存、模型、语料、索引和本机路径没有进入提交范围。

完成条件：全部要求检查通过，或明确记录与本阶段无关的既有失败；不自动 commit 或 push。

## 5. 明确暂缓

- 不继续扩大 Exact/HNSW 阈值校准规模，不新增 100k 以上档位。
- 不实现通用答案级评测器或开放式回答质量验收。
- 不实现 HNSW 图的原地增删、后台索引服务或在线增量索引。
- 不增加新的 Dense、Reranker 或 ANN 模型。

## 6. 执行结果

T0 至 T8 已完成，T9 的验收结论见[第四阶段验收报告](rag-plugin-phase-four-acceptance-report.md)。T6 没有保留新的从零默认优化：长度分桶因质量下降被撤回，批次 64 因内存增幅过高不采用。T8 的结构分片只获得上下文压缩和 BM25 正收益，Dense 与 Hybrid 没有通过单路排序门槛；相邻扩展提高完整证据覆盖，但返回 token 明显增加。
