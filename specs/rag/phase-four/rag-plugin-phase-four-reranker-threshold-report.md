# DSH RAG 插件第四阶段 Reranker 阈值评测报告

本文记录第四阶段 T3 自适应 Reranker 阈值评测。机器可读汇总见 [`data/reranker-threshold-evaluation-summary.json`](data/reranker-threshold-evaluation-summary.json)。评测复用 T2Ranking 10k 与 SciFact 格式 3 Exact 索引，固定 50 个召回候选、20 个 Reranker 候选和 20 个返回文档，没有重新生成 Dense 向量。

## 1. 结论

Reranker 的收益取决于数据集和召回方式，不能只用一个全局 top-2 分差阈值稳定兼顾质量与成本。当前实现省略 `rerank` 时使用的默认值是 `off`，不是 `auto`；需要最大质量时使用显式 `on`，`auto` 也必须由调用方显式请求。不建议把 `auto` 设为默认值。

- BM25 在两个数据集上均有正收益。`0.15` 在 T2Ranking 触发 84%，保留 82% MRR 增益和 80% nDCG 增益；在 SciFact 触发 63%，保留 100% MRR 增益和 82% nDCG 增益。
- Hybrid 在两个数据集上均有正收益。`0.05` 在 T2Ranking 触发 91%，保留 85% MRR 增益和 87% nDCG 增益；在 SciFact 触发 87%，保留全部 MRR 和 nDCG 增益。
- Dense 不存在跨数据集一致结论。SciFact 的 `on` 明显提高质量，但 T2Ranking 的 MRR 几乎不变、nDCG 下降 0.34 个百分点，因此不能为 Dense 推荐通用自动阈值。
- Reranker 单次触发约增加 4.1 至 4.7 秒。触发率超过一半后，整体 p50 进入秒级；只要触发率超过约 5%，p95 通常已经进入秒级。

如果以后增加按召回方式配置的阈值，可以把 BM25 `0.15` 和 Hybrid `0.05` 作为候选；Dense 仍应保持 `off` 或由质量请求显式选择 `on`。本阶段不为这两个候选增加新的运行时配置。

| 数据集 | 召回 | `off` MRR / nDCG | `on` MRR / nDCG | MRR / nDCG 变化 | `off` p50 / p95 | `on` p50 / p95 |

| T2Ranking | BM25 | 42.04% / 33.95% | 51.24% / 42.62% | +9.20 / +8.67 pp | 130.35 / 187.90 ms | 4274.28 / 4423.35 ms |
| T2Ranking | Dense | 56.65% / 54.61% | 56.67% / 54.27% | +0.02 / -0.34 pp | 32.41 / 35.77 ms | 4162.64 / 4274.03 ms |
| T2Ranking | Hybrid | 50.26% / 44.95% | 55.64% / 50.42% | +5.38 / +5.47 pp | 171.77 / 233.04 ms | 4279.24 / 4433.17 ms |
| SciFact | BM25 | 67.64% / 70.91% | 71.08% / 74.42% | +3.44 / +3.50 pp | 38.61 / 59.99 ms | 4717.54 / 4948.67 ms |
| SciFact | Dense | 71.23% / 75.32% | 77.31% / 80.06% | +6.09 / +4.74 pp | 29.54 / 35.63 ms | 4537.10 / 4859.59 ms |
| SciFact | Hybrid | 71.28% / 74.78% | 74.44% / 79.36% | +3.16 / +4.59 pp | 65.34 / 92.66 ms | 4625.24 / 4925.32 ms |

这组结果先回答“Reranker 是否有质量收益”。BM25 和 Hybrid 的 `on` 在两个数据集上均为正收益；Dense 只在 SciFact 上有明确正收益。阈值评测不能把 Dense 的 SciFact 结果外推为通用收益。

## 3. 阈值选择

阈值候选为 `0`、`0.005`、`0.01`、`0.02`、`0.03`、`0.05`、`0.10` 和 `0.15`。触发条件与运行时一致：未重排召回结果的前两名分差比例小于阈值时执行 Reranker。连续阈值若产生相同触发集合，只保留第一项。

| 召回 | 候选阈值 | T2Ranking 触发率 | T2Ranking MRR / nDCG 保留 | SciFact 触发率 | SciFact MRR / nDCG 保留 | 判断 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| BM25 | 0.15 | 84% | 82% / 80% | 63% | 100% / 82% | 两个数据集达到 70% 门槛，但触发率仍高 |
| Dense | 无 | — | `on` 的 nDCG 为负收益 | — | `on` 有正收益 | 不推荐通用阈值 |
| Hybrid | 0.05 | 91% | 85% / 87% | 87% | 100% / 100% | 两个数据集达到门槛，但成本接近常开 |

BM25 的较低阈值不能稳定保留收益：`0.10` 在 T2Ranking 只保留 63% MRR 和 65% nDCG 增益，`0.05` 在 SciFact 只保留 60% MRR 和 45% nDCG 增益。Hybrid 的 `0.03` 在 T2Ranking 只保留 80% MRR 和 65% nDCG 增益，在 SciFact 只保留 12% MRR 和 54% nDCG 增益。因此不能进一步降低推荐候选而仍满足双指标门槛。

## 4. 成本判断

自适应规则确实可以跳过部分 Reranker 调用，但达到质量门槛的触发率仍为 63% 至 91%。在本机 CPU 推理环境中，BM25 `0.15` 和 Hybrid `0.05` 不能把触发查询的约 4 秒延迟消除，只能让未触发查询保留召回阶段延迟。

这意味着 `auto` 适合表达“尽量保留质量，同时允许部分查询跳过重排”，不适合作为低延迟默认值。若部署环境提供明显更快的 Reranker，仍需在该环境重新测量延迟；质量触发集合可以复用相同查询明细重新计算，但延迟数字不能直接外推。

## 5. 真实 `auto` 验证

阈值筛选先组合同一查询的 `off` 和 `on` 明细，随后对 BM25 `0.15` 与 Hybrid `0.05` 运行真实 `auto`。四组运行的触发率和质量指标与明细模拟完全一致，证明阈值计算与提供方执行条件一致；延迟使用真实运行值。

| 数据集 | 召回 / 阈值 | 触发数 | MRR@10 | nDCG@10 | p50 / p95 |
| --- | --- | ---: | ---: | ---: | ---: |
| T2Ranking | BM25 / 0.15 | 84 / 100 | 49.54% | 40.91% | 4249.63 / 4410.29 ms |
| T2Ranking | Hybrid / 0.05 | 91 / 100 | 54.82% | 49.72% | 4150.61 / 4365.26 ms |
| SciFact | BM25 / 0.15 | 19 / 30 | 71.08% | 73.80% | 4348.47 / 4907.64 ms |
| SciFact | Hybrid / 0.05 | 26 / 30 | 74.44% | 79.36% | 4431.46 / 4946.92 ms |

## 6. 验收

- 已分别记录 BM25、Dense 和 Hybrid 的未重排 top-2 分差、`off`、`on`、候选阈值、触发率、质量增益保留比例及延迟。
- T2Ranking 用于阈值选择，SciFact 用于独立验证；没有在同一查询集上同时选择并宣布通过。
- BM25 和 Hybrid 在两个数据集上存在低于 100% 的触发率，并达到至少 70% 的 MRR 与 nDCG 增益保留门槛。
- Dense 的跨数据集收益不稳定，报告保留负结果，不建议自动启用。
- 当前运行时保持性能默认 `off`，质量请求使用显式 `on`；`auto` 不升格为默认策略。
