# DSH RAG 插件第四阶段两轮检索评测报告

本文记录第四阶段 T4 两轮证据收集评测。有效样本与 Agent 复核见 [`data/multi-hop-validated-data-summary.json`](data/multi-hop-validated-data-summary.json)，确定性基线见 [`data/multi-hop-baseline-summary.json`](data/multi-hop-baseline-summary.json)，真实 Loader 轨道见 [`data/multi-hop-agent-baseline-summary.json`](data/multi-hop-agent-baseline-summary.json)。原始样本及其失败结果只保留为诊断资料。

## 1. 结论

T4 的证据获取验收通过。Agent 自主决策轨道的完整证据覆盖率为 68%，在同为 100 个召回候选、最多使用 20 条返回证据的口径下，高于最佳合理单轮基线的 52% 共 16 个百分点，超过概要设计要求的 10 个百分点。

该结论不再使用“第一个预定义子查询为 0%，两个预定义子查询为 94%”的比较。原比较的单轮基线由样本构造决定为 0%，只能证明两条已知子查询具有互补性，不能表示真实 Agent 获得 94 个百分点产品收益。有效样本上的两条预定义查询仍作为 Oracle：每条查询取前 10 条、合计最多 20 条证据时完整覆盖率为 80%，比自主 Agent 高 12 个百分点。

## 2. 样本与独立复核

三个受限子 Agent 分别复核编号 001–034、035–067 和 068–100。初始提示要求每个 Agent 只检查自己的编号范围、不修改 tracked 文件、不把官方 qrels 或既有复核结论当作自动通过依据，并逐条确认两个子问题完整可答且各有至少一篇正文直接支持。

原始 100 条样本只有 51 条通过，49 条因问题不完整或证据不能直接支持而失败，因此原始实验被判定无效。新集合从正文已验证的查询和文档中重建；第一次复核发现 22 条失败，替换后由三个 Agent 再次复核替换项。最终 100/100 条通过，样本 SHA-256 为 `939603825ef5726ba07113e300f36b8e1b09a6774963b49a34d0459937770482`。

## 3. 对照结果

所有轨道使用同一 T2Ranking 10k 格式 3 Exact 索引，自动检索路由和关闭 Reranker。完整覆盖要求返回结果同时包含第一组和第二组经 Agent 核验的证据文档。

| 轨道 | 成功搜索 | 候选预算 | 对齐的证据预算 | 完整覆盖率 |
| --- | ---: | ---: | ---: | ---: |
| 完整组合问题直接检索 | 1 | 50 | Top-10 / Top-20 | 19% / 42% |
| 模型生成单条综合查询 | 1 | 50 | 最多 10 | 11% |
| 成本对齐单次检索 | 1 | 100 | Top-20 | 52% |
| Agent 自主决策 | 2 | 100 | 最多 20 | 68% |
| 两条预定义查询 Oracle | 2 | 100 | 每条 Top-10，合计最多 20 | 80% |

成本对齐单次检索还返回了最多 40 条文档，其 Top-40 完整覆盖率为 70%。该数字使用了自主 Agent 两倍的返回证据预算，因此保留为扩展诊断，不作为同预算验收基线。Oracle 每条查询取前 20 条、合计最多 40 条时为 89%，同样不计为产品收益。

自主提示只要求收集充分证据并自行决定是否需要补充搜索，没有要求必须调用两次。100 条双主题问题均触发两次成功搜索；第二次搜索在 81 条中加入了首轮没有命中的相关证据，并在 68 条中使结果从不完整变为完整。两次结果的平均跨轮重复率为 0。模型另有 6 次第三搜索尝试，全部被工具拒绝，拒绝率为 100%。该结果证明双主题样本上的两轮收益，不证明 Agent 面对单主题问题时也能正确停止在一次搜索。

## 4. 引用编号修复

原实现每次 `knowledge_search` 都从 `K1` 开始，同一 Agent turn 的两次结果无法唯一对应。修复后，第 `callIndex` 次预留调用从 `callIndex × maxResults + 1` 开始编号；例如 `maxResults=10` 时，第一次使用 `K1` 至 `K10`，第二次使用 `K11` 至 `K20`。失败、截断和并发调用仍占用已预留区间，下一 turn 重新从 `K1` 开始；没有 Agent 上下文的直接调用每次从 `K1` 开始。

真实 Loader 轨道的 99 个非空最终回答均使用 `K<n>` 引用，所有引用都能映射到当前 turn 的唯一检索结果；没有重复编号、越过预留区间或无法解析的引用。剩余一条运行在相同 `maxTokens=2048` 配置下没有生成非空最终回答，但两次检索成功，其证据覆盖仍计入检索指标。单元、集成和 keyless Loader snapshot 另行覆盖并发预留、失败后继续、跨 turn 重置和第二次检索编号。

## 5. 延迟与 token 成本

确定性检索延迟不含模型生成：完整问题单次检索 p50 / p95 为 39.93 / 41.31 ms，成本对齐单次检索为 41.91 / 52.66 ms，两条预定义查询 Oracle 为 59.41 / 61.15 ms。

真实 Loader 延迟包含模型生成和工具调用。模型单查询轨道 p50 / p95 为 13.97 / 21.53 秒，总输入 / 输出 token 为 403,723 / 133,406；自主 Agent 轨道为 16.62 / 22.83 秒，总输入 / 输出 token 为 784,833 / 165,379。单查询轨道由工具强制只有一次成功搜索，27 次额外尝试均被拒绝；自主轨道有两次成功搜索，6 次第三尝试均被拒绝。

## 6. 限制

- 完整证据覆盖按核验文档 ID 计算，不评价开放式答案的全部事实、文风或医学建议质量。
- Agent 轨道使用 `deepseek-v4-flash`、`reasoningEffort=low` 和 `maxTokens=2048`；模型、提示或预算变化需要重新运行。
- 最终保留结果对没有非空回答的样本使用相同配置最多重试两次；机器报告记录该策略和最终原始结果摘要。
- 100 条样本都是显式双主题问题，不能用于估计普通单问题中的第二轮触发率。

## 7. 验收状态

- 引用编号冲突：已修复，并由单元、集成、snapshot 和真实 Loader 结果验证。
- 100 条样本语义复核：100/100 通过。
- 三种合理单轮基线、Agent 自主决策和 Oracle：已完成。
- 自主 Agent 相对同候选、同返回证据预算的最佳单轮基线：`68% - 52% = +16 pp`，通过 `+10 pp` 门槛。
- 第三次调用拒绝率：6/6，100%。

因此 T4 完成。后续优化重点是缩小自主 Agent 与同证据预算 Oracle 之间的 12 个百分点差距，并单独处理少量未生成最终回答的模型运行；不得恢复使用原始“0%→94%”作为产品收益结论。

T4 只覆盖显式双主题问题。后续的[两轮触发判断混合评测](rag-plugin-phase-four-search-decision-report.md)补充了单主题、中间事实、首轮充分和证据冲突场景，并验证模型在首轮后继续或停止的判断。
