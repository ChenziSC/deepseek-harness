# DSH RAG 插件第四阶段向量构建报告

本文记录 T5 内容寻址向量缓存的正确性结果，以及 T6/T7 从零构建候选方案和增量构建的性能结果。机器摘要见 [`data/vector-build-evaluation-summary.json`](data/vector-build-evaluation-summary.json)。原始索引、缓存和计时输出只保留在 `packages/experimental/knowledge-local/.cache/`，不进入提交。

## 1. 结论

T5 完成。构建器可以从已验证的格式 3 Exact 索引导入向量，并按完整 Dense 配置与准确 Dense 输入进行内容寻址复用。新增、删除、重排、标题变化、章节路径变化、重复输入、配置变化、损坏缓存和中断恢复均有自动化覆盖；源索引保持只读，目标仍在全部载荷成功后才发布清单。

内容寻址缓存对局部修改有明确正收益。正式 T7 使用 800 篇真实 SciFact 文档生成 1,096 个分片，每组重复三次。平均冷启动为 273.2 秒；0%、约 1% 和约 10% 文档标题变化分别为 65.7、68.0 和 83.4 秒，减少 76.0%、75.1% 和 69.5%。100% 变化为 277.7 秒，比冷启动慢 1.6%，没有产生有意义的额外成本。

T6 的长度分桶候选不采用。它把三次运行的平均时间从 108.3 秒降至 94.5 秒，但同一 21 查询子集的 MRR@10 从 0.8016 降至 0.7500，nDCG@10 从 0.8282 降至 0.7898，向量最小余弦相似度为 0.9875。仅把固定批次从 32 提高到 64 的吞吐收益约为 4%，但峰值 RSS 从 5.09 GB 增至约 7.17 GB，因此默认批次仍为 32。仓库不保留这两个未通过质量或资源门槛的候选实现。

T7 通过。三次冷启动及三次未变化复用的 Exact 排名和 21 条 qrels 指标完全一致；未变化 Exact 载荷逐字节一致。中断实验在提交 160 个新向量后终止，目标目录没有清单；恢复构建复用这 160 个向量、只编码其余 936 个，源索引摘要保持不变，最终 Exact 载荷与未中断构建相同。后续的真实 Markdown 结果见[分片消融报告](rag-plugin-phase-four-markdown-ablation-report.md)。

## 2. 缓存语义

缓存文件固定为 `vectors.sqlite`。键使用长度明确编码的 SHA-256，输入包括模型 ID、revision、模型文件、dtype、pooling、归一化、维度、输入 token 上限、查询前缀、编码实现版本，以及标题、章节路径和分片正文组成的完整 Dense 输入。

缓存按构建批次查询。每个缺失键只编码一次，同一批次或后续批次中的重复输入直接复用。成功的 embedding 批次先在 SQLite 事务中提交，再写目标 Exact 序列或加入 HNSW；失败批次不会部分可见。目标向量始终按新 ordinal 组装，HNSW 始终完整重建。

`--import-vectors-from` 强制重算源索引全部载荷摘要，并要求源索引保留 Dense 配置一致的 `dense.f32le`。导入按源 ordinal 读取 SQLite Dense 输入和 Exact 向量，仅写缓存，不修改源文件。

## 3. 正式 T7 性能验证

固定输入为 SciFact 前 800 篇文档，使用 BGE-M3 q8、384/64 分片、512 Dense token 上限、32 条固定 embedding 批次和 Exact 输出，共生成 1,096 个分片。Dense 输入合计 321,122 token，固定批次 padding 比例为 29.69%。冷启动平均吞吐为 4.01 分片/秒和 1,175 输入 token/秒；只计算 embedding 阶段时为 5.32 分片/秒和 1,560 输入 token/秒。

| 变化组 | 缓存命中 | 新编码 | 平均总时间 | 标准差 | 平均峰值 RSS | 相对冷启动 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 冷启动 | 0 | 1,096 | 273.2 s | 2.08 s | 4.78 GiB | 基线 |
| 0% | 1,096 | 0 | 65.7 s | 0.59 s | 1.05 GiB | -76.0% |
| 约 1% 文档标题变化 | 1,082 | 14 | 68.0 s | 0.59 s | 2.67 GiB | -75.1% |
| 约 10% 文档标题变化 | 982 | 114 | 83.4 s | 0.56 s | 2.76 GiB | -69.5% |
| 100% 文档标题变化 | 0 | 1,096 | 277.7 s | 0.30 s | 4.86 GiB | +1.6% |

一次 0% 复用构建对目标索引和向量缓存进行 100 毫秒间隔采样，峰值工作磁盘为 14,380,872 字节，完成时为 14,341,629 字节。三次同时保留 Exact 与 HNSW 的构建平均为 65.0 秒，HNSW 添加与保存平均仅占 62.3 和 7.5 毫秒；21 条 qrels 的 HNSW 质量指标与 Exact 相同，三次 HNSW 相对 Exact 的 Recall@10 为 1、1 和 0.9952。

MRR@10、nDCG@10 和 Recall@10 在三次冷启动及三次 0% 复用中均为 0.7143、0.7500 和 0.8571。该验证只用于确认复用不改变结果，不把 21 条子集解释为通用质量结论。

## 4. 早期 417 分片样本

固定输入为 SciFact 前 300 篇文档，使用 BGE-M3 q8、384/64 分片、512 Dense token 上限、32 条固定 embedding 批次和 Exact 输出，共生成 417 个基线分片。每个变化组先从同一基线 Exact 索引预热独立缓存。

| 变化组 | 缓存命中 | 新编码 | 复用率 | 总时间 | 相对 105.3 秒冷启动 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0% | 417 | 0 | 100% | 24.9 s | -76.3% |
| 约 1% 文档标题变化 | 412 | 5 | 98.80% | 25.7 s | -75.6% |
| 约 10% 文档标题变化 | 374 | 43 | 89.69% | 32.0 s | -69.6% |
| 100% 文档标题变化 | 0 | 417 | 0% | 105.8 s | +0.5% |

0% 组没有加载 Dense 模型，导入耗时 24 毫秒、缓存查询耗时 4 毫秒。1% 和 10% 组只加载一次模型，并分别编码 5 和 43 个受影响分片。缓存复用的 Exact 向量与源索引逐字节一致。

## 5. 从零构建候选

固定 32 条批次下，单次当前实现的阶段时间为：语料暂存 0.01 秒、分片 25.68 秒、embedding 79.59 秒、Exact 写入 0.01 秒、模型加载 0.73 秒，总时间 105.30 秒。主要瓶颈仍是 embedding，其次是分片 tokenizer。

长度分桶在 128 条有界窗口内按 token 长度排序，保持 32 条上限。三次结果为 94.58、94.48 和 94.40 秒；对照三次为 107.63、108.51 和 108.70 秒。padding 比例从 30.12% 降至 13.74%，但检索质量下降，因此不保留实现。

固定批次 64 的三次构建为 99.80、101.24 和 100.77 秒。相对当前 32 条批次的 105.30 秒样本，收益不足以抵消峰值 RSS 从 5,085,544,448 字节增至 7,149,404,160 至 7,185,727,488 字节；默认值不变。

## 6. 验证状态

- 内容寻址缓存、索引导入和构建器/CLI 定向覆盖率：语句、分支、函数、行均为 100%。
- 真实模型增量路径：1,096 分片的 0%、约 1%、约 10% 和 100% 标题变化各完成三次；0% 组未加载模型。
- 从零候选：长度分桶因质量下降被拒绝；64 条批次因内存增幅过高不设为默认。
- 中断恢复：已提交批次得到复用，未完成目标未发布清单，源索引保持不变。
- Exact/HNSW：三次近似召回和标准 qrels 结果已记录。

因此 T5 和 T7 完成，并为 Markdown 消融提供内容寻址复用基础；T6 没有产生可安全启用的从零默认优化。
