# DSH RAG 插件第四阶段两轮触发判断报告

本文记录第四阶段 T4.1 的 100 条混合评测。固定输入见 [`data/retrieval-decision-samples.jsonl`](data/retrieval-decision-samples.jsonl)，受控语料见 [`data/retrieval-decision-controlled-corpus.jsonl`](data/retrieval-decision-controlled-corpus.jsonl)，聚合结果见 [`data/retrieval-decision-evaluation-summary.json`](data/retrieval-decision-evaluation-summary.json)。模型原始响应、会话日志和临时索引只保留在 `.cache` 与 `.sessions`。

## 1. 结论

T4.1 通过。工具仍将单个 Agent turn 限制为最多两次搜索；更新后的提示要求首条查询覆盖同一主题的全部字段，只在必要证据缺失、证据冲突或缺少中间事实时补充一次搜索，并要求使用首轮发现的不透明标识符直接查询目标记录。

100 条混合请求上的必要第二轮触发召回率为 92.31%，触发精确率为 100%，首轮充分停止率为 100%，总体判断准确率为 95%，均超过 80% 门槛。第二轮命中先前缺失证据的比例为 91.67%；中间事实与冲突场景成功率均为 100%。一次第三次搜索尝试被运行时拒绝，拒绝率为 100%；最终回答中的 568 个引用全部可解析，跨调用引用冲突为 0。

这组结果证明最多两轮的策略能够在混合请求中正确区分大多数继续和停止情况。它不证明两轮能够解决所有检索召回失败：最终完整证据覆盖率为 87%，剩余失败集中在自然 T2Ranking 语料，而不是受控的中间事实、首轮充分或冲突场景。

## 2. 样本与运行配置

| 场景 | 数量 | 数据与目的 |
| --- | ---: | --- |
| 单主题 | 25 | 已独立复核的 T2Ranking 子问题，检查通常在首轮后停止 |
| 双主题 | 25 | 已独立复核的 T2Ranking 合取问题，检查缺失一组证据时继续 |
| 中间事实多跳 | 20 | 首轮只给出不透明档案代码，第二轮必须使用该代码查目标记录 |
| 首轮已经充分 | 15 | 一篇设备卡同时包含两个字段，检查不机械触发第二轮 |
| 首轮证据冲突 | 15 | 两份通知给出冲突日期，首轮提供裁定代码，第二轮查最终裁定 |

自然语料轨道复用 T2Ranking 10k 格式 3 Exact Dense 索引，每次取 50 个候选并返回 10 条证据。受控轨道从一份固定的 100 文档 JSONL 语料为每条样本派生包含 1 至 3 篇文档的小型 BM25 索引；这样首轮证据状态由样本定义，不把 BM25 排名噪声误计为搜索决策错误。受控索引不构建 Dense 向量。

真实 Loader 使用 Aiden 路由的 `ark-deepseek-v4-flash`，未显式设置推理强度，Reranker 关闭。评测配置只暴露 `knowledge_search`，避免子 Agent 或其他工具绕过同一 turn 的两次搜索限制。两条轨道都使用 `maxResults=10` 和 `maxSearchesPerTurn=2`。

## 3. 判断与证据结果

| 指标 | 结果 | 门槛 |
| --- | ---: | ---: |
| 必要第二轮触发召回率 | 60/65，92.31% | ≥80% |
| 第二轮触发精确率 | 60/60，100% | ≥80% |
| 首轮充分停止率 | 35/35，100% | ≥80% |
| 总体判断准确率 | 95/100，95% | ≥80% |
| 第二轮命中先前缺失需求 | 55/60，91.67% | ≥70% |
| 第二条查询精确重复首轮 | 0/60 | 0 |
| 中间事实查询使用桥接标识符 | 20/20，100% | ≥80% |
| 中间事实成功率 | 20/20，100% | ≥80% |
| 冲突处理成功率 | 15/15，100% | ≥80% |
| 第三次调用拒绝率 | 1/1，100% | 100% |
| 已输出引用可解析率 | 568/568，100% | 100% |

成功搜索次数分布为 40 条一次、60 条两次。没有首轮充分后仍成功执行第二次搜索的样本。一个单主题样本首次调用显式传入 `retrieval=auto`、`denseIndex=auto` 和 `rerank=auto`，因固定配置禁止 Reranker 而失败；模型随后省略这些参数并完成一次有效搜索。该无效调用单独记录，不计为有效第二轮。

## 4. 分场景结果

| 场景 | 判断准确率 | 最终完整证据覆盖率 | 说明 |
| --- | ---: | ---: | --- |
| 单主题 | 80% | 80% | 20 条首轮命中后全部停止；5 条首轮未命中核验证据但模型没有改写查询 |
| 双主题 | 100% | 68% | 25 条全部正确触发第二轮；8 条仍受 Dense 召回限制 |
| 中间事实多跳 | 100% | 100% | 20 条第二查询全部只使用首轮发现的档案代码，并命中目标记录 |
| 首轮已经充分 | 100% | 100% | 15 条全部在一次搜索后停止 |
| 首轮证据冲突 | 100% | 100% | 15 条均先发现两份冲突通知，再以裁定代码命中解决记录 |

五个单主题漏触发样本的首轮 Dense 结果没有包含核验文档，模型仍依据邻近内容直接回答。它们分别涉及“不破楼兰终不还”两条重复问法、强行亲吻的法律判断、清洁生产企业发展观和朝鲜战争伤亡人数。该结果说明提示规则能可靠处理显式缺口和冲突，但不能仅靠模型阅读首轮结果识别所有隐性的召回失败。

双主题的 8 条最终覆盖失败都执行了正确的两次查询，但至少一个查询没有召回指定核验文档。因此 T4.1 对“是否继续搜索”的结论为正，对自然语料的最终召回质量不作额外提升声明。

## 5. 运行时限制与引用

模型在一条双主题样本上尝试第三次 `knowledge_search`，运行时返回 `current turn is limited to 2 searches`，没有执行提供方检索。100 条最终回答均非空，所有引用都落在当前 turn 已分配的 `K<n>` 区间，未发现跨调用编号冲突。

提示和工具 schema 已明确要求省略未被用户指定的 `retrieval`、`denseIndex` 与 `rerank`。本次仍观察到一次显式 `auto` 参数错误，说明提示只能降低而不能消除无效参数调用；硬限制和提供方配置仍负责阻止不允许的策略。

## 6. 验收状态

- 最多两次搜索：保持运行时硬上限，第三次尝试 1/1 被拒绝。
- 继续与停止判断：四项核心指标全部通过。
- 中间事实与冲突：两类均 100% 成功。
- 引用：568/568 可解析，跨调用冲突为 0。
- 已知限制：自然语料最终完整证据覆盖率不是 100%，一次模型调用仍擅自传入 `auto` 参数。

因此 T4.1 完成。后续[向量构建报告](rag-plugin-phase-four-vector-build-report.md)不把本评测的受控 BM25 结果解释为自然语料检索质量收益。
