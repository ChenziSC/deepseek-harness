# DSH RAG 两轮检索触发规则与混合评测规格

本文定义第四阶段 T4.1。该任务在进入向量缓存和建库优化前，固定最多两次搜索的运行时上限，明确第二次搜索的判断规则，并验证 Agent 在需要补充证据时继续搜索、在首轮证据充分时停止。两轮检索的既有收益和限制见[两轮检索评测报告](rag-plugin-phase-four-two-search-report.md)。

## 1. 当前机制与问题

`@deepseek-ai/dsh-experimental-tool-knowledge` 通过稳定系统提示引导模型使用 `knowledge_search`，并通过 `maxSearchesPerTurn=2` 强制每个 Agent turn 最多执行两次搜索。提供方负责解析 BM25 或 Dense 等检索策略，不判断问题复杂度或证据充分性。

第二次搜索目前由模型阅读首轮结果后自行决定。运行时没有复杂问题分类器、统一相关性分数阈值、qrels 或答案正确性判定器。T4 已证明两轮搜索能够提高显式双主题问题的完整证据覆盖率，但 100 条样本全部触发两次搜索，因此尚未证明模型能够在混合请求中正确继续或停止。

## 2. 产品策略

默认策略保持最多两次搜索，不开放普通请求的第三次及后续搜索：

1. 搜索前识别请求中相互独立的证据需求。
2. 默认先执行一次搜索。
3. 仅当必要需求缺少直接支持、首轮证据冲突，或回答所需的中间事实缺失时执行第二次搜索。
4. 第二条查询只针对缺失需求、冲突核验或首轮发现的中间实体，不重复首轮查询，也不只为增加结果数量而搜索。
5. 两次搜索后必须使用现有证据回答并说明剩余不确定性。

检索分数不参与通用充分性判断。BM25、Dense 和 Hybrid 的分数不可直接比较，同一策略的高分也不表示多个证据需求均已覆盖。运行时硬上限和引用区间分配继续由工具代码执行；证据需求识别与充分性判断仍由模型完成。

该规则属于始终加载的工具使用约定，应写入 `knowledge_search` 系统提示和包文档，而不是依赖可选 Skill。面向长时间、多来源研究的三轮以上检索属于独立显式模式，不在本任务范围内。

## 3. 混合样本

评测固定 100 条样本，覆盖五种场景：

| 场景 | 数量 | 目的 |
| --- | ---: | --- |
| 单主题 | 25 | 验证一个证据需求通常能够在首轮后停止；首轮未命中时允许补充搜索 |
| 双主题 | 25 | 验证两个独立证据需求缺一时能够发起针对性第二轮 |
| 中间事实多跳 | 20 | 第二条查询必须使用首轮发现、原问题未直接给出的桥接实体或事实 |
| 首轮已经充分的复合问题 | 15 | 即使问题包含多个子句，只要首轮覆盖全部需求就不得机械执行第二轮 |
| 首轮证据冲突 | 15 | 首轮出现互斥结论时，应通过第二轮查找指定的权威或更新证据并保留不确定性 |

单主题和双主题样本复用已经通过独立 Agent 复核的 T2Ranking 问题与证据。中间事实、首轮充分复合问题和冲突问题使用小型固定语料，明确记录文档来源角色、桥接实体、冲突双方和解决证据；该语料只构建 BM25 索引，不生成新的 Dense 向量。

每条样本记录：

- 稳定样本 ID 和场景；
- 用户问题；
- 独立证据需求及每项允许的文档 ID；
- 对受控样本记录桥接实体或冲突解决文档；
- 输入语料、查询集和样本文件摘要；
- 是否允许根据首轮实际结果动态判断第二轮必要性。

## 4. 第二轮必要性判定

评测器不根据问题文字长度或固定场景标签直接判定第二轮是否必要，而是检查首轮实际返回结果：

- **首轮充分**：每个必要证据需求均至少有一篇允许文档被返回，且没有待解决冲突。期望行为是停止搜索。
- **首轮不完整**：至少一个必要需求没有直接支持。期望行为是执行第二次搜索。
- **首轮冲突**：互斥证据同时出现但缺少指定解决证据。期望行为是执行第二次搜索；若第二轮仍无法解决，最终回答必须说明冲突。
- **中间事实缺失**：首轮尚未取得桥接实体。此时不能要求模型猜测第二条查询；首轮取得桥接实体但目标证据未出现时，期望第二条查询包含该实体并搜索目标事实。

如果首轮工具调用失败，样本单独记为工具失败，不计入继续或停止判断的分母。无效参数调用会消耗搜索额度并单独报告，不能算作有效第二轮。

## 5. 指标

机器报告总体及按场景记录：

- 首轮完整证据覆盖率和最终完整证据覆盖率；
- 必要第二轮触发召回率：首轮不充分样本中实际执行有效第二轮的比例；
- 第二轮触发精确率：执行有效第二轮的样本中首轮确实不充分的比例；
- 充分证据停止率：首轮充分样本中停止在一次搜索的比例；
- 判断准确率：正确继续和正确停止占全部可判定样本的比例；
- 第二轮新增相关证据率、补全全部需求比例和跨轮重复率；
- 中间事实样本中，第二条查询包含已核验桥接实体的比例；
- 冲突样本中，第二轮命中解决证据或最终明确保留冲突的比例；
- 0、1、2 次有效搜索分布、无效调用和第三次调用拒绝率；
- p50/p95 墙钟时间及输入、输出、缓存读取和推理 token；
- 非空最终回答比例、引用可解析率和跨调用引用冲突数。

## 6. 验收标准

| 指标 | 门槛 |
| --- | ---: |
| 必要第二轮触发召回率 | ≥ 80% |
| 第二轮触发精确率 | ≥ 80% |
| 充分证据停止率 | ≥ 80% |
| 总体判断准确率 | ≥ 80% |
| 第二轮查询精确重复首轮 | 0 |
| 第二轮命中先前缺失需求 | ≥ 70% |
| 中间事实查询使用正确桥接实体 | ≥ 80% |
| 冲突处理成功率 | ≥ 80% |
| 第三次调用拒绝率 | 100% |
| 已输出引用的可解析率 | 100% |

最终证据覆盖率必须同时报告，不能为了提高继续搜索的触发率而忽略质量。如果判断指标未达门槛，保留报告并进一步收紧提示词；不通过增加搜索上限绕过失败。

## 7. 实施与验证顺序

1. 更新工具提示、英文与中文 README、Agent Note 和真实 Loader snapshot。
2. 固定 100 条混合样本和受控 BM25 语料，记录摘要。
3. 使用同一模型运行一次真实 Loader 评测；每条轨道固定检索方式、索引、候选数和结果数，并在报告中说明轨道差异。
4. 生成逐样本结果和聚合机器报告，人工抽查中间事实与冲突失败项。
5. 运行工具包定向逐文件覆盖率、snapshot、`typecheck`、`lint`、`doc-sync`、`build`、`hygiene` 和 `git diff --check`。
6. T4.1 通过后才开始 T5 内容寻址向量缓存与后续建库优化。

模型原始响应、会话日志、模型缓存和索引保留在 `.cache` 或 `.sessions`，不进入提交。提交范围只包含固定输入、摘要报告、代码、测试和文档；未经用户明确要求不 commit 或 push。
