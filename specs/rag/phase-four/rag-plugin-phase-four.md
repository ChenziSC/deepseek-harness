# DSH RAG 插件第四阶段概要设计规格

本文定义第四阶段的范围、顺序和验收标准。前三阶段的实现和现有证据见[第一阶段实验报告](../phase-one/rag-plugin-phase-one-e1-experiment-report.md)、[第二阶段验收报告](../phase-two/rag-plugin-phase-two-acceptance-report.md)和[第三阶段验收报告](../phase-three/rag-plugin-phase-three-acceptance-report.md)。接口、报告格式和增量向量复用约定见[详细设计](rag-plugin-phase-four-detailed-design.md)，两轮触发判断见[混合评测规格](rag-plugin-phase-four-search-decision-spec.md)与[评测报告](rag-plugin-phase-four-search-decision-report.md)，向量构建结果见[向量构建报告](rag-plugin-phase-four-vector-build-report.md)，分片结果见[Markdown 消融报告](rag-plugin-phase-four-markdown-ablation-report.md)，最终结论见[验收报告](rag-plugin-phase-four-acceptance-report.md)，实施顺序见[实施任务](rag-plugin-phase-four-implementation-tasks.md)。

## 1. 定位

第四阶段不继续增加检索算法，先补齐第三阶段尚缺的效果证据，再降低文档局部修改造成的向量重建成本，最后使用真实 Markdown 语料验证结构分片。工作严格分为两个批次：第一批完成自动路由、自适应 Reranker 和两轮检索评测；第二批先完成向量复用，再运行 Markdown 分片消融。

## 2. 第一批目标

### 2.1 自动路由评测

- 在同一查询和索引上同时运行 `auto`、BM25、Dense 和 Hybrid。
- 记录 `auto` 实际选择、各固定策略质量、查询延迟和相对最佳固定策略的差距。
- 覆盖普通同脚本查询、跨脚本查询和精确标识符查询。
- 复用现有格式 3 的 T2Ranking 与 MLDR English 索引；跨脚本查询通过翻译或改写现有有 qrels 的查询产生，不为查询变化重建向量。
- 如果自动路由不能接近对应数据分组的最佳固定策略，则调整规则或取消其默认地位，不以单元测试通过代替效果结论。

### 2.2 自适应 Reranker 阈值评测

- 将阈值、逐查询 top-2 分差、是否触发、质量变化和延迟写入机器可读报告。
- 分别评测 BM25、Dense 和 Hybrid，不再假设三种召回分数可以共享一个最佳阈值。
- 对比 `off`、多个 `auto` 阈值和 `on`，报告质量增益保留比例、触发率、p50 和 p95。
- 复用现有索引和向量，不重新执行 Dense 编码。
- 当前 `0.15` 继续作为待验证配置，不预设其为最终默认值。找不到跨数据集稳定阈值时，性能默认保持 `off`，质量请求使用显式 `on`。

### 2.3 两轮检索的 100 条多跳样本

- 建立 100 条需要两组互补证据的多跳样本，每条记录问题、首轮查询、补充查询和两组证据文档 ID。
- 优先从现有 T2Ranking 格式 3 语料中选取证据，不增加大规模语料和向量构建。
- 先运行预定义查询的确定性检索上限，再运行真实 Loader 组合，区分“检索器找不到”和“模型没有正确发起第二轮”。
- 单轮基线至少包括完整组合问题直接检索一次、模型生成一条综合查询，以及候选预算与两轮接近的一次检索；另运行不暗示必须搜索两次的 Agent 自主决策轨道。
- 两条预定义查询只作为 Oracle 上限，不把“第一个子查询”当作有竞争力的单轮基线，也不把两者差异表述为产品收益。
- 对比各单轮基线、Agent 自主决策和 Oracle，报告完整证据覆盖率、第二轮边际命中率、重复检索率、调用次数、候选预算、延迟和 token 成本。
- 本评测只判断证据获取和引用 ID 是否正确，不扩展为通用答案事实评分。

### 2.4 两轮触发判断

- 最多两次搜索的运行时上限保持不变，不把普通 RAG 扩展为无界研究循环。
- 工具提示明确要求模型先识别独立证据需求，首轮后仅在需求缺少直接支持、证据冲突或缺少中间事实时补充搜索。
- 使用单主题、双主题、中间事实多跳、首轮充分复合问题和冲突问题组成的 100 条混合集合验证继续与停止判断。
- 第二轮必要性按首轮实际证据覆盖和冲突状态判断，不使用问题长度、固定关键词或不可跨策略比较的召回分数。
- T4.1 通过后才开始内容寻址向量缓存和后续建库优化。

## 3. 第二批目标

### 3.1 统一向量构建管线

本地索引仍以完整、不可变目录发布，但向量生成拆为内容寻址缓存、缺失向量编码和索引组装三个步骤。缓存键由固定版本的 Dense 配置和送入模型的完整文本计算，不使用文档路径、chunk ordinal 或旧 `chunk_id`。这是局部更新、失败续跑和重复实验共用的基础。

新语料完成分片后先查询缓存。命中项直接复制向量到新的 ordinal，只有新增或变化的输入调用 embedding。格式 3 Exact 索引可以经过严格验证后导入缓存，使现有产物成为缓存种子；没有 Exact 载荷的索引不能导入。服务索引和构建缓存分离，因此 HNSW-only 发布物也能在后续构建中复用已经持久化的向量。

新索引始终重新生成 SQLite、清单和目标 Dense 文件。HNSW 第一版仍从完整的新向量序列重建，不实现原地图增删。模型配置、输入文本或向量维度不一致时必须产生缓存未命中或明确拒绝导入，不能静默使用不匹配向量。删除、插入和文档重排不得造成向量与新 ordinal 错配。

### 3.2 从零构建优化

空缓存构建不能从内容复用获益，因此使用同一管线评估缺失向量编码阶段的吞吐候选。按 token 总量限制的动态批处理、长度分桶、有界流水线和额外 worker 只有在结果一致性、标准检索指标和资源上限都通过后才保留；未通过的候选只记录实验结果，不进入受支持构建路径。

并行模型实例、运行时线程数和 HNSW 独立 worker 只作为抽样基准候选。ONNX Runtime 已可能占用多个 CPU 核，只有重复样本证明吞吐提高且峰值 RSS 可接受时才启用额外并行。构建缓存按已完成批次提交，使首次构建中断后可以从最后一个完整批次继续，而不重新编码已经成功的输入。

性能验证使用小规模样本，不重新编码全部 100k 向量。验证覆盖空缓存、热缓存、无变化、少量局部修改、文档新增、删除、重排和模型配置不匹配，并将优化结果与相同小样本的当前串行固定批次构建比较。

### 3.3 真实 Markdown 分片消融

增量向量复用完成后，使用固定版本的真实 Markdown 文档建立 token 窗口基线和结构感知索引。候选语料优先使用本仓库真实文档，但必须固定文件清单、Git revision 和语料摘要，排除生成文档、归档记录和测试 fixture。

查询集至少覆盖章节标题、章节内事实、代码围栏、跨相邻块证据和重复标题。评测比较检索质量、完整证据覆盖率、上下文重复率、返回 token 数和查询延迟；相邻扩展在同一结构索引上分别关闭和开启，不为该开关重新构建向量。

结构分片只有在结构敏感查询上产生可重复收益，且整体标准检索指标没有明显倒退时，才能获得效果验收。若只通过行为测试而没有质量或上下文完整性提升，报告必须将其标记为功能完成但收益未证明。

## 4. 现有产物复用

以下格式 3 产物可直接使用，不执行 Dense 重建：

- `.cache/rag-phase-three/mldr-en-q20-index/`
- `packages/experimental/knowledge-local/.cache/rag-threshold-calibration/index-10000/`
- `packages/experimental/knowledge-local/.cache/rag-threshold-calibration/index-25000/`
- `packages/experimental/knowledge-local/.cache/rag-threshold-calibration/index-50000/`
- `packages/experimental/knowledge-local/.cache/rag-threshold-calibration/index-100000/`

第二阶段格式 2 的 SciFact、MLQA、MLDR Chinese 和旧 T2Ranking 索引不能直接作为第四阶段正式产物。只有重新运行当前分片器并逐条证明 Dense 输入、ordinal、模型配置和向量数量完全一致时，才允许通过离线转换复用 Exact 向量；否则重新编码。格式兼容验证不得进入运行时加载路径。

## 5. 验收指标

| 项目 | 必须报告 | 效果判定 |
| --- | --- | --- |
| 自动路由 | 路由分布、分类命中率、Recall、MRR、nDCG、p50/p95、相对最佳固定策略差距 | 主要数据分组的 nDCG@10 不低于最佳固定策略超过 1 个百分点；失败时调整规则或默认值 |
| 自适应 Reranker | 每阈值触发率、质量增益保留比例、p50/p95、逐召回方式结果 | 至少两个数据集存在低于 100% 的触发率，并保留 `on` 至少 70% 的 MRR@10 与 nDCG@10 增益；否则不推荐 `auto` |
| 两轮检索 | 三种合理单轮基线、Agent 自主决策和预定义查询 Oracle 的完整证据覆盖率、第二轮边际命中、重复率、候选预算、调用与 token 成本 | Agent 自主决策相对最佳合理单轮基线的完整证据覆盖率至少提高 10 个百分点，且第三次调用拒绝率为 100%；Oracle 不计为产品收益 |
| 两轮触发判断 | 必要第二轮触发召回率与精确率、充分证据停止率、判断准确率、中间事实和冲突处理、调用与 token 成本 | 四项判断指标均不低于 80%，第二轮命中先前缺失需求不低于 70%，第三次调用拒绝率与已输出引用可解析率为 100% |
| 向量复用 | 缓存命中数、重编码数、复用率、embedding 时间、总构建时间、结果一致性 | 未变化输入 100% 复用；局部修改时 embedding 调用量随变化量增长；中断后不重复编码已提交批次 |
| 从零构建 | chunks/s、tokens/s、批次 padding 比例、p50/p95 批耗时、RSS、临时磁盘 | 在固定小样本上重复运行后吞吐稳定提高，且质量和资源上限无回退；没有稳定收益的并行方案不得进入默认路径 |
| Markdown 消融 | 标准检索指标、结构子集指标、完整证据覆盖、重复率、token 数和延迟 | 结构子集取得可重复正收益，整体 nDCG@10 不下降超过 1 个百分点 |

上述门槛用于决定默认行为，不要求实验为了通过门槛而修改实现。结果不通过时，保留报告和原始数据，并明确降低、关闭或撤回对应默认策略。

## 6. 非目标

本阶段不执行新的 Exact/HNSW 大规模阈值扩展，不新增超过 100k 分片的向量规模，不实现 HNSW 原地图增删，也不建立通用答案级验收体系。两轮检索只评估证据获取与引用，不评价开放式回答文风或完整事实正确率。

本阶段不引入远程向量数据库、后台索引服务、在线自动调参、查询分类模型、GraphRAG、RAPTOR 或新的 ANN 算法。

## 7. 完成条件

- 第一批三个效果评测及两轮触发判断均生成可复现的机器可读报告和中文结论。
- 增量构建只编码缓存未命中的输入；从零构建候选完成小样本吞吐、结果一致性和资源比较，并对是否采用给出明确结论。
- Markdown 消融在增量构建完成后执行，报告结构分片及相邻扩展的独立结果。
- 新增代码保持相关包逐文件 100% coverage；模型可见行为变化更新真实 Loader 快照。
- `typecheck`、`lint`、相关测试、`doc-sync`、`hygiene` 和 `git diff --check` 通过。
- 不提交模型、向量、索引、下载数据或包含本机绝对路径的报告。
