# DSH RAG 插件第五阶段语义边界 Pilot 报告

## 1. 结论

语义边界 pilot 未达到继续实现门槛，因此本阶段不实现 `semantic-boundary-v1`、边界向量缓存或三路正式建库消融。现有 `markdown-structure-v1` 继续作为默认分片策略。

受长度约束的最大语义间隙算法在6条人工标注主题切换样本上的精确边界召回率为50%，与不使用语义向量、直接选择长度范围内最后一个安全单元的基线相同；其平均边界数为1.50，基线为1.00，近邻边界精确率反而从100%降至83.33%。文档内80百分位和固定0.25距离阈值的精确边界召回率均为33.33%。这些结果没有证明额外模型计算能产生更好的切点。

## 2. 方法

Pilot 使用固定 revision 的 BGE-M3 q8模型和10份小型文档，其中6份标注主题切换边界，另有代码围栏、短文档、语义同质文本和无句末标点长句各1份。候选单元优先采用空行分隔段落，超长段落再按中英文句末拆分，仍超长时按Unicode代码点安全硬切分。完整且未超过上限的代码围栏保持为一个单元。

参数固定为 `maxTokens=120`、`semanticMinTokens=40` 和前后各1个候选单元的语义窗口。比较项为：

- `last-safe-unit`：不使用向量，选择长度范围内最后一个安全候选单元；
- `constrained-max-gap`：在合法长度范围内选择语义距离最大的边界；
- `document-p80`：使用每篇文档的80百分位距离阈值；
- `absolute-0.25`：使用固定0.25距离阈值。

继续条件在运行前固定为：最大语义间隙相对 `last-safe-unit` 的精确边界召回率至少提高10个百分点，并且所有分片都不超过 `maxTokens`。

## 3. 结果

| 算法 | 精确边界精确率 | 精确边界召回率 | 相邻一个单元内精确率 | 相邻一个单元内召回率 | 平均边界数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `last-safe-unit` | 50.00% | 50.00% | 100.00% | 100.00% | 1.00 |
| `constrained-max-gap` | 50.00% | 50.00% | 83.33% | 100.00% | 1.50 |
| `document-p80` | 33.33% | 33.33% | 83.33% | 100.00% | 1.50 |
| `absolute-0.25` | 33.33% | 33.33% | 91.67% | 100.00% | 1.17 |

10/10候选单元解析检查通过，代码围栏保持完整，短文档没有拆分，无句末标点长句触发硬切分；所有观测分片均满足120 token上限。完整运行约4.14秒，其中边界窗口编码约1.69秒。时间只描述本机小样本，不作为构建性能保证。

## 4. 决策与限制

最大语义间隙没有超过无模型基线，还生成更多边界；百分位和绝对阈值结果更差。继续实现会引入异步分片、第二种向量用途、缓存身份和额外建库成本，却没有对应的边界质量证据，因此按预设停止规则终止 T6 与 T7。

该 pilot 只评估候选边界，不是完整检索质量实验，也不能证明语义分片在所有语料上无效。若未来有大量弱结构长文档和人工证据范围，应先扩大独立 pilot，并要求边界指标稳定超过无模型基线，再重新考虑正式实现；不能直接以本次样本调参后进入三路建库。
