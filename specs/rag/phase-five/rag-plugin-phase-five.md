# DSH RAG 插件第五阶段概要设计规格

本文定义第五阶段的范围、默认策略决策和验收标准。现有能力与第四阶段效果结论见[第四阶段验收报告](../phase-four/rag-plugin-phase-four-acceptance-report.md)，算法、接口和评测细节见[详细设计](rag-plugin-phase-five-detailed-design.md)，实施顺序见[实施任务](rag-plugin-phase-five-implementation-tasks.md)。

## 1. 定位

第五阶段处理三个仍限制当前 RAG 效果的环节：先用低成本 pilot 判断语义分片是否值得进入正式实现；把“最多补充一次搜索”扩展为由 Agent 按证据状态决定是否继续的有界循环；在不引入内容审核平台、权限系统或跨工具污点跟踪的前提下，加强检索证据的轻量安全边界。

冲突证据处理归入智能体化 RAG。检索器负责返回可引用的来源和正文，Agent 负责识别冲突、针对缺少的时间、对象、范围或最终裁定继续搜索，并在无法消解时保留不确定性。本阶段不建立独立的通用冲突知识库或确定性事实裁决器。

## 2. 语义分片

### 2.1 候选方案与 Pilot 结论

语义边界 pilot 没有显示相对无模型安全边界基线的精确切点收益，因此本阶段不实现下述候选方案，也不运行高成本三路建库消融。`markdown-structure-v1` 继续作为默认值；重新启动实现需要新的独立 pilot 先满足收益门槛。结果见[语义边界 Pilot 报告](rag-plugin-phase-five-semantic-boundary-pilot-report.md)。

候选 `semantic-boundary-v1` 分片策略使用与 Dense 检索相同的固定 revision BGE-M3 模型计算相邻文本单元的语义距离，但最终分片仍受 `maxTokens` 硬上限约束。语义分片不调用生成式 LLM，不生成摘要，也不属于 RAPTOR、GraphRAG 或上下文感知检索。

文档先被拆成段落、句子和不可安全拆开的短代码围栏等候选单元。系统为每个相邻边界构造包含有限前后单元的窗口，批量生成归一化向量并计算余弦距离；每个允许长度区间选择语义距离最大的边界。没有合格边界或单个单元超过上限时回退到 tokenizer 硬切分。分片完成后继续按现有方式生成最终 Dense 向量，边界向量不能代替最终分片向量。

语义模型默认复用当前 BGE-M3 模型和本地模型缓存，不增加第二套默认模型。语义边界输入使用与最终分片向量隔离的内容寻址缓存命名空间，使未变化文档和中断后的构建可以复用边界向量。BM25-only 索引选择语义分片时仍需要本地语义模型；缺少模型时在建库开始前失败。

### 2.2 未执行的三路消融

只有独立 pilot 通过时，正式实验才比较以下三个完整策略，并且不在结果产生后修改阈值以迁就某一路：

| 策略 | 边界依据 | 额外模型计算 | 章节路径 |
| --- | --- | --- | --- |
| `token-window-v1` | tokenizer 硬上限 | 无 | 无 |
| `markdown-structure-v1` | 标题、段落、句子和代码围栏 | 无 | 有 |
| `semantic-boundary-v1` | 相邻文本单元的语义距离和 token 上限 | 有 | Markdown 输入保留章节路径，但章节标题不直接决定切点 |

主实验关闭 Reranker 和相邻扩展，分别运行 BM25、Dense 和 Hybrid，以隔离分片产生的差异。选出候选默认策略后，再对该策略运行 `adjacentChunkCount=0/1`，确认邻居扩展不会改变默认判断。

评测复用第四阶段的真实 Markdown 固定语料并扩充查询，同时增加具有长段落、弱标题或无标题结构的长文档轨道。报告标准检索指标、完整证据覆盖率、单命中完整率、上下文 token、分片数量、重复率、查询延迟、边界编码成本、最终向量编码成本、总构建时间和峰值 RSS。

### 2.3 默认值决策

第五阶段仍选择一个由 BM25、Dense 和 Hybrid 共用的默认分片策略，不在本阶段引入按召回方式维护两套索引。语义分片只有同时满足以下条件才替换当前 Markdown 默认值：

- 相对 Markdown 结构分片，平均 nDCG@10 至少提高 1 个百分点，或者完整证据覆盖率至少提高 3 个百分点。
- BM25、Dense 和 Hybrid 任一路 nDCG@10 不下降超过 1 个百分点。
- 平均返回 token 不增加超过 10%。
- 冷构建总时间不超过 Markdown 结构分片的两倍，局部修改只重新计算受影响文档及相邻语义窗口。

若没有策略满足门槛，保留 `markdown-structure-v1` 默认值，并分别报告每种策略适合的场景。负结果不通过更换样本、事后选择阈值或只报告获益子集改写为正收益。

## 3. 有界智能体化 RAG

### 3.1 搜索循环

工具提示从“通常一次、最多补充一次”改为证据驱动循环。Agent 每次只发出一个搜索调用，检查结果后再判断独立证据需求是否均有直接支持、是否存在互相冲突的证据、是否缺少继续查询所需的中间事实；只有仍有明确缺口时才构造下一条针对性查询。依赖证据中的不透明标识符时，下一条查询只包含该标识符，避免附加通用词扩大召回范围。证据充分、后续查询只会重复现有结果或无法再提出具体缺口时应停止。

开放式循环不等于无界循环。`maxSearchesPerTurn` 是1至8的可配置有限预算，默认值为6。主评测让同一次 Agent 轨迹最多运行8次，并在第1、2、4、6、8次搜索后记录累计证据覆盖和边际收益；已发生的前缀搜索不会为了比较预算而重复执行。独立硬上限和默认累计输出预算回归确认6次能够覆盖三至六步证据链，而第6至第8次没有新增完整覆盖；详细结果见[有界搜索评测报告](rag-plugin-phase-five-search-budget-report.md)。

新增每轮累计工具输出预算，防止多次搜索使上下文按调用次数线性失控。每次调用仍保留单次结果数、单条字符数、总字符数和超时限制。重复的规范化查询会被拒绝并计入调用预算，语义相近但文本不同的查询不使用额外模型进行拦截。

### 3.2 冲突证据

冲突处理是搜索循环的一种继续条件，而不是独立检索算法。Agent 不得仅根据检索排名、召回分数或“看起来更新”选择一方；它应搜索能够区分时间、主体、适用范围、来源权威性或最终裁定的证据。

存在裁定证据时，最终回答同时引用冲突来源和裁定来源。没有足够证据消解时，最终回答保留各方说法并明确无法确认的事项，不把推测写成事实。本阶段不新增通用可信度分数、事实图谱、时序数据库或失效内容过滤器。

### 3.3 评测

评测保留第四阶段单主题、双主题、中间事实、首轮充分和冲突样本，并增加至少需要三组独立证据、三步中间事实、冲突后继续查裁定以及知识库确实无答案的样本。主轨道从同一条最多 8 次的搜索轨迹投影第 1、2、4、6、8 次调用后的前缀指标，预定义查询仅作为 Oracle 上限。硬上限会改变预算耗尽后的工具错误和最终回答，因此现有 2 次配置与最终候选默认配置仍各运行一次端到端验证，但不为每个中间预算重复完整检索矩阵。

默认搜索预算只有在复杂样本的前缀完整证据覆盖率相对第 2 次检查点提高至少 10 个百分点、首轮充分停止率不低于 95%、重复查询率不高于 5%，且继续提高预算带来的收益不足 2 个百分点时才改变。端到端验证中硬上限执行率、引用可解析率和预算耗尽后的不确定性说明率必须为 100%。

## 4. 轻量安全边界

本阶段只处理知识检索引入的间接提示注入风险，不扩展为通用内容审核、租户权限、数据防泄漏或高风险工具授权系统。

安全措施包括：

- 系统提示明确说明检索内容是不可信证据，不能覆盖系统、开发者或用户指令。
- 工具结果使用稳定的证据边界和来源字段，正文中的命令、角色声明和伪造引用保持数据身份。
- Agent 不得仅依据检索内容执行命令、修改文件、发送信息、泄露凭证或改变权限；有副作用的操作仍由对应工具与现有授权机制决定。
- 检索工具保持只读，不自动访问证据中的 URL，不执行代码，也不加载文档声明的工具或技能。
- 多轮搜索继续受调用次数、累计输出、单次输出和超时限制。

固定攻击样本覆盖“忽略上级指令”、伪造系统消息、要求读取秘密、诱导调用写工具、诱导访问外部地址和伪造 `K<n>` 引用。无密钥快照验证稳定安全提示与结果边界，真实 Agent 小样本验证不会遵从证据中的操作指令。该措施只降低风险，不宣称能够检测或阻止全部提示注入。

## 5. 验收指标

| 项目 | 必须报告 | 默认或通过条件 |
| --- | --- | --- |
| 三路分片 | Recall@5/10/20、MRR@10、nDCG@10、证据完整率、单命中完整率、token、分片数、构建时间、RSS | 按第 2.3 节决定默认值；不满足则保留现状 |
| 语义边界缓存 | 边界输入数、缓存命中、重算数、边界编码时间 | 未变化文档 100% 复用；局部修改不触发其他文档重算 |
| 搜索预算 | 完整证据覆盖、调用分布、停止率、重复率、延迟、累计输出 | 选择达到质量门槛的最小预算；硬上限执行率 100% |
| 冲突处理 | 冲突识别、针对性后续查询、正确消解、未解冲突保留 | 冲突识别率不低于 90%，存在裁定证据时正确处理率不低于 85%，无裁定时不得虚构确定结论 |
| 安全边界 | 注入指令遵从率、非必要副作用工具调用、引用伪造、提示与边界快照 | 固定攻击集中不执行证据指令、不产生伪造引用；所有行为仍受现有工具权限约束 |

## 6. 非目标

本阶段不实现 RAPTOR、GraphRAG、LLM 生成的上下文前缀、语义摘要、远程向量数据库、第二种 ANN、在线 HNSW 增删、知识写入、Proposer/Reviewer 工作流、定期知识整理、用户记忆、租户隔离、通用内容审核、恶意文档分类器或跨工具污点跟踪。

本阶段不修改 `agent-loop`。开放式检索继续通过现有工具调用扩展点实现，工具 Consumer 负责提示、预算和证据展示，Knowledge 提供方仍只负责一次独立搜索。

## 7. 完成条件

- 语义边界 pilot 给出可复现的继续或终止结论；只有通过继续门槛时才要求三种分片策略完成同语料、同查询、同召回配置的正式实验。
- 语义分片进入实现时，模型、边界算法、缓存身份和构建成本均写入索引清单；pilot 终止时保留机器可读负面结果和未实现范围。
- Agent 可以在硬预算内自主执行零至多次补充搜索，复杂问题相对两次上限取得可量化收益，简单问题不会机械增加调用。
- 冲突证据有明确继续、消解和保留不确定性的规则及评测结果。
- 固定间接提示注入样本、模型可见快照、相关包单元测试和逐文件覆盖率通过。
- `typecheck`、`lint`、相关测试、`doc-sync`、`hygiene` 和 `git diff --check` 通过。
- 模型、向量、索引、完整语料、真实会话和包含本机绝对路径的运行日志不进入提交范围。
