# DSH RAG 插件第二阶段实施任务

## 1. 执行原则

本文按依赖顺序拆解[第二阶段概要设计](rag-plugin-phase-two.md)和[详细设计](rag-plugin-phase-two-detailed-design.md)。每项任务只在完成条件全部满足后结束。真实模型和完整数据集实验不进入默认 CI，但决定默认阈值和质量结论时必须执行。完整基准索引一次只保留当前实验所需的一份，保存报告后删除再进入下一组，不要求本机同时容纳全部索引。

第二阶段不另建生产平台，不同时引入多种 ANN、分词器或 Dense 模型。实现顺序优先保证第一阶段回归、Exact 对照和可验证的索引格式，再增加 HNSW 与大数据集。

## 2. 前置收尾

### RAG2-000：完成第一阶段仓库基线

等级：E2；第二阶段代码开始前完成。

范围：

- 保持第一阶段本地实验结论不变。
- 补齐第一阶段新增源文件的仓库覆盖率门槛。
- 增加真实 Loader 组合的无密钥模型可见快照。
- 确认第一阶段分支通过变更范围要求的文档、构建、hygiene 和预推送检查。

完成条件：

- 第一阶段分支可以独立通过 CI，不依赖第二阶段代码修复。
- SciFact 六组结果和微型 BM25 示例仍可复现。
- 第二阶段只修改已经稳定的公共接口和索引格式。

## 3. 依赖与接口

### RAG2-010：验证 BGE-M3 与 USearch 可行性

等级：E0。

固定版本、实测结果和平台限制见[可行性验证报告](rag-plugin-phase-two-feasibility-report.md)。

依赖：`RAG2-000`。

范围：

- 固定 `onnx-community/bge-m3-ONNX` revision，并选择一个实际量化文件。
- 在支持的 Node 版本上验证中文、英文和跨语言 embedding，确认 1024 维、CLS pooling 和归一化。
- 验证 `usearch` 的 Node 安装、HNSW 构建、搜索、保存和重新加载。
- 在 macOS、Linux 和 Windows 检查预编译产物或本机构建要求。
- 记录模型缓存体积、单查询延迟、最小 HNSW 索引体积和许可证。

完成条件：

- 使用固定缓存可以完全离线完成中英文 embedding。
- 保存并重新加载的 HNSW 索引返回有效且稳定的 ordinal。
- `usearch` 不满足支持平台或持久化要求时停止实现，先修改详细设计，不并行引入第二个库。

### RAG2-020：扩展检索策略接口

等级：E0。

依赖：`RAG2-010`。

范围：

- 在 Service Definition 中增加 retrieval、denseIndex 和 rerank 枚举。
- 扩展搜索请求和解析后策略结果。
- 增加策略不允许错误码。
- 在 Provider 中实现独立的纯策略解析函数。
- 将第一阶段 `mode` 和布尔 `rerank` 配置替换为默认值与允许集合。

完成条件：

- 默认请求解析为 `hybrid + auto + rerank off`。
- BM25 携带显式 Dense 索引、请求禁用选项和开启被禁止的 Reranker 均明确失败。
- 允许集合只有一个值时能够表达开发者强制策略。
- 请求解析不读取硬件状态，也不修改 Provider 配置。

## 4. 索引第二版

### RAG2-030：建立流式 SQLite 索引

等级：E0 + E1。

依赖：`RAG2-020`。

范围：

- 将索引格式升级到版本 2，不维护版本 1 兼容读取器。
- 使用 `knowledge.sqlite` 保存分片和预分析后的 BM25 文本。
- 使用 SQLite FTS5 的固定 BM25 评分参数，不保留 `bm25K1` 和 `bm25B` 配置。
- 让通用 JSONL 语料按批次解析、分片和写入，不一次性保存全部文档对象。
- 保留固定 ordinal，并让 SQLite、Dense 行和 HNSW key 使用同一映射。
- 更新清单、文件哈希、验证命令和微型示例索引。

完成条件：

- 空目录构建成功，非空目录、未知 schema、数量不一致和损坏载荷明确失败。
- 运行时以只读方式打开 SQLite，不生成业务写入。
- 第一阶段微型语料重建后返回相同目标文档。
- 流式构建测试证明文档处理具有固定批次上限。

### RAG2-040：实现中英文混合 BM25

等级：E0。

依赖：`RAG2-030`。

范围：

- 实现 `mixed-zh-en-v1` 分析器和 ASCII 词项编码。
- 在 SQLite FTS5 中构建和查询预分析词项。
- 保留确定性排序和查询词项去重。
- 用第一阶段英文样例和新增中文、混排样例验证行为。

完成条件：

- 中文 unigram/bigram、英文、数字、下划线和 NFKC 均有手算测试。
- 原始查询不会直接拼入 MATCH 表达式。
- 空查询、纯标点和无命中查询返回明确结果。
- SciFact BM25 回归差异有报告，不能把 FTS5 分数与第一阶段分数直接比较。

## 5. 多语言 Dense 与索引选择

### RAG2-050：接入 BGE-M3

等级：E0 + E1。

依赖：`RAG2-030`、`RAG2-010`。

范围：

- 将模型维度、前缀、池化、归一化和输入长度收敛为模型配置。
- 使用固定 revision 的 BGE-M3 ONNX 生成中英文统一向量。
- 以批次追加方式写入 `dense.f32le`。
- 保留第一阶段模型配置作为显式英文回归配置，不自动按语言切换。

完成条件：

- 假模型测试覆盖维度、截断、池化、归一化和批次写入。
- 真实缓存烟测分别完成中文、英文和中文查询检索英文文本。
- 运行时缺少缓存时不联网，并报告缺失模型。
- 百万级构建路径不把全部向量复制进 JavaScript 对象数组。

### RAG2-060：实现 Exact 与自动阈值

等级：E0。

依赖：`RAG2-050`。

范围：

- 保留完整 float32 Exact 扫描作为正确性基线。
- 实现 `scanElements = vectorCount × vectorDimension`。
- 增加构建参数 `denseIndex` 和 `exactScanMaxElements`。
- 支持 `auto|exact|hnsw|both`，其中 `auto` 只保留推荐载荷，`both` 只用于明确对照。
- 把请求值、推荐值、最终产物模式、阈值、扫描量和查询默认值写入清单。
- Exact 向量改为首次请求时加载。
- 在完成分片后输出构建计划；交互式调用确认选择，非交互调用确定性采用推荐值。

完成条件：

- 默认阈值 `50,000,000` 的边界值和前后一个值均有测试。
- BGE-M3 的 50,000 向量默认解析为 HNSW，第一阶段 6,673 个 384 维向量解析为 Exact。
- 加载器重新计算并验证扫描量，不按当前机器重新选择。
- 显式 Exact 不会静默切换 HNSW。
- HNSW-only 不生成 `dense.f32le`，Both 同时生成并加载两种载荷。

### RAG2-070：实现 HNSW

等级：E0 + E1。

依赖：`RAG2-050`、`RAG2-060`。

范围：

- 增加 USearch 适配器，隔离原生库 API 和距离语义。
- 使用 ordinal 建图并保存 `dense.usearch`。
- 实现延迟加载、并发加载复用、失败重试和释放。
- 支持 `connectivity`、`expansionAdd` 和 `expansionSearch` 的开发者配置。
- 将构建参数、运行参数和库版本写入清单或报告。

完成条件：

- 微型索引保存、重新加载和查询结果与内存实例一致。
- HNSW 返回的 key、距离、数量异常均被验证并明确失败。
- 无 HNSW 载荷时显式 HNSW 请求失败，不回退 Exact。
- HNSW 与 Exact 使用同一向量和候选数进行 Recall@k 对照。
- 原生调用前后检查取消信号，且不声称可以中断正在执行的调用。

## 6. 工具与组合执行

### RAG2-080：扩展 `knowledge_search`

等级：E0 + E1。

依赖：`RAG2-020`、`RAG2-070`。

范围：

- 在工具 schema 中增加三个可选高层策略字段。
- 更新提示词中的默认性能模式和明确质量模式规则。
- 将请求字段原样交给 Provider 解析。
- 在成功结果中显示解析后的高层策略。
- 保持证据字符限制、不可信内容提示和 `K<n>` 引用。

完成条件：

- 普通知识查询只传 query，并执行默认性能模式。
- 关键词、精确语义、混合不重排和质量优先分别有模型可见快照。
- 工具 schema 不包含 HNSW、BM25、RRF、候选数、阈值或模型底层参数。
- Provider 拒绝策略时，工具不会自行选择替代组合。

### RAG2-090：完成全部检索组合

等级：E0。

依赖：`RAG2-080`。

范围：

- 让 BM25、Dense 和 Hybrid 使用统一策略执行器。
- Dense 和 Hybrid 分别支持 Exact 与 HNSW。
- Reranker 可独立应用于三种召回方式。
- 保持 RRF 去重、错误传播、候选数和稳定排序规则。

完成条件：

- 所有有效组合有确定性微型测试。
- BM25 不加载 Dense 索引，未重排请求不加载 Reranker。
- Hybrid 任一路失败和 Reranker 失败均不返回部分结果。
- 默认性能模式与质量模式的实际执行策略可从结果确认。

## 7. 数据与评测

### RAG2-100：增加 SciFact 与 MLDR 评测

等级：E1。

依赖：`RAG2-090`。

范围：

- 将 SciFact 重新构建为索引版本 2，并运行英文回归。
- 增加 MLDR 中文和英文准备适配器。
- 验证长文档分片、多语言 Dense 和同构中英文指标。
- 在多个规模切片上记录 Exact 与 HNSW 搜索阶段延迟。

完成条件：

- 数据来源、revision、许可证和摘要进入机器可读准备记录。
- SciFact 结果没有未解释的明显回退。
- MLDR zh/en 均生成 Recall、MRR、nDCG、Success 和延迟报告。
- 报告区分向量搜索阶段与完整检索延迟。

### RAG2-110：增加 T2Ranking 规模评测

等级：E1。

依赖：`RAG2-100`。

范围：

- 准备 T2Ranking passage、开发查询和 qrels，并生成可复现的固定切片。
- 在固定切片上构建中文 BM25、BGE-M3 向量和 HNSW 索引。
- 观察默认阈值的性能余量。
- 比较 Exact、HNSW、Hybrid 和可选 Reranker；全量建库只作为资源允许时的压力测试。

完成条件：

- 固定切片构建不会一次性把全部语料或向量保存在 JavaScript 对象中。
- 报告包含各载荷体积、构建阶段耗时、峰值 RSS、p50/p95 和质量指标。
- HNSW 加速比、相对 Exact Recall@10 和 Recall@100 有明确结果。
- 报告说明 `exactScanMaxElements` 是可覆盖的保守甜点值，不声明为跨机器临界点。

### RAG2-120：增加 MLQA Retrieval 跨语言评测

等级：E1。

依赖：`RAG2-100`。

范围：

- 准备 MLQA Retrieval `eng-zho` 的中文查询、英文语料和 qrels。
- 评测中文查询检索英文证据的 Exact、HNSW 和 Reranker 路径。
- 将跨语言结果与中英文混合索引共存测试分开报告。

完成条件：

- 查询、答案和语料映射规则可复现且有完整性检查。
- 报告至少包含 Recall@20、Recall@100、HNSW 近似损失和延迟。
- 结论不把同语言 MLDR 或混合语料共存误写为跨语言质量证明。

## 8. 收尾与提交

### RAG2-130：完成第二阶段实验报告

等级：E1。

依赖：`RAG2-110`、`RAG2-120`。

范围：

- 汇总 SciFact、MLDR、T2Ranking 和 MLQA Retrieval 结果。
- 分别给出性能模式和质量模式结论。
- 明确 BGE-M3、HNSW 和 Reranker 的质量、延迟、内存与磁盘代价。
- 记录最终自动阈值和不适用范围。

完成条件：

- 每个结论能够追溯到机器可读报告。
- 不把单一数据集或单机结果声明为普遍最优。
- 不把 HNSW 描述为节省内存，也不把 Reranker 的提升描述为无成本。

### RAG2-140：完成仓库集成质量

等级：E2。

依赖：`RAG2-130`。

范围：

- 更新 Agent Note、三包 README、JSDoc、目录和生成目录。
- 增加真实 Loader 组合测试、模型可见快照和自跳过真实模型 E2E。
- 对新增原生依赖执行发布、运行时闭包和支持平台检查。
- 使用 `dsh-pre-push-checks` 选择并运行变更范围所需检查。

完成条件：

- 新增和修改源文件满足仓库逐文件覆盖率门槛。
- 文档、索引格式、公共接口、工具 schema 和实际行为一致。
- 微型 CI 不下载模型或数据；真实实验只在显式环境中运行。
- 构建、lint、hygiene、文档检查、相关快照和预推送检查全部通过。

## 9. 不拆入本阶段的任务

以下内容留到后续阶段，不作为第二阶段“顺手完成”的事项：

- IVF、DiskANN、向量量化和第二个 HNSW 实现。
- 在线增量索引、文件监听和自动同步。
- 远程向量数据库、分布式检索和多租户权限。
- 查询改写、学习型路由和自动参数搜索。
- 推理调度队列、后台构建服务和生产监控。
