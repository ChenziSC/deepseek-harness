# DSH RAG 插件第三阶段概要设计规格

本文确认第三阶段的发展方向、能力范围、默认行为和验收标准。第二阶段的索引、检索组合、多语言模型和实验结论见[第二阶段概要设计](../phase-two/rag-plugin-phase-two.md)与[第二阶段验收报告](../phase-two/rag-plugin-phase-two-acceptance-report.md)。接口和算法约定见[详细设计](rag-plugin-phase-three-detailed-design.md)，实施顺序见[实施任务](rag-plugin-phase-three-implementation-tasks.md)，实际结果见[第三阶段验收报告](rag-plugin-phase-three-acceptance-report.md)。

## 1. 定位

第三阶段继续把插件定位为本地优先、可评测的轻量 RAG 检索组件。重点从增加检索算法转为改进证据组织和自动决策，使普通开发者在不理解底层参数时得到较合理的默认结果，同时保留 BM25、Dense、Hybrid、Exact、HNSW 和 Reranker 的高层显式覆盖。

本阶段只实现四项能力：结构感知分片与相邻块扩展、查询策略自动路由、自适应 Reranker、单个 agent turn 内最多两轮的 Agentic 检索。

## 2. 目标

- Markdown 文档优先沿标题章节、代码围栏、段落和句子边界分片，并让标题路径参与 BM25 与 Dense 索引。
- 每个排名命中可以附带同文档前后各一块上下文，邻居不参与召回评分、不占用命中数量，也不改变离线召回指标。
- 未显式指定召回方式时，根据查询词项特征、查询文字脚本和语料脚本画像选择 BM25、Dense 或 Hybrid。
- `rerank: auto` 根据召回候选的歧义决定是否调用神经重排；性能模式仍默认关闭，质量优先请求使用自适应重排。
- agent 对简单问题通常检索一次；首轮证据不足时可以改写查询再检索一次；同一 turn 的第三次检索由工具执行端拒绝。
- 分别评测四项能力及其组合效果，避免只报告组合结果而无法判断收益来源。

## 3. 非目标

第三阶段不包含 GraphRAG、RAPTOR、多向量表示、查询分类模型、LLM 路由器、远程向量数据库、索引在线增量更新、跨编码器并发调度、超过两轮的自主检索循环或新的 ANN 实现。

提示词仍只能控制 `retrieval`、`denseIndex` 和 `rerank` 等高层选项，不能设置分片大小、邻居数量、路由正则、分差阈值、候选数量、RRF 或 HNSW 参数。

## 4. 默认行为

| 项目 | 默认行为 |
| --- | --- |
| 分片 | Markdown 结构优先，超长结构按 tokenizer 上限确定性切分 |
| 标题路径 | 参与 BM25 和 Dense 索引，原始命中文本保持独立 |
| 相邻扩展 | 每个命中最多前后各一块，同文档限定，精确重叠文本去重 |
| 召回路由 | `auto`；精确标识符优先 BM25，明显跨语言优先 Dense，其他查询优先 Hybrid |
| Reranker | 未指定时沿用性能默认关闭；质量优先映射为 `auto`；明确要求重排映射为 `on` |
| Agentic 检索 | 单 turn 最多两次；第二次仅用于补充首轮不足的证据 |

自动路由和自适应重排都必须返回实际执行策略。开发者限制的允许集合高于自动推荐；推荐值不可用时按确定性的允许顺序选择，不在执行阶段静默降级。

## 5. 能力间依赖

四项能力不是完全独立：

1. 结构感知分片需要索引记录标题路径；跨语言自动路由需要索引记录语料脚本画像。两者共同依赖一次索引格式和 SQLite schema 升级。
2. 查询自动路由与自适应 Reranker共同依赖“请求偏好 → 召回执行计划 → 最终执行结果”的两阶段策略解析。自动路由先确定实际召回方式，自适应重排再根据该方式产生的候选分数决定是否执行。
3. 相邻块扩展必须位于召回和可选重排之后，否则邻居会污染排序与评测指标。
4. 两轮 Agentic 检索在工具 Consumer 中独立执行，不依赖修改 agent loop；但它的提示词、快照和组合验收应在前三项输出稳定后完成。

因此实施顺序为：先确定规格和公共语义，再升级索引基础，随后实现结构分片与自动路由，再实现自适应重排，最后收敛两轮工具行为和组合评测。

## 6. 结构感知分片与相邻扩展

第一版只识别 ATX Markdown 标题和反引号或波浪线 fenced code block。标题层级形成 `父标题 > 子标题` 路径。标题路径与文档标题共同加入索引文本，但工具结果继续区分标题、章节路径和原始命中文本。

分片边界优先级为章节边界、完整代码围栏、段落、句子、token 硬边界。超过 `maxTokens` 的章节或代码块允许按 token 硬切，不能为了保持结构完整而突破模型输入上限。

相邻扩展默认最多前后各一块，只允许同一文档。若邻居本身已是排名命中则不重复附加；overlap 产生的完全相同前后缀需要去重。工具输出先保留命中块，再在剩余字符预算内加入前块和后块。

## 7. 查询策略自动路由

`retrieval` 增加请求态 `auto`，结果态只允许实际执行的 `bm25`、`dense` 或 `hybrid`。未指定 `retrieval` 时，本地提供方默认使用 `auto`。

第一版采用无模型、确定性的规则：URL、文件路径、错误码、代码标识符、长数字和长十六进制值优先 BM25；查询与语料的主要文字脚本明显不一致时优先 Dense；普通自然语言和中英文混合查询优先 Hybrid。

语料脚本画像在构建索引时按 Latin 与 CJK 字符比例生成 `latin`、`cjk`、`mixed` 或 `neutral`，写入清单。该画像只用于粗粒度路由，不宣称完成语言识别。

## 8. 自适应 Reranker

`rerank: off` 永不重排，`rerank: on` 强制重排，`rerank: auto` 根据召回候选决定。省略 `rerank` 时使用部署默认值，默认仍为 `off`，因此普通查询不会新增模型延迟。

自适应规则只使用已产生的候选分数：候选不足两条时跳过；前两名归一化分差达到阈值时认为首名较明确并跳过；分差低于阈值时重排前 `rerankerCandidateCount` 条。默认分差阈值为 `0.15`，属于保守甜点值，由开发者配置，不向模型暴露。

结果中的 `strategy.rerank` 表示本次是否真正执行重排，而不是请求偏好。

## 9. 最多两轮的 Agentic 检索

“两轮”指同一个 agent turn 内最多两次 `knowledge_search` 成功派发，不是整个 session 只能检索两次。新 turn 自动重新计数。

工具提示要求首轮使用覆盖问题核心的查询；只有证据不足或复杂问题存在互补证据时才进行第二轮，第二轮必须改写查询或补充缺失角度。两次之后停止检索，基于已有证据作答并说明不确定性。

次数限制由 `knowledge_search` 执行端按当前 agent 和持久 turn 边界实施，不能只依赖提示词。参数校验失败不消耗次数；已经进入提供方检索的失败调用消耗次数，避免模型通过重试绕开成本限制。没有调用 agent 的直接程序调用不共享 turn 预算。

## 10. 评测与验收

结构分片使用包含标题层级、代码围栏、跨块答案和 overlap 的确定性 Markdown fixture，并在 SciFact 与 MLDR 样本上比较原分片和结构分片。报告标准检索指标与证据完整率，邻居文本不计入召回命中。

自动路由使用精确标识符 fixture、SciFact 或 T2Ranking 普通查询、MLQA Retrieval 跨语言查询，报告路由命中率、实际策略和相对固定策略的质量与延迟。

自适应重排在固定查询样本上报告触发率、Recall、MRR、nDCG、p50 和 p95，并与 `off`、`on` 对照。默认阈值只有在相同候选集合上完成消融后才视为验收。

两轮 Agentic 检索使用一个需要两份互补证据的小型确定性 fixture 和真实 Loader 快照，验证一次足够、第二次补充、第三次拒绝、新 turn 清零及证据不足时停止。

第三阶段完成时必须满足：四项能力均有定向单元测试；三包相关 coverage 保持每文件 100%；真实组合快照覆盖模型可见提示与结果；现有数据集评测生成机器可读结果；`typecheck`、`lint`、`doc-sync` 和 `git diff --check` 通过。

## 11. 风险

- Markdown 结构规则只覆盖常见语法，不等同于完整 Markdown AST；复杂嵌套格式可能退化为段落或 token 分片。
- 标题路径增加索引文本后可能改善主题召回，也可能放大重复标题，需要通过消融判断。
- 不同检索方式的分数分布不同，统一分差阈值只能作为轻量默认值，不能保证所有数据集最优。
- 自动路由规则追求可解释和低成本，可能把包含标识符的自然语言查询过度路由到 BM25；显式策略覆盖和评测报告用于暴露该限制。
- 两轮限制控制成本但会放弃部分多跳问题的上限，本阶段不为少数复杂问题扩展无限循环。
