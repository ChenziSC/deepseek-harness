# DSH RAG 插件第三阶段验收报告

## 1. 验收结论

第三阶段的四项主体能力已完成并通过代码级验收：Markdown 结构感知分片与相邻块扩展、查询策略自动路由、自适应 Reranker、单个 agent turn 内最多两次 `knowledge_search`。索引格式升级为 3，SQLite schema 升级为 2；模型只能选择召回方式、Dense 索引方式和重排偏好，不能直接设置底层数值参数。

代码级验收不等同于四项能力均已证明质量或性能收益。结构分片、自动路由和两轮检索已有确定性行为证据，但缺少对应真实数据集上的独立消融。后续专项复核证明 Reranker 在 T2Ranking 和 SciFact 样本上有质量正收益，但默认 `0.15` 阈值对 Hybrid 的触发率为 100%，没有体现自适应节省；第三阶段可作为功能实现验收，不能视为四项能力均优于第二阶段默认行为。

MLDR English 固定切片的 15 组评测全部成功，BM25、Dense、Hybrid、Exact、HNSW 与重排 `off/auto/on` 均可组合运行。该切片由查询对应的正负 passage 构成，所有组合的标准质量指标均为 100%，因此只能证明完整路径没有回退，不能证明某种组合具有普遍质量优势。

自适应 Reranker 的执行语义通过验收，但默认分差阈值 `0.15` 在 MLDR、T2Ranking 和 SciFact 的 Hybrid 样本上都触发 100%，等同于强制开启。T2Ranking 的阈值扫描显示 `0.02` 可在触发 45% 查询时保留部分质量收益和低中位延迟，但 SciFact 同一阈值触发 60%，尚不能作为跨数据集默认值。性能模式继续默认关闭 Reranker；质量模式需要明确接受秒级尾延迟或按部署查询分布校准阈值。

T2Ranking 的 10k、25k、50k 和 100k Exact/HNSW 校准完成了 52 次机器可读报告。四档都满足延迟门槛，但 25k 和 50k 未满足质量门槛，10k 与 100k 通过，结果不具备随规模单调变化的稳定切换边界。`exactScanMaxElements` 保持 `50,000,000`，该值是未获得可靠新边界时保留的现有默认值，不是本次实验验证出的最优阈值。

### 6.5 阈值结论

结果没有形成随规模单调变化的相邻“Exact 保留/HNSW 通过”边界，且最小的 10k 档已经通过。按照[阈值校准实验规格](rag-plugin-exact-hnsw-threshold-calibration.md#7-判定门槛)，本实验不修改默认值，`exactScanMaxElements` 保持 `50,000,000`。这意味着 50,008 分片档按默认规则选择 HNSW，尽管该档在本次查询集上未通过质量门槛；接入者不能将默认阈值视为跨语料质量保证。

不补充 60k 档：补点规则用于稳定的相邻失败/通过区间，而当前 10k 通过、25k 和 50k 失败、100k 通过，主要问题是近似质量非单调，不是单一规模边界精度不足。若继续校准，应先增加查询数或重复 HNSW 构建以判断质量波动来源，再设计新的阈值实验。

## 7. 性能问题与修复

相邻块 overlap 去重最初对每个候选反复执行字符数组转换、切片和拼接，使关闭重排的 BM25、Dense Exact、Hybrid HNSW p50 分别达到 231.78 ms、193.11 ms 和 236.50 ms。当前实现改用原生字符串前后缀比较，同一索引和查询上的 p50 分别降至 39.95 ms、29.93 ms 和 54.15 ms，质量指标不变。

修复后的关闭重排延迟与第二阶段同一 MLDR 切片的结果接近。相邻扩展仍会增加最多 40 次主键查询和字符串比较，但不再构成百毫秒级额外开销。

## 8. 已知限制

1. MLDR 固定切片的候选集合较容易，所有策略都已达到 100%，不能用于比较结构分片、自动路由或 Reranker 的质量增益；Reranker 正收益来自 T2Ranking 100 查询和 SciFact 30 查询专项复核，规模仍有限。
2. 结构分片只在确定性 Markdown fixture 中充分覆盖；尚未使用大型真实 Markdown 知识库做质量消融。
3. 自动路由使用可解释的规则，不是学习型分类器。跨脚本规则有 MLQA 第二阶段结果和确定性测试支持，但第三阶段没有重新运行 MLQA 全量索引。
4. 自适应 Reranker 的 `0.15` 阈值在三个 Hybrid 样本上都退化为 100% 触发；较低阈值的触发率和质量保留程度随数据集变化，插件不做在线自动调参。
5. 两轮限制保证成本上限，但模型是否发起第二轮取决于提示理解；当前没有大规模 Agentic 多跳问答基准。
6. Exact/HNSW 校准只使用 100 个 T2Ranking 查询；25k、50k 和 100k 的质量结果不单调，无法建立稳定的自动切换边界。
7. 构建报告只有每档总耗时，没有单独的 HNSW 构建耗时；100k 墙钟时间还包含主机休眠。

这些限制不阻塞第三阶段作为学习、实验和轻量本地接入组件的验收，也不构成生产级检索质量承诺。
