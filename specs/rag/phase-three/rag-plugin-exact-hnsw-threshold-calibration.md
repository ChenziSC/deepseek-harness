# Exact/HNSW 自动切换阈值校准实验规格

## 1. 实验目的

本实验为本地轻量 RAG 插件校准 Exact 与 HNSW 的默认切换阈值。实验回答“从多大索引开始，HNSW 的延迟收益足以抵消近似检索误差和额外构建成本”，不追求完整 T2Ranking 压力测试，也不为单台机器拟合复杂的自动调参规则。

默认 `exactScanMaxElements = 50,000,000` 在本实验完成前保持不变。实验结果只有同时满足延迟和质量门槛，并形成明确的失败规模与通过规模边界时，才可以支持后续修改默认值。

## 2. 范围

- 数据集使用 T2Ranking 开发集，但不构建约 230 万篇 passage 的全量索引。
- 初筛规模为约 10k、25k、50k、100k 个分片；规模指最终 `vectorCount`，不是原始 passage 数量。
- Dense 模型、分片规则、HNSW 参数、候选数量和返回数量保持一致，只改变向量规模与 Dense 索引方式。
- Reranker 固定关闭，避免神经重排延迟掩盖 Exact/HNSW 差异。
- Dense 检索作为索引差异的主要性能对照；Hybrid 使用同一查询集做默认使用路径的回归，不单独改变阈值。

本实验不引入新的 ANN 算法、远程向量数据库、并行查询压测或全量 T2Ranking 索引。

## 3. 稳定嵌套切片

查询集固定为 T2Ranking 官方开发查询源顺序中前 100 条至少包含一个 retrieval qrels 正例的查询，所有规模共享完全相同的查询、qrels 和评测参数。切片清单记录数据源摘要、查询 ID、passage ID、选择顺序和分片数量，以便重复实验。

每档切片按以下顺序组成：

1. 收集固定查询集中 qrels 相关性大于零的全部 passage，按固定查询顺序和 passage ID 去重排序，并在所有规模中保留。
2. 从官方 `dev.bm25` 结果中排除上述正例，将其余 passage 作为困难负例。
3. 困难负例按 BM25 名次、固定查询顺序、passage ID 排序；同一 passage 只保留第一次出现。
4. 正例排在稳定语料序列前部，困难负例按上述顺序追加。各档只在文档边界截断，使 10k 是 25k 的前缀，25k 是 50k 的前缀，50k 是 100k 的前缀。
5. 档位允许因最后一篇文档产生少量超额分片，但必须记录实际 `vectorCount` 和 `scanElements = vectorCount × vectorDimension`。

如果官方困难负例不足以形成最大档，实验停止并报告缺口，不混入随机负例改变语料分布。

## 4. 一次编码与索引派生

最大档完成一次分片和 Dense 编码，生成按稳定语料顺序排列的 SQLite 数据与 float32 向量。其余档位从最大档按文档和向量前缀派生，不重复调用嵌入模型。

每个规模生成一组独立、可校验的实验索引：

- Exact 使用对应向量前缀生成 `dense.f32le`。
- HNSW 使用同一向量前缀独立构建 `dense.usearch`。
- SQLite 只保留该档文档、分片和 FTS 记录。
- manifest 写入该档实际数量、产物模式、文件摘要和索引指纹。

派生后先用小型 fixture 验证 ordinal、向量顺序、SQLite 记录、manifest 数量和文件摘要，再开始真实模型构建。实验索引按规模轮换保留，不要求四档长期同时占用磁盘。

## 5. 查询执行规则

查询性能评测必须严格串行，构建任务、其他评测进程和 Reranker 不得同时运行。每个索引加载后先完成一次不计时的完整查询集预热，再进入测量。

测量使用 ABBA 顺序降低温度、缓存和运行时漂移影响：

```text
A: Exact 完整查询集
B: HNSW 完整查询集
B: HNSW 完整查询集
A: Exact 完整查询集
```

每个规模至少运行三个 ABBA 块。查询顺序在全部运行中固定，单次查询完成后才发出下一次查询；报告各轮原始结果和合并统计，不能只保留最好的一轮。

## 6. 记录指标

每个规模和检索方式至少记录：

| 类别 | 指标 |
| --- | --- |
| 查询性能 | p50、p95；Dense 为主要对照，Hybrid 为默认路径回归 |
| qrels 质量 | Recall@10、Recall@100、MRR@10、nDCG@10 |
| 近似误差 | HNSW 相对 Exact 的 Top-10、Top-100 结果重合度 |
| 构建成本 | 最大档分片与编码时间、各档派生时间、各档 HNSW 构建时间 |
| 资源 | 构建峰值 RSS、查询峰值 RSS、SQLite/Exact/HNSW 各产物与合计磁盘占用 |

Exact 是同规模的质量参考。Top-K 重合度用于定位近似搜索差异，不能替代 qrels 指标。

## 7. 判定门槛

一个规模只有同时满足以下条件，才视为 HNSW 适合作为默认索引：

- Dense HNSW 的 p95 不高于 Dense Exact 的 70%，即至少快 30%。
- Hybrid HNSW 的 p95 不高于 Hybrid Exact，避免默认检索路径出现性能倒退。
- Recall@10、Recall@100、MRR@10 和 nDCG@10 相对同规模 Exact 的绝对下降均不超过 1 个百分点。
- Top-10 重合度不低于 95%，Top-100 重合度不低于 97%；未达到时即使 qrels 通过，也标记为近似结果不稳定并复核查询明细。
- 三个 ABBA 块中至少两个分别满足延迟门槛，避免一次偶然快结果决定阈值。

默认切换边界需要一组相邻的“Exact 保留”和“HNSW 通过”规模。配置语义继续是 `scanElements <= exactScanMaxElements` 使用 Exact，超过阈值使用 HNSW；候选阈值取补充测试后最大的“HNSW 未通过”规模对应的扫描元素，并保留实际维度换算记录。

如果 10k 已通过或 100k 仍未通过，当前范围不能形成双侧边界，实验只报告结果，不修改默认值。

## 8. 补点规则

初筛只运行 10k、25k、50k、100k。只有相邻档位出现一档未通过、后一档通过的模糊区间时才补点：

- 25k 至 50k 区间优先补 40k。
- 50k 至 100k 区间优先补 60k；如果 60k 仍不能缩小边界，再补剩余区间的中点。
- 其他模糊区间只补当前失败规模与通过规模的中点。

补点沿用最大档的向量和稳定前缀，不重新编码。每次补点后重新判断边界；不为了寻找单机最优数字进行连续细粒度扫描。

## 9. 产出与时间预算

实验预计占用 7 至 12 小时，主要成本是最大档 BGE-M3 编码和各档 HNSW 构建。执行前必须确认剩余磁盘能够容纳最大档 SQLite、向量和 HNSW 临时产物；空间不足时先轮换删除可再生成的旧实验索引。

最终产出包括机器可读报告和中文结论，至少列出每档实际规模、ABBA 各轮指标、质量差异、构建资源、磁盘占用、是否通过门槛及建议阈值。没有完成全部门槛验证时，结论必须保留现有 `50,000,000` 默认值，并明确未校准部分。
