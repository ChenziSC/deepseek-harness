# DSH RAG 插件第一阶段实施任务

## 1. 使用方式

本清单把[概要设计](rag-plugin-phase-one.md)和[详细设计](rag-plugin-phase-one-detailed-design.md)拆成按学习顺序可运行、可验证的任务。每项标明工程等级：E0 保证实验正确，E1 提升本地实验体验，E2 是正式提交 DSH 仓库前的集成要求。E3 不进入第一阶段任务。

第一阶段实现目标为 E1。完成 RAG-040 后应已有可调用的 BM25 RAG 插件；后续任务每次只增加一种核心检索能力，避免直到最后才能运行完整链路。

## 2. 依赖关系

```text
RAG-001
  └─ RAG-010
      └─ RAG-020
          └─ RAG-030
              └─ RAG-040    BM25 完整链路
                  └─ RAG-050    Dense
                      └─ RAG-060    Hybrid
                          └─ RAG-070    Reranker
                              └─ RAG-080    SciFact 六组评测
                                  └─ RAG-090    E1 收尾
                                      └─ RAG-100    E2 仓库集成
```

## 3. BM25 完整链路

### RAG-001：建立三个实验包

等级：E0。

范围：

- 创建 `knowledge`、`knowledge-local`、`tool-knowledge` 三个实验包。
- `knowledge` 默认导出抽象 `Knowledge` Service。
- `knowledge-local` 默认导出 `LocalKnowledge extends Knowledge`，不使用函数插件包装 Service。
- `tool-knowledge` 使用 `name`、`inject`、`Config` 和 `apply` 注册模型工具。
- 为 `knowledge-local` 增加 `dsh-knowledge` 命令入口。

完成条件：

- 三个包的依赖方向为 Consumer → Service Definition、Provider → Service Definition。
- Loader 配置只挂载 `knowledge-local` 和 `tool-knowledge`，不会单独实例化抽象 Service。
- `dsh-knowledge --help` 能从构建入口启动。

### RAG-010：实现语料解析和分片

等级：E0。

依赖：`RAG-001`。

范围：

- 添加 `@huggingface/transformers`，使用固定 revision 的 BGE tokenizer。
- 实现通用 JSONL 语料解析。
- 实现 SciFact corpus、queries 和 qrels 适配器。
- 实现段落、句子、token 回退分片和 token 重叠。
- 生成稳定的分片 ordinal 和分片标识。

完成条件：

- 重复 ID、错误类型、空正文和错误 qrels 报告文件与行号。
- 相同文档集合以不同行顺序输入时产生相同分片记录。
- 评测查询由 qrels 引用集合选择；qrels 中重复的查询与文档组合、未知引用或没有正例的查询会失败。
- 微型 SciFact 夹具能解析为预期文档、查询和相关性映射。

### RAG-020：实现简单索引格式

等级：E1。

依赖：`RAG-010`。

范围：

- 实现 `manifest.json`、`chunks.jsonl`、`bm25.json` 和可选的 `dense.f32le`。
- 固定载荷文件名，不允许清单提供任意路径。
- 记录语料哈希、分片配置、模型 revision、向量维度、构建工具版本与耗时、载荷大小和哈希。
- 先写载荷，成功后最后写 `manifest.json`。

完成条件：

- 缺少清单的目录不会被当作有效索引。
- 文件缺失、哈希错误、维度不符、NaN 和配置不匹配明确失败。
- 非空目标目录不被覆盖。
- 不实现目录级原子替换、迁移和崩溃恢复。

### RAG-030：实现 BM25

等级：E0。

依赖：`RAG-020`。

范围：

- 实现 `english-v1` 分析器。
- 构建倒排表、文档长度和平均长度。
- 实现概要设计规定的 Okapi BM25 公式和确定性排序。
- 实现供本地诊断使用的词项贡献。

完成条件：

- 手算夹具的 token、IDF、词项贡献和最终排序与实现一致。
- 无命中查询返回空结果。
- 大小写、Unicode NFKC、数字、重复查询词和分数平局有测试。
- BM25 模式不要求模型权重，也不触发网络访问。

### RAG-040：接通 `knowledge_search` 和微型示例

等级：E0 + E1。

依赖：`RAG-030`。

范围：

- 实现 `Knowledge.search` 和 BM25 模式的 `LocalKnowledge`。
- 注册只接受 `query` 的 `knowledge_search`。
- 生成 `K1`、`K2` 等证据编号并限制完整模型输出长度。
- 注册证据不可信、回答引用和证据不足提示词。
- 创建使用微型 BM25 索引的可运行示例。

完成条件：

- 示例能够从问题调用工具、返回证据并生成带 `K1` 引用的回答。
- 模型不能选择检索模式、模型、候选数或索引路径。
- 工具结果不包含算法诊断、模型路径或内部缓存信息。
- 这是第一条完整可运行链路，后续算法不得阻塞它。

## 4. 增加检索算法

### RAG-050：实现 Dense 精确检索

等级：E0 + E1。

依赖：`RAG-040`。

范围：

- 使用固定 revision 的 `bge-small-en-v1.5` q8 ONNX 模型。
- 实现查询前缀、CLS pooling、384 维 L2 归一化和 float32 点积。
- 查询与文档均启用 512 token 截断；查询前缀和文档标题优先保留。
- 将文档向量写入 `dense.f32le`，运行时执行精确扫描。
- 加载期间共享 Promise，成功后复用模型实例，失败后允许下一次调用重试；不实现独立状态机或请求队列。

完成条件：

- 假模型测试验证前缀、截断、池化、归一化和维度。
- 精确扫描结果与完整排序参考实现一致。
- 已准备缓存可完成一个文档批次和一个查询的本地烟测。
- 运行时使用 `local_files_only`，不会隐式下载模型。

### RAG-060：实现 Hybrid RRF

等级：E0。

依赖：`RAG-050`。

范围：

- BM25 和 Dense 分别取得前 50 个候选。
- 按分片标识去重并使用 `rrfK = 60` 融合。
- 按 RRF 分数、更优单路名次和分片标识确定最终顺序。

完成条件：

- 手算夹具覆盖双路命中、单路命中、重复分片和完全平局。
- 任一路失败时 Hybrid 失败，不返回部分结果。
- 相同输入多次运行产生相同顺序。

### RAG-070：实现跨编码器重排序

等级：E0 + E1。

依赖：`RAG-060`。

范围：

- 使用固定 revision 的 `bge-reranker-v2-m3` q8 ONNX 模型。
- 对召回阶段前 50 个候选按查询与文档文本对打分。
- 实现 512 token 截断、每批 8 条、原始 logit 排序和稳定平局。
- 让 BM25、Dense、Hybrid 都能独立开启重排序。
- 加载期间共享 Promise，成功后复用模型实例，失败后允许下一次调用重试；不实现独立状态机或请求队列。

完成条件：

- 六条检索路径均有确定性测试。
- 输出数量错误、NaN 和批次失败不会产生部分结果。
- 检索在 ONNX 调用前后和批次之间检查取消信号。
- 已准备缓存可完成一个重排序批次的本地烟测。

## 5. 统一评测

### RAG-080：实现 SciFact 六组评测

等级：E0 + E1。

依赖：`RAG-070`。

范围：

- 实现 `prepare scifact`、`index` 和 `evaluate` 命令。
- 下载 SciFact 时验证官方 MD5；模型交给 Transformers.js 固定 revision 缓存。
- 将分片结果折叠为文档结果。
- 固定使用 50 个召回候选和前 20 个文档结果。
- 实现 Recall、MRR、nDCG 和 Success，运行六组实验。
- 输出 `report.json` 和由它投影得到的 `report.md`。

完成条件：

- `rel > 0` 才视为相关文档，查询按查询标识排序。
- 指标通过包含多个相关文档的手算夹具，Recall 与 Success 不混用；p50 和 p95 使用 nearest-rank。
- 任一查询失败会使对应组合失败，不计算部分平均值；其他组合继续运行。
- 六组实验使用相同语料、分片、查询、候选数和结果深度。
- 报告包含质量指标、预热后的 p50/p95 延迟、索引大小、模型 revision 和完整实验配置。

### RAG-090：完成 E1 实验收尾

等级：E1。

依赖：`RAG-080`。

范围：

- 检查索引、模型和运行配置匹配。
- 验证并发首次调用只触发一次模型加载、加载失败后可重试、基本取消和释放后拒绝新请求。
- 在本机运行完整 SciFact 六组实验。
- 更新三包 README，说明模型大小、SciFact 仅英文和实验限制。

完成条件：

- 六组实验有可重复执行的命令和本地报告。
- BM25 示例不依赖模型缓存，Dense 和 Reranker 模式完全离线运行。
- 没有实现 E3 的自定义并发队列、完整加载状态机、索引迁移或自动恢复。
- 第一阶段概要设计中的 E0 和 E1 验收条件均有代码、测试或报告证据。

## 6. 正式提交仓库

### RAG-100：补齐 E2 集成要求

等级：E2；不阻塞本地学习实验，正式提交 DSH 仓库前必须完成。

依赖：`RAG-090`。

范围：

- 增加或更新 Agent Note、包 README、JSDoc 和 `./invariant`。
- 增加真实 Loader 组合测试和无密钥模型可见快照。
- 按仓库要求增加自跳过的真实模型 E2E。
- 记录 SciFact、原始模型和 ONNX 转换来源及许可证。
- 运行当时变更范围要求的仓库检查。

完成条件：

- Service、工具和提示词在 fiber 释放后不会重复注册。
- 真实模型和完整数据产物未进入 Git。
- `dsh-pre-push-checks` 选择的检查全部通过。
- 概要设计、详细设计、公共 API、README 和实际行为一致。

## 7. E3 后续方向

下列内容不拆成第一阶段任务：

- 自定义并发推理队列和完整模型加载状态机。
- 等待全部推理静止的复杂释放流程。
- 目录级原子发布、索引迁移和崩溃恢复。
- HNSW、远程向量数据库和大规模性能优化。
- 自动重试、降级、监控告警、权限控制和多租户。
