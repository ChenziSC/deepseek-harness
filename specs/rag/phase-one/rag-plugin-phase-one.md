# DSH RAG 插件第一阶段概要设计规格

本文确认第一阶段的目标、范围、算法选择、插件职责和验收条件。接口、文件格式和运行流程见[详细设计](rag-plugin-phase-one-detailed-design.md)，可交付任务及依赖顺序见[实施任务](rag-plugin-phase-one-implementation-tasks.md)。

## 1. 目标

本阶段实现一个面向学习与实验的只读 RAG（检索增强生成）插件，使 agent 能从一份预先准备的静态语料库中检索证据。现有 agent loop 继续负责调用工具和生成回答；本能力只负责索引、召回、重排序和结果呈现，不在检索插件内再次调用大模型生成答案。

第一阶段必须在相同语料、分片、查询、候选数量和评测器下完成以下六组可复现实验：

| 召回方式 | 不使用重排序器 | 使用重排序器 |
| --- | --- | --- |
| BM25 | 必须 | 必须 |
| Dense | 必须 | 必须 |
| Hybrid | 必须 | 必须 |

第一阶段的目标不是宣布某一种方案普遍最优，而是让开发者可以观察词项匹配、语义匹配、结果融合和跨编码器重排序分别解决什么问题，以及它们在质量、延迟、内存和索引体积上的代价。

## 2. 范围

第一阶段包含：

- 读取通用 JSONL 语料并生成不可变本地索引。
- 适配 BEIR SciFact 数据集，作为默认公开实验数据。
- 确定性的文本分片。
- Okapi BM25 稀疏检索。
- BGE 稠密 embedding 与精确向量检索。
- 基于 RRF 的稀疏与稠密混合检索。
- 可独立开关的跨编码器重排序器。
- 一个模型可调用的 `knowledge_search` 工具。
- 离线准备、建索引和评测命令。
- 覆盖六组组合的质量与性能报告。

第一阶段不包含：

- 运行时写入、增量更新、删除或多版本索引。
- 用户长期记忆、会话记忆或个性化召回。
- 多知识库选择、租户隔离、访问控制和权限过滤。
- 远程向量数据库或托管搜索服务。
- 语义分片、知识图谱、GraphRAG、RAPTOR 和多模态检索。
- 学习型稀疏检索，例如 SPLADE 或 BGE-M3 的稀疏向量。
- HNSW、IVF 等近似最近邻索引。
- 自动查询改写、查询路由和由模型动态选择检索算法。
- 自定义推理调度队列、完整模型加载状态机和自动故障恢复。
- 索引迁移、增量发布、崩溃恢复和跨版本兼容。
- 多机性能测试、监控告警和生产容量规划。

### 2.1 工程等级

本规格用工程等级区分实验必需内容和后续生产能力：

| 等级 | 含义 | 第一阶段要求 |
| --- | --- | --- |
| E0 | 保证算法和评测结论正确 | 全部完成 |
| E1 | 低成本提升可复现性和实验体验 | 完成与本地实验直接相关的部分 |
| E2 | 正式提交 DSH 仓库所需的集成质量 | 准备提交时完成 |
| E3 | 面向生产部署和大规模运行 | 不实施，只记录后续方向 |

第一阶段实现目标为 E1，实验是否成功按 E0 验收。固定模型 revision、本地缓存、简单索引清单、基本取消、微型测试和可运行示例属于 E1。Agent Note、完整仓库门禁和真实组合测试属于 E2，不改变算法实验范围。自定义并发调度、索引迁移、自动恢复和生产监控属于 E3。

## 3. 默认数据集

默认实验数据采用 [BEIR SciFact](https://github.com/beir-cellar/beir/wiki/Datasets-available)。它是英文科学事实核验数据集，规模约为五千篇文档和三百条测试查询，适合在个人电脑上完成端到端实验。它不是中文数据集，因此本阶段只能验证英文检索链路，不能据此推断中文效果。

适配器读取 BEIR 的标准文件：

- `corpus.jsonl`：文档正文和标题。
- `queries.jsonl`：评测查询。
- `qrels/test.tsv`：查询与相关文档的标注。

数据集不提交到仓库，也不在插件启动时自动下载。准备命令必须由开发者显式执行，并校验下载内容。仓库只提交一份足够覆盖算法和错误路径的微型合成语料。

通用 JSONL 文档格式为：

```json
{"id":"doc-1","title":"可选标题","text":"非空正文","source":"可选来源"}
```

其中 `id` 必须是唯一非空字符串，`text` 必须是非空字符串，`title` 和 `source` 可选。文件输入属于不可信边界，解析器必须拒绝重复标识、缺失字段、错误类型和不可解析的行，并报告行号。

## 4. 插件拆分

按照 DSH 的能力 seam 约定，本功能拆成三个实验包：

| 包 | 角色 | 职责 |
| --- | --- | --- |
| `@deepseek-ai/dsh-experimental-knowledge` | Service Definition | 定义 `ctx.knowledge`、品牌化标识、提供方无关的请求、结果与错误类型 |
| `@deepseek-ai/dsh-experimental-knowledge-local` | Service Provider | 加载本地索引，实现 BM25、Dense、Hybrid、重排序、索引构建和评测 |
| `@deepseek-ai/dsh-experimental-tool-knowledge` | Consumer | 注册 `knowledge_search`，限制模型输入输出并提供提示词和通用展示 |

`Knowledge` 是抽象 Cordis Service。`knowledge-local` 默认导出继承它的 `LocalKnowledge`，并由该类注册 `ctx.knowledge`；运行配置不单独挂载抽象 Service。第一阶段只有一个本地实现，不增加提供方注册表。

服务请求包含查询文本、可信调用方提供的最大结果数和取消信号。每条结果包含文档标识、分片标识、标题、正文、来源和最终排序分数。分数只允许在同一次响应内比较，不承诺跨算法、跨查询或跨索引可比。各阶段原始分数只进入本地评测诊断，不进入模型上下文。

本地提供方同时提供独立可执行程序，至少支持：

```text
prepare   显式下载并校验数据集和模型
index     从语料构建不可变索引
evaluate  运行六组实验并生成报告
```

插件启动只加载已有产物，不下载数据、不下载模型，也不隐式重建索引。

## 5. 文档分片

分片器必须是确定性的，并按以下顺序寻找边界：

1. 段落边界。
2. 句子边界。
3. 模型 tokenizer 的 token 边界。

默认最大长度为 384 个模型 token，重叠为 64 个 token。标题不参与边界计算，但在 BM25、Dense 和重排序输入中以“标题、换行、分片正文”的形式加入。分片标识由文档标识和正文 token 起止位置确定，因此同一语料和相同配置必须产生稳定标识。

所有召回算法都以分片为检索单位。SciFact 的相关性标注是文档级的，因此评测时先按排名保留每篇文档首次出现的分片，再计算文档级指标，避免同一文档的多个分片重复占位。

## 6. BM25 稀疏检索

第一阶段的稀疏算法固定为标准 Okapi BM25，不同时引入其他稀疏模型，以便建立可解释、低依赖的基线。

默认英文分析器命名为 `english-v1`，处理流程为：

1. Unicode NFKC 规范化。
2. 转为小写。
3. 提取连续的 Unicode 字母和数字作为 token。

第一阶段不做词干化、同义词扩展、停用词移除或学习型词项加权。默认参数为 `k1 = 1.2`、`b = 0.75`，均属于本地提供方配置。逆文档频率定义为：

```text
idf(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))
```

查询中的重复 token 只计算一次，不额外引入查询词频权重。

结果按 BM25 分数降序排列；分数相同时按分片标识升序排列。评测诊断应能展示查询 token、词频、文档频率、分片长度和各词项贡献，但这些信息不发送给模型。

## 7. Dense 稠密检索

第一阶段选择 [BAAI/bge-small-en-v1.5](https://huggingface.co/BAAI/bge-small-en-v1.5) 作为明确的稠密 embedding 算法，使用 [onnx-community/bge-small-en-v1.5-ONNX](https://huggingface.co/onnx-community/bge-small-en-v1.5-ONNX) 的量化模型和 Transformers.js Node 运行时。默认数据类型为 `q8`。

编码规则固定如下：

- 文档输入：标题、换行、分片正文，不添加指令。
- 查询输入：在原查询前添加 `Represent this sentence for searching relevant passages: `。
- 查询和文档输入均按模型上限截断到 512 token；查询前缀完整保留，超出部分从正文尾部截断。
- 池化：取最后一层隐藏状态的 CLS token。
- 向量维度：384。
- 归一化：L2 归一化。
- 相似度：使用 float32 点积；归一化后它与余弦相似度具有相同排序。

第一阶段采用精确的扁平向量扫描，不引入 HNSW。它能提供确定性的正确性基线，也使后续增加近似索引时可以直接测量召回损失。分数相同时按分片标识升序排列。

模型标识不能只依赖可变标签。准备命令必须解析并记录固定 revision，运行时使用该 revision 和本地缓存加载模型，并启用只读本地文件模式。索引清单记录模型标识、revision、数据类型、向量维度、池化和归一化方式。

未来的中文实验可以新增 `bge-small-zh-v1.5` 配置，但不能复用本阶段 SciFact 索引：中文模型向量维度为 512，还需要中文分析器和中文评测集。第一阶段不把中英文模型自动切换纳入范围。

## 8. Hybrid 混合检索

Hybrid 同时执行 BM25 和 Dense，默认分别取前 50 个候选，以分片标识去重后使用 Reciprocal Rank Fusion（RRF）融合：

```text
rrfScore(d) = 1 / (rrfK + bm25Rank(d)) + 1 / (rrfK + denseRank(d))
```

未进入某一路候选集的分片不贡献该项。默认 `rrfK = 60`。结果先按 RRF 分数降序，再按两路中的更优名次升序，最后按分片标识升序。

第一阶段不对 BM25 分数和向量相似度做线性归一化，不训练融合权重，也不按查询类型路由。RRF 只依赖排名，适合作为可解释且稳定的混合基线。

## 9. 重排序器

重排序是独立于召回方式的开关，必须能应用于 BM25、Dense 和 Hybrid，从而形成六组完整实验，而不是只为 Hybrid 提供重排序。

默认重排序模型采用 [BAAI/bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3)，通过 [onnx-community/bge-reranker-v2-m3-ONNX](https://huggingface.co/onnx-community/bge-reranker-v2-m3-ONNX) 运行，默认数据类型为 `q8`。该跨编码器接收查询与“标题、换行、分片正文”的文本对。

默认候选数量为 50，文本对最大长度为 512 个模型 token，批大小为 8，最终结果数量由 Consumer 控制。重排序按原始 logit 降序排列；不做 sigmoid，因为单调变换不改变排名。logit 相同时保持召回阶段的原始顺序。

稠密模型和重排序模型按需延迟加载。并发加载共享同一个 Promise；加载成功后复用模型实例，加载失败后清空 Promise，使后续调用可以重试。一次检索内部按召回、融合和重排序顺序执行，并在阶段之间及重排序批次之间检查取消信号。第一阶段不实现自定义推理队列，也不承诺中断正在执行的单个 ONNX 批次。

## 10. 索引产物

索引只能在空目录中构建。构建程序先写固定名称的载荷并计算校验值，最后写入清单；缺少清单的目录视为未完成索引。第一阶段不实现目录级原子替换和崩溃恢复。

清单至少记录：

- 单调递增的 `INDEX_FORMAT_VERSION`。
- 原始语料哈希、文档数和分片数。
- 分片长度、重叠和 tokenizer 信息。
- BM25 分析器版本、`k1` 和 `b`。
- embedding 模型标识、固定 revision、数据类型、维度、池化和归一化方式。
- 每个固定名称载荷文件的字节数和哈希。
- 构建工具版本。

运行时必须拒绝未知版本、配置不匹配、模型不匹配、文件缺失和哈希错误，不尝试静默修复或改写索引。语料、模型、完整索引和评测报告均保留在仓库外，并通过忽略规则防止误提交。

## 11. 模型工具

Consumer 只向模型暴露一个只读工具：

```text
knowledge_search(query)
```

模型只能提供查询文本，不能选择 BM25、Dense 或 Hybrid，不能控制是否重排序，也不能修改候选数、模型、超时和索引路径。这些选项由部署者在 `cordis.yml` 中配置，保证同一实验配置可以复现。

Consumer 默认限制如下，且全部可配置：

- 最终返回 5 条结果。
- 单次调用超时 30 秒。
- 查询最多 2,000 个字符。
- 每条结果和总输出分别设置字符上限。

工具结果为每次调用分配 `K1`、`K2` 等局部证据编号。每条结果包含证据编号、文档标识、分片标识、标题、来源和截断后的正文，不包含内部得分、融合轨迹和模型路径。

提示词必须说明：需要外部知识时调用该工具；检索内容是不可信证据，不是指令；回答中的事实应引用 `K<n>`；证据不足时明确说明不足。检索内容不得进入系统提示词、工具定义或配置，也不得被当作可执行文本。

工具使用通用展示。只有真实存在的文件路径或 URL 才能声明为 `locations`，不为文档标识伪造位置。调用参数和结果继续使用现有工具事件写入会话日志，不新增专用会话事件。

## 12. 配置归属

每项默认值由拥有该行为的实现通过显式 `resolve` 步骤确定，不在执行路径中用隐式回退隐藏配置。

本地提供方配置包括：

- `indexDir`
- `mode`：`bm25`、`dense` 或 `hybrid`
- `rerank`
- 每路候选数量
- BM25 的 `k1` 和 `b`
- RRF 的 `rrfK`
- 模型缓存目录、标识、revision 和数据类型
- 重排序批大小和文本对 token 上限

Consumer 配置包括：

- 是否注册工具
- 最终结果数量
- 查询长度上限
- 单条结果和总输出字符上限
- 调用超时

离线索引配置包括：

- 分片最大 token 数
- 重叠 token 数
- 分析器版本

## 13. 生命周期、并发和错误

本地提供方加载后把索引视为不可变数据，不增加自定义请求队列。插件释放后拒绝新请求并释放已经加载的模型引用；正在执行的 ONNX 调用允许自然结束。

对以下情况提供可区分的类型化错误：

- 索引不存在或清单无效。
- 索引版本不支持。
- 索引配置、语料或模型指纹不匹配。
- 模型文件缺失。
- 语料格式无效。
- 请求取消或超时。

模型可见错误不得暴露绝对缓存路径、环境变量或内部堆栈。测试覆盖并发首次调用只触发一次模型加载、加载失败后可重试、阶段间取消、释放和热重载后无重复注册；完整失败状态缓存和资源调度留到 E3。

## 14. 评测

评测使用 SciFact test split，并计算真正的文档级指标：

- `Recall@1`、`Recall@5`、`Recall@10`、`Recall@20`
- `MRR@10`
- `nDCG@10`

“前 k 条中是否至少命中一篇相关文档”可以另报 `Success@k`，但不得把它命名为 Recall。多个相关文档存在时，Recall 必须使用已命中的相关文档数量除以相关文档总数。

评测与模型工具使用不同的结果上限。评测固定取前 20 个文档结果，三种召回方式都使用 50 个候选；模型工具仍默认只返回 5 条证据。qrels 中相关性大于 0 的文档视为相关，查询按查询标识排序。任一查询失败会使当前实验组合失败，不使用其余查询计算部分平均值。

每份报告还记录：

- 六组实验各自的指标。
- 预热后的查询延迟 `p50` 和 `p95`。
- 建索引耗时和索引字节数。
- 语料哈希、索引指纹、模型标识与 revision、完整配置。
- 失败查询和错误信息。

评测先执行固定次数预热，预热请求不计入延迟统计。查询顺序、排序平局处理和报告字段必须确定。报告记录成功组合的指标和失败组合的错误，不在代码中硬编码“最佳方案”。

单元测试使用微型合成语料覆盖：

- 分片稳定性与文档级去重。
- BM25 token、IDF 和排序。
- 向量归一化、点积和精确扫描。
- RRF 融合和确定性平局处理。
- 重排序开关与候选截断。
- 六条检索路径。
- Recall、MRR、nDCG 和 Success 的计算。
- 索引损坏、配置不匹配、取消与生命周期。

真实模型和完整 SciFact 评测作为本地可复现实验，不进入默认 CI。CI 只运行不依赖网络和大模型文件的确定性测试。

## 15. 与现有能力的关系

`ctx.sessionQuery` 检索的是 DSH 会话日志，使用 SQLite 条件查询，也不提供相关性得分；它不应承担外部知识库检索。

会话压缩中“不为会话内容增加向量旁路”的既有结论针对会话真源和压缩语义，不限制独立、只读的外部语料索引。

现有第三方 memory MCP 示例把用户记忆委托给外部服务。本规格实现的是本地共享知识检索，不写入用户记忆，也不复用其数据模型。

## 16. 交付顺序

1. 完成 Service Definition、本地 Provider、语料加载、分片、BM25、`knowledge_search` 和微型可运行示例，得到第一条完整检索链路。
2. 完成 BGE embedding、精确向量扫描和本地模型准备，加入 Dense 对比实验。
3. 完成 RRF 和跨编码器重排序，形成 BM25、Dense、Hybrid 及其重排序版本。
4. 完成 SciFact 六组统一评测、报告和 E1 收尾；准备正式提交时再补齐 E2 仓库要求。

四步全部完成才算第一阶段完成。BM25、Dense、Hybrid 或 Reranker 中任何一项只能运行但没有进入统一评测矩阵，都不满足验收要求。

## 17. 验收标准

- 三个实验包分别承担 Service Definition、Service Provider 和 Consumer；运行配置挂载 `knowledge-local` 和 `tool-knowledge`，由 `LocalKnowledge` 注册 `ctx.knowledge`。
- 离线命令能从显式提供的 SciFact 文件构建确定性索引；运行时完全离线且不修改索引。
- BM25 严格使用本规格中的分析器、公式和默认参数。
- Dense 严格使用固定 revision 的 BGE 英文模型、CLS 池化、384 维 L2 归一化向量和精确点积扫描。
- Hybrid 严格使用 BM25 与 Dense 各前 50 条候选和 `rrfK = 60` 的 RRF。
- 重排序器能独立应用于三种召回方式，并保持确定性的平局顺序。
- 统一评测器以 50 个候选和前 20 个文档结果生成六组结果，指标实现经过微型夹具验证，文档级 Recall 与 Success 明确区分，失败组合不产生部分平均值。
- `knowledge_search` 只接受查询文本，结果有引用编号和严格输出上限，不向模型暴露诊断分数。
- 缺失、损坏或不匹配的索引和模型在最早可判断时明确失败，不静默降级到其他算法。
- E1 具备焦点单元测试、可运行示例和真实模型本地烟测；正式提交仓库时补齐 E2 要求的 Agent Note、真实 Loader 组合、无密钥快照和受影响文档。

## 18. 已知风险

- 重排序模型明显大于稠密 embedding 模型，冷启动、磁盘和内存成本可能主导本地体验，报告必须单独呈现有无重排序的代价。
- SciFact 较小、仅英文，而且多数查询相关文档很少，适合教学基线但不足以代表中文、长文档或多跳问答。
- 分片级召回与文档级标注存在粒度差异，必须保留文档折叠逻辑并在报告中说明。
- 检索文本可能包含提示注入内容，工具结果必须保持不可信数据身份，不能改变系统指令。
- ONNX 在不同 CPU 和操作系统上的绝对延迟会变化，性能报告必须附带平台和模型 revision，不能只给脱离环境的数字。
- 三包拆分增加少量脚手架，但能保持能力角色清晰，并避免把模型工具、离线索引和检索实现绑定在一个难以替换的包中。
