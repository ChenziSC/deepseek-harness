# Agent Note: 本地知识索引的预算化上下文前缀

Status: rejected — 真实语料评测未达到成本、质量、稳定性和事实性门槛

[English](2026-09-09-budgeted-contextual-prefixes.md) | 中文

## Problem

第六阶段的隔离实验表明，生成式上下文可以改善歧义分片的检索，但逐分片方案不适用于大规模语料。该方案为每个分片重复输入文档上下文，使索引 token 增加29.49%，一次运行未达到生成成功率门槛，而且使用的合成样本存在明显模板偏差。在真实收益尚未得到证明前对所有分片应用该方案，会产生大量模型费用和不必要的向量失效。

现有确定性检索文本成本低且稳定，但不能始终解析代词、相对时间、跨章节引用或通用标题。因此值得实现的是选择性离线增强，而不是无条件替换当前索引路径。

## Proposal

把上下文前缀实现为必须显式开启的离线索引选项。默认值保持`off`；加载索引和执行查询均不调用前缀模型。启用后的构建先生成确定性计划和成本预览，再在明确的候选比例与 token 预算内，只为高歧义分片生成前缀。

检测器使用版本化的词法和结构规则，不调用LLM。生成过程把同一文档章节内的相邻候选合并到有限上下文窗口，避免每个分片重复提交长文档。每个请求除了各前缀的正文额度，还预留128个输出token，用于JSON结构和供应商计入输出用量的推理过程。提示词要求每条前缀只写一个紧凑句子，目标长度不超过校验上限的一半，为tokenizer差异预留余量；解析器仍严格拒绝超过配置硬上限的前缀。分片器会抑制仅由尾部空白触发、内容完全落在重叠区间内的尾部分片，确保缓存中的token区间严格递增。独立的内容寻址缓存以准确上下文窗口、目标分片、检测器和提示版本、模型身份、参数及输出限制为键。未选中分片保持现有检索文本和向量缓存身份。

完整语料只扫描汇总候选和成本统计。精确扫描对每篇文档执行 tokenizer；超大语料可以通过文档 ID 摘要的确定性抽样估算分片级总量，但扫描器仍逐篇读取、校验、计算完整语料摘要和文档数，并记录抽样模数与实际分片文档数。质量评测构建包含完整qrels证据的有界子集，每个数据集最多10,000个分片、合计最多50,000个分片，不重新构建完整语料索引。生成前缀与来源证据分开保存，知识工具不返回前缀。

## Alternatives considered

**为每个分片生成前缀。** 不采用，因为完整本地语料预计约有950万个分片。按第六阶段的逐分片用量外推会产生数十亿生成token，MLDR长文档的重复全文提示还会高于统一估算。

**只使用确定性标题和章节元数据。** 保留为默认值和回退方案。它成本低且可复现，但第六阶段Pilot表明它无法解决所有依赖上下文的分片。

**生成一份文档摘要并附加到全部分片。** 不作为唯一方案，因为单一摘要可能稀释章节实体，并向索引重复加入相同文本。生成批次可以共享文档或章节上下文，但每个入选分片仍获得有界前缀。

**查询时生成上下文。** 不采用，因为它增加在线延迟，使检索依赖额外模型请求，并降低结果可复现性。前缀生成属于离线产物构建。

## Acceptance criteria

- 默认构建不初始化前缀模型、不读取凭据，也不发起网络请求。
- 完整语料评测只执行流式统计，不创建完整SQLite、BM25、Exact或HNSW索引。
- 真实语料质量评测每个数据集不超过10,000个分片，合计不超过50,000个分片。
- 有界批处理相对为每个候选分片提交完整文档，生成输入至少减少80%。
- 未变化构建重复运行时复用全部成功前缀，局部文档变化只使受影响上下文窗口失效。
- 生成前缀相对确定性前缀使高歧义Recall@10或完整证据覆盖率至少提高5个百分点，同时任一检索路径的nDCG@10回退不超过1个百分点。
- 即使全部条件通过，功能仍必须显式开启并保持默认关闭。

## Risks

确定性规则可能漏掉语义歧义或误选无害代词，因此需要真实语料复核候选准确率和召回率。生成文本可能加入无依据的具体表述或改变排序的关键词。供应方计费可能与预估token不同，尤其是长篇多语言输入，因此实际usage始终是权威数据。模型或提示升级会使生成前缀缓存失效，并可能在原文档未变化时重新编码全部入选分片。
