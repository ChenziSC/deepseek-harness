# Agent Note: Local read-only RAG retrieval seam

Status: implemented

English | [中文](2026-09-04-local-rag-retrieval.zh.md)

## Problem

DSH had no provider-neutral way for an agent to retrieve evidence from a developer-supplied knowledge corpus. A learning implementation also needed to compare sparse retrieval, dense retrieval, rank fusion, and neural reranking under one corpus and evaluator without coupling those algorithms to the agent loop or exposing deployment controls to the model.

## Decision

The experimental capability is split into the three complete seam roles. `@deepseek-ai/dsh-experimental-knowledge` defines the provider-neutral `ctx.knowledge` service, branded document and chunk identifiers, ranked hits, and stable caller-visible errors. `@deepseek-ai/dsh-experimental-knowledge-local` provides that service from one immutable local index. `@deepseek-ai/dsh-experimental-tool-knowledge` consumes the service through the read-only `knowledge_search(query, asOf?)` model tool.

The local provider supports SQLite FTS5 BM25 with deterministic English or mixed Chinese-English analysis, exact float32 Dense scan with fixed-revision BGE-M3, HNSW through USearch, and Reciprocal Rank Fusion over sparse and Dense routes. HNSW queries default to `expansionSearch=1024`; the value remains deployment-configurable and is not model-visible. Request-time automatic routing sends exact identifiers to BM25 and all other queries to Dense, with deterministic fallbacks inside the deployment-configured allowed set. This rule retains the measured cross-script benefit while avoiding Hybrid's quality and latency regression on the T2Ranking same-script sample; Hybrid remains an explicit caller choice. A fixed-revision multilingual BGE cross-encoder can rerank the leading candidates for any retrieval mode; `off` is the performance default, `on` forces reranking for a non-empty result, and `auto` applies it only when the normalized top-two recall-score gap is below the configurable `0.15` default. Recall retains 50 candidates by default while the cross-encoder scores at most the first 20. Every result reports the concrete retrieval and Dense index plus whether reranking actually ran. A request may select one explicit RFC 3339 instant; otherwise the provider captures the current time once. Documents are eligible on an inclusive `validFrom` and exclusive `validUntil` interval, while missing bounds remain searchable. BM25 filters before its candidate limit, Exact skips ineligible ordinals, HNSW progressively over-fetches without returning invalid fallbacks, and Hybrid fuses only filtered candidates. `supersedes` is returned as provenance and never hides another document or changes ranking.

Markdown-aware chunking is the default and prefers ATX section boundaries, then paragraphs and sentences, while preserving fenced code blocks unless one exceeds the token limit. Section paths join the indexed BM25 and Dense text. The offline builder also exposes a fixed token-window strategy without section paths for controlled comparisons, records the strategy in the manifest, and rejects derivation across strategies. After ranking, the provider may attach one preceding and one following same-document chunk without increasing the result count; overlap text is removed and selected neighbors are not repeated. The Consumer bounds matched and adjacent evidence, encloses each result in generated untrusted-data markers, indents every untrusted field line, assigns citations that are unique within one agent turn, and omits scores and low-level tuning from model context. Retrieved text cannot authorize tool use or override system, developer, or user instructions; the model may quote or analyze it only as evidence. Its prompt asks the model to identify independent evidence requirements, start with one query, issue only one search at a time, inspect its result, and continue only for a requirement without direct support, conflicting evidence, or a missing intermediate fact. Each follow-up targets the remaining gap rather than repeating an earlier query; a follow-up that needs an opaque identifier obtained from evidence contains only that identifier. A material conflict remains unresolved until a targeted query distinguishes its time, subject, scope, version, or authoritative decision; rank, score, and apparent recency alone cannot select a side, and absent adjudicating evidence remains explicit uncertainty. Deployments may allow one through eight searches per turn, with six as the measured default, and separately bound the cumulative rendered text from successful results. Searches with the same explicit `asOf` and NFKC-equivalent, lowercased, whitespace-folded query are rejected; the same query at a different instant is distinct. Every attempted call consumes the search-count budget and a disjoint citation range, including duplicates, provider failures, and output-budget rejection; only successful rendered results consume the cumulative character budget. The next turn resets all usage. Direct non-agent calls are not turn-limited and each starts at `K1`.

Index preparation is an explicit offline operation. Format version 4 streams source documents through bounded transactions into `knowledge.sqlite`, where a normalized document table owns source version, validity, and replacement metadata while chunk records, section paths, and pre-analyzed SQLite FTS5 input share ordinal keys with optional `dense.f32le` and `dense.usearch` payloads. The manifest records a streaming Latin/CJK corpus profile for reproducible evaluation without retaining another corpus copy. After chunking, the builder records the exact scale and a conservative recommendation based on `vectorCount × dimensions`; an interactive command may confirm Exact-only, HNSW-only, or Both before embedding, while a non-interactive command deterministically accepts the recommendation. HNSW-only still embeds every chunk but does not retain the additional Exact file, and Both is reserved for explicit comparisons. Long-document chunking locates each hard token limit with bounded local probes instead of repeatedly tokenizing the remaining document or its complete prefix. The manifest records the Dense model, vector count, dimensions, scan threshold, recommendation, requested choice, retained payload mode, query default, and HNSW build parameters. Runtime opens SQLite read-only, validates payload types and sizes plus schema metadata, optionally verifies hashes on startup, and exposes a separate command that always recomputes every payload hash. Exact vectors and the HNSW graph load only when requested. SQLite FTS5 owns fixed BM25 scoring parameters; deployment configuration does not expose the first implementation's in-memory `k1` and `b` controls. Plugin startup and search never download corpora or models and never rebuild or modify the index. Dense retrieval and reranking require an explicit populated local model cache; BM25 can run without model weights.

Dense construction may use a separate build-time SQLite vector cache. Each key is a length-delimited SHA-256 over the complete document-encoding configuration and exact Dense input, including title, section path, and chunk text. The builder reads cache entries in bounded batches, encodes each missing key once, commits each successful embedding batch atomically, and assembles Exact vectors in the target's new ordinal order. A verified format-4 Exact index can prefill the cache only when its payload hashes and Dense settings match; the source remains read-only. Interrupted builds retain committed cache batches but never publish the target manifest. HNSW is rebuilt from the complete newly ordered vector sequence rather than updated in place.

Index construction may also use an independent document-derivation SQLite cache. Its length-delimited content key covers tokenizer and chunking configuration, BM25 analyzer semantics, document id, title, and body. Each value contains the complete ordinal-independent chunk sequence, Dense inputs, and analyzed BM25 text. Source, version, validity, and replacement metadata remain outside the key and are always projected from the current corpus into the rebuilt document table. Cache hits skip tokenization, chunking, and BM25 preprocessing; the builder still assigns new global ordinals and reconstructs every published payload. Cache rows commit atomically before target SQLite writes, while schema, digest, identity, chunk order, token range, and Dense-input failures stop the build with the affected key.

The offline command prepares fixed revisions of BEIR SciFact, MLDR English and Chinese, T2Ranking, and MLQA Retrieval `eng-zho`, builds indexes, verifies their hashes, and evaluates selected automatic, BM25, Dense, Hybrid, Exact, HNSW, and `off`/`auto`/`on` reranking combinations under one document-level evaluator. The concise aggregate report folds chunk hits to unique documents and records Recall, MRR, nDCG, Success, latency, payload sizes, resolved-route counts, adaptive-reranking application rate, and HNSW recall relative to Exact. A separate JSONL file records each measured query's requested and resolved strategy, ranking, judgments, single-query metrics, latency, and the recall top-two score gap when reranking has not replaced the recall scores. Failed queries are recorded before their complete configuration is marked failed, and no partial aggregate is reported. Each dataset supports a bounded conclusion: SciFact is an English regression, MLDR covers multilingual long documents, T2Ranking covers Chinese retrieval and scale, and MLQA Retrieval covers Chinese queries over English passages.

Exact/HNSW threshold calibration uses deterministic nested T2Ranking slices containing every selected-query positive followed by official BM25 hard negatives. The largest slice is embedded once; smaller ordinal-prefix indexes rebuild SQLite and HNSW while copying validated Exact vector batches. Derivation rejects a mismatched chunk identity, retrieval text, analyzer, tokenizer, or chunking configuration, so reused vectors cannot silently attach to different content.

## Alternatives considered

**Add retrieval behavior directly to `agent-loop`.** Rejected: retrieval is an optional capability with its own provider and Consumer lifecycle. The existing tool path already lets the model request evidence and keeps the loop independent of corpus and ranking choices.

**Implement the service, local algorithms, and model tool in one package.** Rejected: this would make a future provider depend on local index formats and make a non-model Consumer depend on prompt and rendering policy. The three roles change for different reasons and satisfy the repository's capability-seam structure without adding a provider registry.

**Use a remote vector database or managed search service.** Rejected for this phase: it would add deployment, credentials, network behavior, and provider-specific indexing before the retrieval algorithms can be compared locally. The provider-neutral service leaves that option open without putting remote concerns in the teaching implementation.

**Expose embedding or reranker inference as the product API.** Rejected: callers need ranked evidence, not model tensors. Making model execution the service would leak pooling, dimensions, prompts, and cache layout across the package boundary and would not represent BM25 or Hybrid retrieval.

**Download missing corpora or models at runtime.** Rejected: startup would become network-dependent and mutable, while experiments could silently use changed assets. Explicit preparation and fixed revisions make runtime behavior reproducible and let missing prerequisites fail clearly.

**Keep separate JSONL chunk and JSON BM25 payloads.** Rejected: loading those files materializes the complete corpus and inverted index in JavaScript before a query can run. One embedded SQLite payload supports bounded construction, read-only lookup, schema validation, and BM25 without adding a database service.

**Reuse vectors by source identity or ordinal.** Rejected: document insertion, deletion, reordered input, or changed chunk boundaries would either miss reusable content or attach a vector to the wrong text. Content-addressed keys make exact Dense input equality and model configuration the reuse condition, while target ordinals remain local to each immutable index.

**Filter validity only after retrieval.** Rejected: expired or future documents could fill the BM25 or ANN candidate window and hide eligible evidence. Every recall route filters before final ranking, and the provider asserts candidate eligibility before reranking and projection.

**Enable length-bucketed encoding or a larger default batch.** Rejected by the measured sample. Length bucketing reduced wall time but changed Exact rankings and lowered MRR@10 and nDCG@10; increasing the fixed batch from 32 to 64 provided only a small throughput gain while raising peak RSS by about 41%. Both remain outside the supported builder instead of becoming unproven defaults.

**Claim Markdown boundaries or adjacent expansion as universal quality improvements.** Rejected by the fixed 25-query Markdown ablation. Structure-aware chunks reduced the five-hit context by about one third and improved BM25, but Dense and Hybrid nDCG@10 each fell by 1.48 percentage points. Adjacent expansion improved average complete-evidence coverage by 4 percentage points while increasing returned tokens by 77%. The features remain explicit, measurable choices rather than unconditional quality claims.

**Add semantic-boundary chunking after a small boundary pilot.** Rejected because constrained maximum-gap selection matched the no-model last-safe-unit baseline at 50% exact boundary recall while producing more boundaries; percentile and fixed-distance variants were worse. A larger independent pilot must first show a stable boundary benefit before semantic chunking, a second vector-cache purpose, or a three-index ablation is justified.

**Add LLM-generated contextual prefixes to production retrieval text.** Rejected because the independent 200-query real-corpus evaluation failed cost, quality, stability, and factuality thresholds. Bounded batching saved 79.7587% rather than the required 80%; high-ambiguity Recall@10 and complete-coverage gain peaked at zero; SciFact and MLQA nDCG@10 fell by about 2.96–3.40 percentage points; all-candidate generation success was 98.16%; and blind factual review passed 70/73 generated prefixes, or 95.89%. Small Hybrid nDCG gains on three datasets without Recall improvement do not justify product index integration.

## Consequences

Deployments mount one Knowledge provider and may mount the tool Consumer; they do not mount the abstract Service Definition. The provider resolves each request through deployment defaults and allowed sets before retrieval. Index format 4 intentionally supports one read-only corpus, immutable whole-index publication, SQLite FTS5 BM25, Exact Dense scan, and one HNSW implementation. Automatic Dense selection uses the recorded vector-count-by-dimension scan size rather than current-machine detection. The `50,000,000`-element default is a configurable conservative sweet spot, not a measured cross-machine crossover. Requesting an unavailable Dense index fails instead of falling back. Automatic query routing and adaptive reranking are transparent deterministic heuristics, not learned classifiers; callers can override the high-level strategy, while only deployments configure thresholds. USearch graph construction with native automatic threading can produce different graph bytes and approximate neighbors from the same vectors, so each evaluation records the exact index fingerprint. Failed builds may leave an unpublished incomplete directory, and complete benchmark indexes are built, evaluated, and removed sequentially when local storage is constrained. The implementation does not provide in-place index updates, incremental HNSW graph mutation, multi-corpus routing, access control, remote storage, a second ANN family, inference scheduling, or production recovery.

The checked-in `rag-knowledge` example exercises the assembled BM25 path without external models. Package tests cover the service lifecycle, index validation, Markdown-aware chunking, script profiling, multilingual BM25, Exact-only, HNSW-only and dual-payload Dense retrieval, content-addressed vector reuse and recovery, version-validity filtering across all recall paths, RFC 3339 boundaries, RRF, automatic routing, adaptive bounded reranking, adjacent expansion, configurable turn-scoped search and output limits, duplicate-query rejection, cancellation, offline commands, and dataset evaluation. Keyless snapshots exercise the real Loader composition and the model-visible default, lexical, exact, and quality requests. Model-cache smoke tests run in a separate test module without the Transformers.js mocks used by unit tests. Local benchmark results and hardware-specific latency remain experimental evidence rather than product guarantees. SciFact and MLQA Retrieval have full-query local reports; T2Ranking and MLDR use fixed slices. HNSW result overlap is an observation rather than a universal acceptance threshold, and standard qrels metrics own dataset quality conclusions.

Content-addressed reuse makes document derivation and Dense encoding independent of source-document and chunk ordinals, but it intentionally requires exact relevant-input equality. Changed bodies, headings, titles, tokenizer, chunking, analyzer, or Dense settings produce the corresponding cache miss. Neither cache is part of a published runtime index or weakens format-4 validation and immutable publication.

The fixed 800-document, 1,096-chunk SciFact build benchmark accepts document-derivation caching as a measured optimization. Relative to vector-cache-only builds, mean construction time falls by 99.8% with no document changes, 93.3% with about 1% changed documents, and 60.7% with about 10% changed documents. A 100% change adds 1.14% mean construction time and reduces mean peak RSS by 3.8%. Chunk rows, analyzed FTS input, Exact vector bytes, and the fixed 21-query metrics remain identical; the detailed evidence is in [`specs/rag/phase-six/rag-plugin-phase-six-incremental-build-report.md`](../../../../specs/rag/phase-six/rag-plugin-phase-six-incremental-build-report.md).

The Markdown ablation preserves structure-aware chunking as the default because it supplies section paths, reduces returned context, and does not materially reduce mean quality across the tested retrieval modes. The evidence does not establish a per-mode ranking improvement: Dense and Hybrid each missed the one-percentage-point nDCG tolerance. Adjacent expansion remains the quality-first default because it improved complete evidence on the fixed sample, but deployments with tight context budgets can disable it.

Semantic-boundary chunking is not part of the supported strategy set. The fixed pilot did not beat a no-model safe-boundary baseline, so the implementation avoids model-dependent asynchronous chunking and boundary-vector cache state without evidence of better cuts.

LLM-generated contextual prefixes are not part of the index format or retrieval path. Offline commands retain deterministic candidate statistics, bounded plans, explicit generation budgets, and an independent content-addressed cache for evaluation only. The real-corpus evaluation failed its release thresholds, so `index` does not accept generated records and normal construction never reads prefix credentials or calls a generation model; [`specs/rag/phase-six/rag-plugin-phase-six-one-acceptance-report.md`](../../../../specs/rag/phase-six/rag-plugin-phase-six-one-acceptance-report.md) records the evidence and reintroduction conditions.
