# Agent Note：本地只读 RAG 检索能力 seam

Status: implemented

[English](2026-09-04-local-rag-retrieval.md) | 中文

## 问题

DSH 原本没有与提供方无关的方式，让 agent 从开发者提供的知识语料中检索证据。用于学习的实现还需要在同一语料和评测器下比较稀疏检索、稠密检索、结果融合和神经重排序，同时不把这些算法耦合进 agent loop，也不向模型暴露部署控制项。

## 决定

该实验能力拆成一个完整 seam 的三个角色。`@deepseek-ai/dsh-experimental-knowledge` 定义与提供方无关的 `ctx.knowledge` 服务、品牌化文档与分片标识、排序结果和稳定的调用方可见错误。`@deepseek-ai/dsh-experimental-knowledge-local` 从一份不可变本地索引提供该服务。`@deepseek-ai/dsh-experimental-tool-knowledge` 通过只读模型工具 `knowledge_search(query)` 消费该服务。

本地提供方支持使用确定性英文或中英文混合分析器的 SQLite FTS5 BM25、固定 revision BGE-M3 的 float32 精确 Dense 扫描、USearch HNSW，以及对稀疏和 Dense 结果执行 Reciprocal Rank Fusion。HNSW 查询的 `expansionSearch` 默认为 1024；该值仍可由部署配置，但不向模型开放。请求态自动路由把精确标识符交给 BM25，把其他查询交给 Dense；首选路径不可用时只在部署配置的允许集合内按固定顺序回退。该规则保留跨脚本查询的实测收益，同时避免 Hybrid 在 T2Ranking 同脚本样本上的质量与延迟回退；调用方仍可显式选择 Hybrid。固定 revision 的多语言 BGE 跨编码器可为任意召回模式重排前部候选；`off` 是性能优先默认值，`on` 对非空结果强制重排，`auto` 仅当前两名召回分数的归一化差距低于可配置的默认值 `0.15` 时执行。召回默认保留 50 条，跨编码器最多处理前 20 条。每个结果都会报告具体召回方式、Dense 索引，以及是否实际执行重排序。

Markdown 感知分片是默认策略，优先使用 ATX 章节边界，其次使用段落与句子边界；除非单个围栏代码块超过 token 上限，否则保持代码块完整。章节路径会加入 BM25 和 Dense 索引文本。离线构建器还提供不含章节路径的固定 token 窗口策略用于受控对照，在清单中记录策略，并拒绝跨策略派生。完成排序后，提供方可以为每条命中附加前后各一个同文档分片，但不增加结果数；实现会去除 overlap 文本，也不会重复已入选的相邻分片。Consumer 限制命中证据和相邻证据长度，把每条结果放在工具生成的不可信数据标记之间，为每行不可信字段增加缩进，分配在单个 agent 轮次内唯一的引用编号，并且不向模型上下文发送分数和底层调参字段。检索文本不能授权工具调用，也不能覆盖系统、开发者或用户指令；模型只能把它作为证据引用或分析。提示词要求模型先识别独立证据需求、从一条查询开始、每次只发出一个搜索调用并检查结果，且仅在必要需求缺少直接支持、证据冲突或缺少中间事实时继续搜索。每条后续查询针对剩余缺口而不是重复早先查询；需要证据中的不透明标识符才能继续时，下一条查询只能包含该标识符。实质冲突只有在针对性查询能够区分时间、主体、范围、版本或权威裁定后才算解决；排名、分数和表面上的新旧不能单独决定采用哪一方，缺少裁定证据时必须明确保留不确定性。部署可允许每轮执行一至八次搜索，实测默认值为六次，并独立限制成功结果的累计渲染文本。NFKC 等价、转为小写且空白折叠后的重复查询会被拒绝。每次调用尝试都会消耗搜索次数预算并占用独立引用区间，包括重复调用、提供方失败和累计输出预算拒绝；只有成功渲染的结果消耗累计字符预算。下一个轮次会重置全部用量。不带 agent 的直接调用不受轮次限制，并且每次都从 `K1` 开始。

索引准备是显式的离线操作。格式版本 3 通过有界事务把源文档流式写入 `knowledge.sqlite`，其中的分片元数据、章节路径和预分析 SQLite FTS5 输入与可选 `dense.f32le`、`dense.usearch` 载荷共用 ordinal。清单通过流式统计记录 Latin/CJK 语料画像，用于可复现评测且不额外保留一份语料。完成分片后，构建器记录准确规模，并按 `vectorCount × dimensions` 给出保守推荐；交互式命令可以在 embedding 前确认 Exact-only、HNSW-only 或 Both，非交互命令确定性接受推荐。HNSW-only 仍会编码全部分片，但不保留额外的 Exact 文件；Both 只用于明确的对照实验。长文档分片通过有界的局部探测定位每个 token 硬上限，不再重复 token 化剩余全文或完整前缀。清单记录 Dense 模型、向量数量、维度、扫描阈值、推荐值、请求值、保留的载荷模式、查询默认值和 HNSW 构建参数。运行时以只读方式打开 SQLite，校验载荷类型与大小和 schema 元数据，可按配置在启动时校验摘要，并提供始终重算全部载荷摘要的独立命令。Exact 向量和 HNSW 图仅在请求需要时加载。SQLite FTS5 使用固定 BM25 评分参数，部署配置不再暴露第一版内存实现的 `k1` 和 `b`。插件启动和搜索不会下载语料或模型，也不会重建或修改索引。Dense 检索与重排序需要显式且已填充的本地模型缓存；BM25 无需模型权重即可运行。

Dense 构建可以使用独立的构建期 SQLite 向量缓存。每个键是完整文档编码配置与准确 Dense 输入的长度明确编码 SHA-256，输入包含标题、章节路径和分片正文。构建器按有限批次读取缓存，每个缺失键只编码一次，原子提交每个成功的 embedding 批次，并按目标的新 ordinal 顺序组装 Exact 向量。只有在载荷摘要和 Dense 配置都一致时，经过验证的格式 3 Exact 索引才能预热缓存；源索引始终只读。中断构建会保留已提交的缓存批次，但不会发布目标清单。HNSW 基于完整的新顺序向量序列重建，不执行原地更新。

离线命令能够准备固定 revision 的 BEIR SciFact、MLDR 中英文、T2Ranking 和 MLQA Retrieval `eng-zho`，构建索引、校验摘要，并在同一文档级评测器下选择自动、BM25、Dense、Hybrid、Exact、HNSW 和 `off`／`auto`／`on` 重排序组合。简洁的聚合报告先把分片结果折叠为唯一文档，再记录 Recall、MRR、nDCG、Success、延迟、载荷体积、实际路由数量、自适应重排序触发比例和 HNSW 相对 Exact 的召回率。独立 JSONL 文件记录每条计时查询的请求策略、实际策略、排序结果、相关性标注、单查询指标和延迟；仅在重排序没有替换召回分数时记录召回前两名的分差。失败查询会先写入明细，再把完整配置标记为失败，聚合报告不计算部分结果。每个数据集只支持有限结论：SciFact 用于英文回归，MLDR 覆盖多语言长文档，T2Ranking 覆盖中文检索和规模，MLQA Retrieval 覆盖中文查询检索英文段落。

Exact/HNSW 阈值校准使用确定性的嵌套 T2Ranking 切片：先包含所选查询的全部正例，再加入官方 BM25 困难负例。最大档只生成一次嵌入；较小的 ordinal 前缀索引复制通过校验的 Exact 向量批次，并重新构建 SQLite 和 HNSW。分片身份、检索文本、分析器、tokenizer 或分片配置只要不一致，派生就会失败，避免复用向量静默关联到不同内容。

## 备选方案

**直接在 `agent-loop` 中增加检索行为。** 不采用：检索是有独立提供方和 Consumer 生命周期的可选能力。现有工具路径已经能让模型按需请求证据，并使 loop 不依赖语料与排序选择。

**把服务、本地算法和模型工具放在一个包内。** 不采用：这会迫使未来的提供方依赖本地索引格式，也会迫使非模型 Consumer 依赖提示词和展示策略。三个角色因不同原因变化，当前拆分满足仓库的能力 seam 结构，也没有额外增加提供方注册表。

**使用远程向量数据库或托管搜索服务。** 本阶段不采用：在能够本地比较检索算法之前，这会先引入部署、凭证、网络行为和提供方专属索引。本服务保持提供方无关，因此未来仍可增加远程实现，而无需把远程系统问题放入教学实现。

**把嵌入或重排序推理暴露为产品 API。** 不采用：调用方需要的是排序后的证据，而不是模型张量。以模型执行作为服务会把池化方式、维度、提示前缀和缓存布局泄漏到包边界外，也无法表示 BM25 或 Hybrid 检索。

**在运行时下载缺失的语料或模型。** 不采用：启动过程会依赖网络并产生修改，实验也可能静默使用发生变化的资产。显式准备和固定 revision 使运行行为可复现，并让缺少前置产物时清晰失败。

**继续分别保存 JSONL 分片和 JSON BM25 载荷。** 不采用：加载这些文件会在查询前把完整语料和倒排索引放入 JavaScript 内存。单个内嵌 SQLite 载荷支持有界构建、只读查询、schema 校验和 BM25，且无需增加数据库服务。

**按源身份或 ordinal 复用向量。** 不采用：文档插入、删除、输入重排或分片边界变化会漏掉可复用内容，或把向量关联到错误文本。内容寻址键把准确 Dense 输入相等和模型配置一致作为复用条件，目标 ordinal 仍只属于各自的不可变索引。

**启用按长度分桶编码或增大默认批次。** 实测样本不支持该选择。长度分桶缩短了墙钟时间，但改变 Exact 排名并降低 MRR@10 和 nDCG@10；固定批次从 32 增至 64 只带来较小吞吐收益，峰值 RSS 增加约 41%。两者都不进入受支持构建器，避免成为缺少证据的默认值。

**把 Markdown 边界或相邻扩展描述为普遍质量提升。** 固定 25 条 Markdown 查询的消融不支持该结论。结构分片使五条命中的上下文减少约三分之一并改善 BM25，但 Dense 和 Hybrid 的 nDCG@10 均下降 1.48 个百分点。相邻扩展使平均完整证据覆盖率提高 4 个百分点，同时返回 token 增加 77%。这些功能保留为显式、可测量的选择，而不是无条件质量结论。

**在小规模边界 pilot 后增加语义边界分片。** 不采用：受长度约束的最大语义间隙与无模型的最后安全单元基线同为50%精确边界召回率，却产生更多边界；百分位和固定距离方案更差。只有新的独立 pilot 先证明稳定边界收益，才值得引入语义分片、第二种向量缓存用途或三索引消融。

## 结果

部署挂载一个 Knowledge 提供方，并可选择挂载工具 Consumer；抽象 Service Definition 不单独挂载。提供方在检索前通过部署默认值和允许集合解析每个请求。索引格式 3 有意只支持一份只读语料、不可变的全量索引发布、SQLite FTS5 BM25、Exact Dense 扫描和一种 HNSW 实现。Dense 自动选择使用清单记录的向量数乘维度，不根据当前机器重新判断。默认的 `50,000,000` 个扫描元素是可配置的保守甜点值，不是跨机器实测临界点。请求不可用的 Dense 索引会失败，不会回退。查询自动路由和自适应重排序是透明、确定的启发式规则，而不是学习型分类器；调用方可以覆盖高层策略，只有部署方能配置阈值。USearch 使用原生自动线程建图时，相同向量可能生成不同的图文件字节和近似邻居，因此每份评测都记录具体索引指纹。构建失败可能留下未发布的不完整目录；本机存储受限时，完整基准索引按顺序构建、评测和删除。当前实现不提供原地索引更新、增量 HNSW 图修改、多语料路由、访问控制、远程存储、第二种 ANN、推理调度或生产恢复。

仓库内的 `rag-knowledge` 示例无需外部模型即可验证完整 BM25 组合路径。包测试覆盖服务生命周期、索引校验、Markdown 感知分片、脚本画像、多语言 BM25、Exact-only、HNSW-only 和双载荷 Dense 检索、内容寻址向量复用与恢复、RRF、自动路由、自适应有界重排序、相邻扩展、可配置的轮次级搜索和输出限制、重复查询拒绝、取消、离线命令和数据集评测。无密钥快照覆盖真实 Loader 组合以及模型可见的默认、关键词、精确和质量优先请求。模型缓存烟测位于独立测试模块，不使用单元测试中的 Transformers.js mock。本地基准结果和与硬件相关的延迟只作为实验依据，不成为产品保证。SciFact 和 MLQA Retrieval 已生成全量查询报告；T2Ranking 和 MLDR 使用固定切片。HNSW 结果重合度属于观察指标，数据集质量结论以标准 qrels 指标为准。

内容寻址复用使 Dense 编码不依赖源文档和分片 ordinal，但复用单位有意限定为输入完全相同。相似正文、标题变化、章节变化以及任何 Dense 配置变化都会导致缓存未命中。缓存不是已发布运行时索引的一部分，也不会削弱格式 3 校验和不可变发布规则。

Markdown 消融保留结构感知分片的默认地位，因为它提供章节路径、减少返回上下文，并且在所测召回方式的平均质量上没有明显回退。证据不能证明每种召回方式的排序都提高：Dense 和 Hybrid 都没有达到 nDCG 下降不超过一个百分点的容差。相邻扩展在固定样本上改善了完整证据，因此继续作为质量优先默认值；上下文预算紧张的部署可以关闭它。

受支持的策略集合不包含语义边界分片。固定 pilot 未超过无模型安全边界基线，因此在没有更好切点证据时不引入依赖模型的异步分片和边界向量缓存状态。
