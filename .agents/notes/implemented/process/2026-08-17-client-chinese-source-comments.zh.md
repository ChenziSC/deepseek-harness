# Agent Note: 浏览器客户端使用中文说明性注释

Status: implemented

[English](2026-08-17-client-chinese-source-comments.md) | 中文

## Problem

浏览器客户端展示中文产品文案，但过去要求源码注释使用英文。这种分工增加了仓库主要中文学习读者理解实现的难度；与此同时，翻译可执行字符串或生成的模型可见说明会改变行为，而不只是改进文档。

## Decision

`packages/client/*` 与 `apps/web` 中的说明性注释和 JSDoc 使用中文。代码标识符、协议值、第三方名称和约定俗成的技术术语保持不变。注释应保留行为、时序、所有权、失败和生命周期事实，不逐字翻译，也不复述代码。

运行时字符串不属于本决策。会被提取为模型可见文本、协议说明或英文生成目录的公共 JSDoc 和源码文字，保留相关系统实际消费的英文原文，并在附近补充中文解释。测试 fixture、快照、机器指令和外部引文在其文本属于受测输入或输出时保持字节不变。

浏览器客户端指令文件负责维护这项语言规则。客户端变更仍根据受影响行为执行相同的类型检查、lint、GUI 测试、Web 回放、文档检查和生成目录检查。

## Alternatives considered

**保留英文注释，只增加外部中文指南。** 说明会远离实现，局部不变量变化时指南也容易产生偏差。

**在每个源码文件中保留双语注释。** 重复每项事实会增加注释密度，并产生两份不受仓库文档配对检查保护的本地版本。

**翻译客户端代码附近的所有英文字符串。** 工具 schema、协议值、快照、诊断和生成的模型可见文字属于行为或兼容性输入，而非源码注释；修改它们超出了学习型本地化的范围。

## Consequences

中文读者可以在非显然客户端不变量的使用位置直接学习它们，今后该子树中的说明性注释也遵循同一语言。国际贡献者需要阅读中文说明或使用成对维护的架构文档。对运行时与生成英文的例外可避免注释本地化改变请求、协议、快照或公开生成目录。
